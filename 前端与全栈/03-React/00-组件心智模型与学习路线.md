# 组件心智模型与学习路线

> 优先级：⭐

## 一、是什么

React 是用于构建用户界面的 JavaScript 库。组件是接收输入并返回 UI 描述的函数。

~~~text
Props + State
      ↓
组件函数
      ↓
JSX
      ↓
React 更新界面
~~~

## 二、为什么需要

React 的难点不是标签语法，而是把 UI 看成状态的结果：

- 数据放在哪里
- 谁负责修改数据
- 哪些组件需要共享状态
- 哪些逻辑属于事件
- 哪些逻辑属于外部系统同步

## 三、核心用法

把页面拆成有职责的组件：

~~~text
Page
├── Header
├── SearchBox
├── NoteList
│   └── NoteCard
└── EmptyState
~~~

组件边界优先依据职责和数据流，而不是机械地每个标签拆一个组件。

## 四、核心原理

### UI 是状态的函数

可以把组件理解为：

~~~text
UI = f(Props, State)
~~~

直观含义：同样的输入得到同样的 UI；事件或外部数据变化后，React 使用新的输入重新调用组件。

### 渲染不是修改 DOM

组件函数执行时主要是在计算下一份 UI 描述。不要把组件函数当作“按顺序执行一次的脚本”，也不要在渲染期间修改外部系统。

### 单向数据流

数据通常从父组件通过 Props 流向子组件；子组件通过回调请求父组件修改状态。

## 五、常见场景

- 页面拆分。
- 组件复用。
- 多个组件共享数据。
- 表单和列表交互。
- 加载、错误和空状态。

## 六、踩坑点

1. 组件函数可能被多次调用。
2. 不要在渲染期间发请求、写 DOM 或修改外部变量。
3. 不要把所有逻辑都塞进一个页面组件。
4. 不要一开始就引入全局状态库。
5. 组件拆分要服务于职责、复用和测试。

## 七、项目中的实际使用

一个学习资料页面可以按职责拆分：

~~~text
NotesPage：组织页面和状态
SearchInput：收集搜索输入
NoteList：渲染列表
NoteCard：展示单条资料
RequestState：处理加载和错误
~~~

页面拥有需要共享的状态；展示组件尽量保持纯粹。

## 八、一句话总结

React 的核心是：组件根据 Props 和 State 计算 UI，事件改变状态，新的状态触发新的 UI 计算。

## 九、核心问答

### 1. React 组件本质上是什么？

一个接收 Props、读取 State 并返回 UI 描述的函数。

### 2. 为什么要遵守单向数据流？

数据变化路径清晰，容易追踪、调试和复用。

### 3. 渲染期间为什么不能发请求？

渲染应该是可重复的纯计算；请求属于外部系统副作用，放在事件或合适的 Effect 中。

### 4. 组件应该按什么标准拆分？

按职责、数据边界、复用需求和可测试性拆分，不按标签数量机械拆分。

3. 为什么组件函数不能被当作只执行一次的脚本？
4. 哪些代码不应该放在渲染阶段？
