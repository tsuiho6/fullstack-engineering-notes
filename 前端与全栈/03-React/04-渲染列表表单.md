# 条件渲染、列表、Key 与表单

> 优先级：⭐

## 一、是什么

条件渲染决定显示哪个 UI；列表渲染把数据数组映射成组件集合；表单用于收集和提交用户输入。

## 二、为什么需要

真实页面不只有“有数据时显示内容”，还要处理：

- 加载中
- 请求失败
- 成功但为空
- 成功且有数据
- 表单输入和校验

## 三、核心用法

### 条件渲染

~~~tsx
if (status === 'loading') {
  return <Spinner />
}

if (status === 'error') {
  return <ErrorMessage />
}

if (items.length === 0) {
  return <EmptyState />
}

return <List items={items} />
~~~

### 列表和 Key

~~~tsx
items.map((item) => (
  <li key={item.id}>{item.title}</li>
))
~~~

Key 应该来自数据中稳定、同级唯一的 ID。

### 受控表单

~~~tsx
function SearchForm() {
  const [keyword, setKeyword] = useState('')

  return (
    <input
      value={keyword}
      onChange={(event) => setKeyword(event.target.value)}
    />
  )
}
~~~

输入值由 React State 控制，输入变化通过事件更新 State。

### 提交

~~~tsx
function handleSubmit(event: React.FormEvent<HTMLFormElement>) {
  event.preventDefault()
  submit(keyword)
}
~~~

## 四、核心原理

### Key 用于身份，不是数组下标

React 使用 Key 判断列表项在不同渲染之间是否是同一个实体。稳定 Key 能保留正确的组件状态；错误 Key 会导致状态错位。

### 受控与非受控

| 方式 | 数据来源 | 适合场景 |
| --- | --- | --- |
| 受控 | React State | 需要即时校验、联动和提交控制 |
| 非受控 | DOM/表单元素 | 简单表单或使用 FormData |

项目中可以根据复杂度选择，不必所有输入都强行复杂化。

## 五、常见场景

- 表格和卡片列表。
- 搜索、筛选和分页。
- 登录和资料编辑。
- 新增、编辑和删除表单。
- 加载、错误和空状态。

## 六、踩坑点

1. 不要把数组下标作为会增删排序列表的 Key。
2. 不要使用随机数作为 Key。
3. 条件渲染中注意 0 会被渲染出来，例如 `count && <span>`。
4. input 受控后不要无意中把 value 变成 undefined。
5. 提交表单时要阻止浏览器默认刷新。
6. 校验错误属于 UI 状态，也要设计清楚。

## 七、项目中的实际使用

请求页面推荐明确建模：

~~~text
loading：显示骨架屏
error：显示错误和重试
success + empty：显示空状态
success + data：显示列表
~~~

搜索和表单提交时，先更新本地输入，再在提交边界校验和发送请求。

## 八、一句话总结

列表需要稳定身份，表单需要明确数据拥有者，页面必须把 loading、error、empty、success 都当作真实状态。

## 九、核心问答

### 1. Key 的作用是什么？

让 React 识别列表项身份，从而正确复用、移动或销毁组件。

### 2. 为什么数组下标不适合作为 Key？

插入、删除或排序后下标会变化，React 可能把旧组件状态对应到错误的数据项。

### 3. 受控输入和非受控输入怎么选？

需要即时校验、联动和精细控制时用受控；简单表单或直接使用 FormData 时可用非受控。

### 4. 为什么要单独处理空状态？

请求成功但没有数据与请求失败是两种不同事实，用户需要不同的提示和操作。

## 十、自测与答案

### 题目

1. 列表 Key 应该来自哪里？
2. 为什么随机 Key 会造成问题？
3. 如何阻止表单提交刷新页面？
4. `count && <span>` 在 count 为 0 时可能显示什么？

<details>
<summary>查看答案</summary>

1. 来自稳定且在兄弟节点中唯一的数据 ID。
2. 每次渲染都变，React 会误以为节点全部换了。
3. 在提交处理器中调用 event.preventDefault()。
4. 可能直接渲染数字 0，需要显式比较 count > 0。
