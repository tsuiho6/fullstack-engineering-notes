# 闭包

> 优先级：⭐

## 一、是什么

闭包是函数和它能够访问的词法环境的组合。即使外层函数已经执行结束，内部函数仍然可以访问外层变量。

## 二、为什么需要

闭包是以下能力的基础：

- 工厂函数和私有状态
- 回调与事件处理器
- 定时器
- 防抖和节流
- React Hooks 中的状态捕获

## 三、核心用法

~~~js
function createCounter() {
  let count = 0

  return {
    increment() {
      count += 1
      return count
    },
    current() {
      return count
    },
  }
}

const counter = createCounter()
counter.increment() // 1
counter.current() // 1
~~~

外部无法直接访问 count，只能通过返回的方法操作它。

## 四、核心原理

函数创建时会记录自己需要访问的外部变量。即使外层调用栈结束，只要内部函数仍被引用，这些变量就继续存活。

~~~text
外层函数创建变量
→ 内层函数引用变量
→ 内层函数被返回或注册
→ 变量继续存活
~~~

闭包保存的是对变量环境的访问，不是简单复制一份变量值。

## 五、常见场景

- 生成带配置的函数。
- 防抖和节流。
- 事件和定时器回调。
- React 事件处理器和 Effect。

## 六、踩坑点

### 循环中的 var

~~~js
for (var i = 0; i < 3; i += 1) {
  setTimeout(() => console.log(i), 0)
}
// 3 3 3
~~~

var 没有块级作用域。使用 let：

~~~js
for (let i = 0; i < 3; i += 1) {
  setTimeout(() => console.log(i), 0)
}
// 0 1 2
~~~

### React 中的旧闭包

某次渲染创建的函数会捕获那次渲染中的状态。异步回调延迟执行时，可能拿到旧状态。要根据场景使用函数式更新、正确依赖或 ref。

### 内存生命周期

长期保存的回调如果引用了很大的对象，这些对象可能无法及时回收。

## 七、项目中的实际使用

防抖函数：

~~~js
function debounce(fn, delay) {
  let timer

  return (...args) => {
    clearTimeout(timer)
    timer = setTimeout(() => fn(...args), delay)
  }
}
~~~

输入：函数和延迟时间；输出：一个带延迟控制的新函数。

使用闭包前先问：我需要保存的状态是什么？它应该活多久？普通参数传递是否已经足够？

## 八、一句话总结

闭包让函数携带外部变量环境，因此可以在外层函数结束后继续使用那些变量。

## 九、核心问答

### 1. 为什么 createCounter 返回的方法还能访问 count？

因为返回的方法形成了闭包，仍然能访问外层词法环境。

### 2. 闭包保存的是值还是环境？

更准确地说，是保存了对外部词法环境的访问。

### 3. 为什么 React 中会出现旧状态？

因为回调属于某次渲染，它捕获的是那次渲染中的状态值。

### 4. 闭包什么时候不适合使用？

普通参数已经足够，或者闭包会保留大对象、增加理解成本时，不要为了抽象而使用。
