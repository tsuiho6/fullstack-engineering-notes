这篇不是新知识，而是把各篇主干串起来，检查是否形成了可调用的模型。

## 一、依赖关系

~~~text
基础语法
  ├─ 对象与数组：数据形状和不可变更新
  ├─ 闭包：函数与变量生命周期
  ├─ Promise：异步结果
  │    └─ async/await：异步流程表达
  ├─ 模块：文件和依赖边界
  └─ 事件循环：异步代码的执行顺序
~~~

最小闭环：

~~~text
读取数据
→ 检查 HTTP 结果
→ 解析 JSON
→ 转换对象数组
→ 更新状态

~~~

## 二、核心综合问答

### 1. 为什么一个 API 请求同时涉及对象、数组、Promise 和模块？

请求结果通常是对象或对象数组；请求本身是 Promise；请求函数通常被放在独立模块中，再由页面模块调用。

### 2. 为什么“不可变更新”和“闭包”经常一起出现？

状态更新需要创建新对象；异步回调又可能捕获旧状态。理解引用和闭包，才能判断更新是否正确、回调拿到的是否是最新值。

### 3. 如何判断两个请求应该串行还是并行？

看数据依赖。第二个请求需要第一个结果时串行；互不依赖时先启动两个请求，再使用 Promise.all。

### 4. 为什么 fetch 请求成功仍然可能进入业务错误？

网络层成功只表示拿到了 HTTP 响应，404、500 等仍可能是业务失败，需要检查 response.ok 和返回数据结构。

### 5. 为什么 Promise 回调通常比 setTimeout 回调先执行？

Promise 回调进入微任务队列，当前同步代码结束后会优先清空微任务，再处理普通任务。

### 6. 为什么模块比把所有代码放在一个文件中更适合项目？

模块提供独立作用域和清晰依赖，使请求、数据转换、页面逻辑可以分别测试和复用。

### 7. 如何处理搜索框中的过期请求？

在每次新搜索时取消上一次请求，或者给请求附加序列号，只接受最新请求的结果。实际项目优先使用 AbortController 加上服务端校验。

### 8. 为什么不能把所有代码都写成 async/await？

async/await 只改变 Promise 的表达方式，不会自动解决并行、取消、重试、错误分类和状态展示问题。

## 三、项目最小闭环示例

下面是一个不依赖框架的请求模块：

~~~js
export async function searchTodos(keyword, signal) {
  const url = '/api/todos?q=' + encodeURIComponent(keyword)
  const response = await fetch(url, { signal })

  if (!response.ok) {
    throw new Error('搜索失败：HTTP ' + response.status)
  }

  const data = await response.json()

  if (!Array.isArray(data)) {
    throw new Error('响应格式错误')
  }

  return data.filter((todo) => todo.title.includes(keyword))
}
~~~

调用方需要维护：

~~~text
loading：请求进行中
success：展示结果
empty：请求成功但没有结果
error：展示错误和重试入口
~~~

这里同时用到了：

- 模块：export
- async/await：异步流程
- Promise：fetch 返回值
- 对象与数组：响应数据和 filter
- 事件循环：请求完成后的回调调度
- AbortController：取消旧请求

const userPromise = fetchUser()
const settingsPromise = fetchSettings()
const [user, settings] = await Promise.all([
  userPromise,
  settingsPromise,
])
~~~

4. 后发的请求可能先返回，先发的请求随后返回并覆盖最新结果。
