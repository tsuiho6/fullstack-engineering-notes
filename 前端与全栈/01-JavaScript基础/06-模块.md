# JavaScript 模块

> 优先级：⭐

## 一、是什么

模块是拥有独立作用域、可以导入和导出值的文件。现代 JavaScript 项目主要使用 ES Modules，也就是 import/export。

## 二、为什么需要

模块解决：

- 全局变量污染
- 文件之间依赖不清
- 代码难以复用
- 大文件难以维护

## 三、核心用法

命名导出：

~~~js
export function formatDate(date) {
  return date.toISOString()
}

export const version = '1.0.0'
~~~

命名导入：

~~~js
import { formatDate, version } from './date.js'
~~~

默认导出：

~~~js
export default function App() {
  return null
}
~~~

默认导入：

~~~js
import App from './App.js'
~~~

## 四、核心原理

模块有自己的作用域。文件中的变量默认不会暴露给其他文件，只有通过 export 导出的绑定才能被导入。

构建工具会分析模块依赖图，完成打包、代码分割和按需加载。

## 五、常见场景

- 一个文件只负责一个明确领域。
- 抽离 API 请求函数。
- 抽离类型、常量和工具函数。
- 组件之间复用逻辑。

推荐的业务目录：

~~~text
src/
  components/   可复用 UI
  lib/          通用函数与基础设施
  features/     按业务功能组织
  types/        共享类型
~~~

## 六、踩坑点

1. 默认导出每个文件最多一个；命名导出可以有多个。
2. 命名导入名称必须匹配；默认导入名称可以自定义。
3. 不要为了少写几行代码大量使用 export *。
4. 循环依赖可能导致初始化顺序问题。
5. 模块路径是否需要扩展名取决于运行时和构建工具。

## 七、项目中的实际使用

请求模块只负责请求和数据转换：

~~~js
export async function getTodos() {
  const response = await fetch('/api/todos')

  if (!response.ok) {
    throw new Error('加载任务失败')
  }

  return response.json()
}
~~~

页面模块负责调用它并展示状态。不要把请求、数据转换和页面渲染全部写进一个文件。

## 八、一句话总结

模块通过明确的导入导出建立依赖图，是 JavaScript 工程组织代码的基本单位。

## 九、核心问答

### 1. 默认导出和命名导出有什么区别？

默认导出一个文件最多一个，导入时可以改名；命名导出可以多个，导入名称需要匹配。

### 2. 为什么不建议到处使用 export *？

它隐藏真实依赖和名称来源，容易产生冲突，也让重构和查找变困难。

### 3. 模块为什么能减少全局污染？

每个模块拥有独立作用域，未导出的变量不会直接出现在全局。

### 4. 为什么大型项目需要按领域拆分模块？

让依赖边界和职责更清楚，减少修改一个功能时对其他功能的影响。
