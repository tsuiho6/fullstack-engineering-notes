# 异步与事件循环

> 优先级：⭐

## 一、是什么

JavaScript 通常在一个主线程上执行同步代码。事件循环负责在调用栈空闲后，从任务队列中取出回调继续执行。

## 二、为什么需要

网络请求、定时器、用户事件和文件操作都可能等待很久。同步等待会阻塞页面；异步模型让程序在等待期间继续处理其他工作。

## 三、核心用法

~~~js
console.log('A')

setTimeout(() => {
  console.log('timeout')
}, 0)

Promise.resolve().then(() => {
  console.log('promise')
})

console.log('B')
~~~

通常输出：

~~~text
A
B
promise
timeout
~~~

## 四、核心原理

一个足够实用的模型：

~~~text
调用栈执行同步代码
→ 清空微任务队列
→ 取一个普通任务执行
→ 再清空微任务队列
→ 重复
~~~

常见微任务：

- Promise 的 then、catch、finally
- queueMicrotask

常见任务：

- setTimeout
- 用户事件
- 网络事件回调

这是理解常见代码的模型，不是浏览器和 Node.js 所有调度细节的完整规范。

## 五、常见场景

- 判断 Promise 和定时器的执行顺序。
- 排查页面卡顿。
- 分析连续微任务。
- 设计异步任务和取消机制。

## 六、踩坑点

1. setTimeout(fn, 0) 不是立即执行。
2. 微任务过多可能推迟渲染和普通任务。
3. 异步代码不等于多线程。
4. Promise 不能自动取消底层请求。
5. 复杂顺序不要只靠猜，用日志和最小实验验证。

## 七、项目中的实际使用

用 AbortController 取消无意义的请求：

~~~js
const controller = new AbortController()

fetch('/api/search', {
  signal: controller.signal,
})

controller.abort()
~~~

搜索框、页面卸载和组件切换时，取消已经无意义的请求，可以减少资源浪费和旧结果覆盖新结果的问题。

## 八、一句话总结

事件循环先执行同步代码，再优先清空微任务，最后执行普通任务；异步是调度，不是自动多线程。

## 九、核心问答

### 1. Promise 回调和 setTimeout 谁先执行？

当前同步代码结束后，通常先执行 Promise 微任务，再执行定时器任务。

### 2. setTimeout(fn, 0) 为什么不是立即执行？

它只是把回调放入任务队列，必须等待当前调用栈和优先级更高的微任务完成。

### 3. 异步代码是否等于多线程？

不是。JavaScript 主代码通常仍在一个线程执行，异步 I/O 由宿主环境调度。

### 4. 为什么要取消无意义的请求？

避免旧请求覆盖新结果，减少网络和服务端资源浪费，并降低组件卸载后的更新问题。
