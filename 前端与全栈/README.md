# 前端与全栈

这里整理从 JavaScript 到 TypeScript、React、Next.js 的前端与全栈学习主线。

学习顺序不是“把四门技术分别学完”，而是逐层建立能力：

~~~text
JavaScript 运行时
    ↓
TypeScript 类型边界
    ↓
React UI 与组件模型
    ↓
Next.js 应用运行时
    ↓
PostgreSQL、认证、部署与 AI 应用
~~~

## 一、推荐入口

1. [JavaScript 基础](./01-JavaScript基础/README.md)
2. [TypeScript](./02-TypeScript/README.md)
3. [React](./03-React/README.md)
4. [Next.js](./04-Next.js/README.md)

## 二、每个阶段解决什么问题

| 阶段 | 主要问题 | 进入下一阶段前 |
| --- | --- | --- |
| JavaScript | 值、函数、对象、模块和异步代码如何运行 | 能写出并解释一个模块化的异步小项目 |
| TypeScript | 如何为数据、函数和模块建立可靠边界 | 能给 API、表单和业务函数建模，并知道何时需要运行时校验 |
| React | 如何把状态和数据流组织成可交互 UI | 能写出列表、表单、异步状态和可复用组件 |
| Next.js | 如何把 UI 变成可路由、可取数、可写入、可部署的全栈应用 | 能完成一个带数据库、权限和错误处理的最小闭环 |

## 三、阅读原则

- 先读每组 README 的学习路线，再按数字顺序阅读。
- 每篇先回忆问题，再查看代码和答案。
- 优先完成项目闭环，不追求一次读完全部 API。
- JavaScript 讲运行时，TypeScript 讲类型边界，React 讲 UI，Next.js 讲应用和服务器边界。
- PostgreSQL、认证、部署和 AI 是 Next.js 的全栈扩展，不是 React 或 Next.js 基础语法的前置条件。

## 四、项目主线

建议贯穿一个“全栈学习资料库”：

~~~text
静态笔记列表
→ React 搜索与表单
→ Next.js 路由与服务端取数
→ PostgreSQL 持久化
→ 登录、授权与后台编辑
→ AI 摘要与流式问答
→ 部署与生产验证
~~~
