# 类型缩小与未知输入

> 优先级：⭐

## 一、是什么

类型缩小是根据运行时条件，把一个较宽的联合类型判断为更具体的类型。

~~~text
string | number
→ typeof value === 'string'
→ string
~~~

## 二、为什么需要

联合类型、API 数据和用户输入都可能有多个形态。没有类型缩小，就只能使用不安全的断言或 any。

## 三、核心用法

### typeof

~~~ts
function format(value: string | number) {
  if (typeof value === 'string') {
    return value.toUpperCase()
  }

  return value.toFixed(2)
}
~~~

### 真值和相等判断

~~~ts
function print(value: string | undefined) {
  if (value !== undefined) {
    console.log(value.toUpperCase())
  }
}
~~~

不要仅依赖 if (value) 判断数字 0 或空字符串，因为它们是合法值但属于假值。

### in

~~~ts
type Dog = { bark(): void }
type Fish = { swim(): void }

function move(animal: Dog | Fish) {
  if ('swim' in animal) {
    animal.swim()
  } else {
    animal.bark()
  }
}
~~~

### 可辨识联合

~~~ts
type Result<T> =
  | { status: 'success'; data: T }
  | { status: 'error'; message: string }

function getMessage(result: Result<string>) {
  if (result.status === 'success') {
    return result.data
  }

  return result.message
}
~~~

### unknown

~~~ts
function parseValue(value: unknown) {
  if (typeof value === 'string') {
    return value.trim()
  }

  return null
}
~~~

### 自定义类型谓词

~~~ts
function isString(value: unknown): value is string {
  return typeof value === 'string'
}
~~~

## 四、核心原理

TypeScript 的类型缩小依赖代码中的控制流分析。编译器会根据 if、switch、return、throw 等路径，判断某个分支内哪些类型仍然可能存在。

类型缩小不是运行时转换：

~~~text
检查事实
→ 编译器更新当前分支的类型视图
→ 代码仍然使用原来的运行时值
~~~

### never 和穷尽检查

~~~ts
type Shape =
  | { kind: 'circle'; radius: number }
  | { kind: 'square'; side: number }

function assertNever(value: never): never {
  throw new Error('Unexpected shape')
}

function area(shape: Shape) {
  switch (shape.kind) {
    case 'circle':
      return Math.PI * shape.radius ** 2
    case 'square':
      return shape.side ** 2
    default:
      return assertNever(shape)
  }
}
~~~

新增一个分支却忘记处理时，穷尽检查能帮助编译器发现问题。

## 五、常见场景

- 处理 API 返回的不同状态。
- 解析 unknown 的 JSON 数据。
- 处理表单输入。
- 区分不同事件或消息类型。
- 实现状态机和命令分发。

## 六、踩坑点

1. 类型断言不会进行真实检查。
2. typeof null 是 object。
3. if (value) 会排除 0、空字符串和 false。
4. 使用 in 前要确认右侧是对象或函数。
5. 自定义类型谓词如果写错，会让编译器相信错误信息。
6. 只给 JSON 写类型，不代表 JSON 真符合类型。

## 七、项目中的实际使用

对外部 JSON 使用 unknown 作为入口：

~~~ts
async function readJson(response: Response): Promise<unknown> {
  return response.json()
}
~~~

然后通过校验函数得到可信类型。简单数据可以手写校验；复杂项目可以使用运行时 schema 工具。核心原则不变：

~~~text
外部 unknown
→ 运行时校验
→ 内部可信类型
~~~

## 八、一句话总结

类型缩小不是把值变成另一种类型，而是用运行时事实证明当前分支可以安全地按更具体类型使用它。

## 九、核心问答

### 1. 类型缩小和类型断言有什么区别？

类型缩小基于真实运行时条件；类型断言只是修改编译器的看法，不会检查数据。

### 2. 为什么外部 JSON 更适合先用 unknown？

因为它迫使代码先确认数据形状，避免把不可信输入直接传播到业务层。

### 3. 可辨识联合为什么适合表示状态？

每个分支有稳定的标签字段，判断标签后，其他字段会自动缩小到对应分支。

### 4. never 在穷尽检查中表达什么？

表达某个位置理论上不可能再有值；如果出现值，说明联合分支没有处理完整。

4. 如何检查一个联合类型的分支是否处理完整？
