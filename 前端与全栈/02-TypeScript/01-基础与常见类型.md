# 基础与常见类型

> 优先级：⭐

## 一、是什么

常见类型是描述 JavaScript 值的基础工具。项目中最常用的不是复杂类型，而是准确表达字符串、数字、布尔值、数组、对象、联合和可选状态。

## 二、为什么需要

类型能把“函数应该接受什么”和“对象应该有什么字段”变成可检查的约束，减少拼写错误、错误传参和重构遗漏。

## 三、核心用法

### 基本类型

~~~ts
let title: string = '学习笔记'
let count: number = 10
let published: boolean = true
let empty: null = null
let missing: undefined = undefined
~~~

使用小写的 string、number、boolean，不使用大写的 String、Number、Boolean。

### 数组和元组

~~~ts
const ids: string[] = ['a', 'b']
const scores: Array<number> = [90, 95]

const result: [boolean, string] = [true, 'ok']
~~~

数组表示任意长度的同类集合；元组表示固定位置和固定长度的结构。

### 对象类型

~~~ts
type User = {
  id: string
  name: string
  avatarUrl?: string
  readonly createdAt: Date
}
~~~

- ? 表示属性可能不存在，读取时需要考虑 undefined。
- readonly 只限制 TypeScript 中的赋值，不等于运行时冻结对象。

### 联合类型

~~~ts
type ID = string | number

function printId(id: ID) {
  console.log(id)
}
~~~

联合表示“值可能属于多个类型之一”，使用前通常需要缩小。

### 字面量类型

~~~ts
type Theme = 'light' | 'dark'
type Role = 'admin' | 'member'
~~~

字面量联合很适合表示有限状态和配置选项。

### 函数类型

~~~ts
type Formatter = (value: number) => string

const formatPrice: Formatter = (value) => {
  return '¥' + value.toFixed(2)
}
~~~

### Promise 类型

~~~ts
async function getCount(): Promise<number> {
  return 1
}
~~~

## 四、核心原理

### 推断优先，注解边界

~~~ts
const name = 'Xuhao'
const numbers = [1, 2, 3]
~~~

局部变量通常可以依靠推断；函数参数、公共函数返回值、API 和组件 Props 是更值得显式描述的边界。

### optional 不等于 null

~~~ts
type User = {
  nickname?: string
}
~~~

nickname 可能不存在，读取结果通常是 string | undefined；它不自动包含 null。

### never、void 和 undefined

- void：函数不关心返回值，常见于没有有用返回值的函数。
- undefined：一个具体的运行时值。
- never：函数不会正常返回，或某个类型分支不可能存在。

## 五、常见场景

- API 请求和响应。
- React Props。
- 表单模型。
- 配置对象。
- 有限状态机和权限角色。

## 六、踩坑点

1. 不要把所有东西都标成 any。
2. 不要把 string 写成 String。
3. 元组 [number] 不是 number[]，前者是一个元素的元组。
4. optional 属性读取时需要处理 undefined。
5. readonly 不是运行时冻结。
6. 联合类型不能直接使用每个成员独有的属性。
7. 过度使用显式类型会让代码重复，先观察推断结果。

## 七、项目中的实际使用

用有限状态联合替代多个互相矛盾的布尔值：

~~~ts
type RequestState<T> =
  | { status: 'idle' }
  | { status: 'loading' }
  | { status: 'success'; data: T }
  | { status: 'error'; message: string }
~~~

相比 isLoading、hasError、hasData 三个布尔值，这种写法能表达互斥状态，后续也更容易缩小类型。

## 八、一句话总结

常见类型的核心不是写满注解，而是准确表达数据形状、可选性和有限状态。

## 九、核心问答

### 1. 什么时候依靠推断，什么时候写类型？

局部变量优先依靠推断；公共函数、边界数据、Props 和复杂状态应该显式描述。

### 2. optional 属性和 null 有什么区别？

optional 通常表示属性可能不存在，对应 undefined；null 是一个明确的空值，需要业务约定。

### 3. 联合类型的价值是什么？

表达一个值可能属于多个合法分支，并要求使用前通过判断选择正确分支。

### 4. 为什么推荐用状态联合而不是多个布尔值？

联合类型可以排除互相矛盾的状态，例如同时 loading 和 success。

3. nickname?: string 读取时可能是什么类型？
4. 如何表示只能是 light 或 dark 的主题？
