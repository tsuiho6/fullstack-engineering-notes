# 函数与对象类型

> 优先级：⭐

## 一、是什么

函数类型描述输入参数和输出结果；对象类型描述一个值必须具备的属性结构。

## 二、为什么需要

函数和对象是 TypeScript 项目中最常见的边界。准确描述它们，可以让错误在调用处暴露，而不是等到运行时。

## 三、核心用法

### 函数参数和返回值

~~~ts
function add(a: number, b: number): number {
  return a + b
}
~~~

返回值通常可以推断，但公共函数、复杂分支和 API 函数可以显式写出。

### 可选参数和默认参数

~~~ts
function greet(name: string, prefix = 'Hello') {
  return prefix + ', ' + name
}

function findUser(id: string, includeDeleted?: boolean) {
  // includeDeleted 的类型是 boolean | undefined
}
~~~

可选参数必须放在必选参数之后。

### 回调函数

~~~ts
function mapValues<T, U>(
  values: T[],
  transform: (value: T, index: number) => U,
): U[] {
  return values.map(transform)
}
~~~

### 对象类型

~~~ts
type User = {
  id: string
  name: string
  active?: boolean
}
~~~

### interface 与 type

~~~ts
interface User {
  id: string
  name: string
}

type UserId = string | number
~~~

实际项目中两者都能描述对象结构。需要联合、交叉、元组或类型运算时，type 更直接；需要面向可扩展的对象契约时，interface 也很常见。

### readonly

~~~ts
type Config = {
  readonly apiUrl: string
}
~~~

它表达“这个位置不应被重新赋值”，不是运行时冻结。

## 四、核心原理

### 上下文类型

TypeScript 可以从使用位置推断匿名函数参数：

~~~ts
const names = ['Alice', 'Bob']

names.forEach((name) => {
  console.log(name.toUpperCase())
})
~~~

name 从 forEach 的上下文中被推断为 string。

### 函数参数的兼容

回调函数的参数数量和类型需要满足调用方约定。写回调类型时，不要随意让参数比实际调用场景更宽或更窄。

### 函数重载

函数重载可以为同一个函数提供多个调用签名：

~~~ts
function format(value: number): string
function format(value: Date): string
function format(value: number | Date): string {
  return value instanceof Date
    ? value.toISOString()
    : value.toFixed(2)
}
~~~

△ 重载适合调用关系确实不同的 API；简单联合类型通常更易读，不要为了炫技使用重载。

## 五、常见场景

- 服务函数和工具函数。
- React Props。
- API 请求和响应。
- 事件回调。
- 配置对象和数据库模型。

## 六、踩坑点

1. 不要把所有函数返回值都写成 any。
2. optional 参数读取时需要处理 undefined。
3. readonly 不等于深度不可变。
4. 类型断言会绕过对象结构检查。
5. 索引签名会放宽对象的属性约束，不要随意使用。
6. interface 和 type 不需要争论唯一正确答案，按表达需求选择。

## 七、项目中的实际使用

把服务函数的输入和输出放在边界：

~~~ts
type CreateNoteInput = {
  title: string
  content: string
}

type Note = CreateNoteInput & {
  id: string
  createdAt: string
}

async function createNote(input: CreateNoteInput): Promise<Note> {
  // 调用 API 或数据库
  return {
    id: 'n1',
    ...input,
    createdAt: new Date().toISOString(),
  }
}
~~~

输入类型和持久化返回类型分开，避免把 id、时间等服务端字段误当成用户输入。

## 八、一句话总结

函数类型描述“怎么调用”，对象类型描述“必须具备什么”；类型应该优先放在模块和系统边界。

## 九、核心问答

### 1. 函数返回值都需要显式标注吗？

不需要。简单函数可以依靠推断；公共边界、复杂分支和重要 API 可以显式标注。

### 2. interface 和 type 如何选择？

对象契约两者都可用；需要联合、交叉和类型运算时，type 通常更方便。

### 3. readonly 能阻止运行时修改吗？

不能，它主要是编译期约束。运行时需要冻结或使用不可变数据结构。

### 4. 为什么输入类型和返回类型应该分开？

它们代表不同边界。用户提交的数据通常没有 id 和服务端时间，混用会导致安全和建模问题。

## 十、自测与答案

### 题目

1. 可选参数的类型为什么包含 undefined？
2. 什么是上下文类型？
3. 什么时候可以考虑函数重载？
4. 为什么 CreateNoteInput 不应该直接复用 Note？

<details>
<summary>查看答案</summary>

1. 因为调用者可以不传该参数。
2. TypeScript 根据函数被使用的位置推断匿名函数参数类型。
3. 同一函数确实有多个清晰的调用签名，并且联合类型无法保持调用体验时。
4. Note 包含服务端生成的 id 和时间，用户输入并不应该提供这些字段。
