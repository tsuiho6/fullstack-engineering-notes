# 泛型与类型操作

> 优先级：⭐ / △

## 一、是什么

泛型让类型也可以像参数一样传递；类型操作则根据已有类型创建新的类型。

最小心智模型：

~~~text
普通函数：输入值 → 输出值
泛型函数：输入类型和值 → 保持类型关系 → 输出类型和值
~~~

## 二、为什么需要

没有泛型时，类似逻辑可能需要为 string、number、User 分别复制一份。泛型可以保留输入和输出之间的关系，同时不放弃类型检查。

## 三、核心用法

### 泛型函数

~~~ts
function first<T>(items: T[]): T | undefined {
  return items[0]
}

const user = first([{ id: 'u1' }])
~~~

输入：T[]；输出：T | undefined。调用时 T 通常由参数推断。

### 泛型约束

~~~ts
function getLength<T extends { length: number }>(value: T) {
  return value.length
}
~~~

T 可以是任何拥有 length 的类型，但不能是任意值。

### keyof 和索引访问

~~~ts
function getProperty<T, K extends keyof T>(object: T, key: K): T[K] {
  return object[key]
}

const user = { id: 'u1', name: 'Xuhao' }
const name = getProperty(user, 'name')
~~~

keyof 得到对象的键集合；T[K] 得到某个键对应的值类型。

### 常用工具类型

~~~ts
type User = {
  id: string
  name: string
  email: string
}

type UserPreview = Pick<User, 'id' | 'name'>
type UserPatch = Partial<User>
type UserWithoutEmail = Omit<User, 'email'>
type UserMap = Record<string, User>
~~~

项目高频工具类型：

- Pick：选取字段。
- Omit：排除字段。
- Partial：全部变为可选。
- Required：全部变为必选。
- Record：表示键到值的映射。
- ReturnType：取得函数返回类型。

## 四、核心原理

### 泛型保留关系，any 破坏关系

~~~ts
function identity<T>(value: T): T {
  return value
}
~~~

传入 string 得到 string，传入 User 得到 User。泛型保留了类型关系；any 则会让关系失去约束。

### 类型操作不是运行时转换

Pick、Omit、Partial 等只改变编译期类型视图，不会删除或添加运行时属性。

### 条件类型和映射类型

△ 条件类型、映射类型、模板字面量类型适合编写库和高度复用的类型工具，但不是 React/Next.js 入门阶段的主干。遇到现成类型时先会读，再逐步学习如何写。

## 五、常见场景

- 通用列表、分页和请求函数。
- API 响应包装类型。
- 表单更新类型。
- 从领域模型派生视图模型。
- 根据对象键安全地读取属性。

## 六、踩坑点

1. 泛型不是越多越好，先看是否真的需要保持类型关系。
2. 没有约束的 T 不能直接访问属性。
3. Partial 只改变静态可选性，不会产生运行时补丁逻辑。
4. Omit 和 Pick 不会改变对象实际字段。
5. 复杂类型表达式可能比重复一个简单类型更难维护。
6. 不要用泛型替代运行时校验。

## 七、项目中的实际使用

统一 API 响应：

~~~ts
type ApiResponse<T> =
  | { ok: true; data: T }
  | { ok: false; message: string }

type PageResult<T> = {
  items: T[]
  total: number
  page: number
}
~~~

这样可以复用外层结构，同时让 data 和 items 保留真实类型。

## 八、一句话总结

泛型用于保留类型关系，工具类型用于从已有模型派生新模型；它们服务于复用和边界清晰，而不是类型炫技。

## 九、核心问答

### 1. 泛型和 any 的区别是什么？

泛型保留输入和输出的类型关系并继续检查；any 会放弃检查。

### 2. 为什么 T extends { length: number } 很重要？

它告诉编译器 T 至少拥有 length，函数才能安全访问该属性。

### 3. keyof T 和 T[K] 分别表示什么？

keyof T 表示 T 的合法键集合；T[K] 表示键 K 对应的值类型。

### 4. `Partial<User>` 会在运行时把字段变成可选吗？

不会，它只改变 TypeScript 的静态类型；运行时对象仍然是什么字段就有什么字段。

4. 为什么工具类型不能替代数据校验？
