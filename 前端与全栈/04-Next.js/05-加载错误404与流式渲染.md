# loading、error、not-found 与流式渲染

> 优先级：⭐ 必须掌握：把加载、错误、404 和流式反馈做成完整 UI。

## 一、是什么

loading.tsx、error.tsx 和 not-found.tsx 是 App Router 的特殊文件，分别为加载中、运行时错误和资源不存在提供路由级 UI。

流式渲染是把页面或组件拆成多个块，先发送已经准备好的部分，再逐步发送慢数据对应的内容。

## 二、为什么需要

真实页面一定会遇到慢请求、异常和不存在的数据。没有明确边界，用户只能看到空白、整页崩溃或没有解释的 404。

## 三、核心用法

加载 UI：

~~~tsx
export default function Loading() {
  return <div aria-busy="true">正在加载笔记……</div>;
}
~~~

错误边界必须是 Client Component：

~~~tsx
'use client';

import { useEffect } from 'react';

export default function ErrorPage({
  error,
  reset,
}: {
  error: Error & { digest?: string };
  reset: () => void;
}) {
  useEffect(() => {
    console.error(error);
  }, [error]);

  return (
    <section>
      <p>页面加载失败。</p>
      <button onClick={() => reset()}>重试</button>
    </section>
  );
}
~~~

资源不存在：

~~~tsx
import { notFound } from 'next/navigation';

const note = await getNote(slug);
if (!note) notFound();
~~~

也可以在目录中放 not-found.tsx 作为该段的 404 UI。

组件级流式：

~~~tsx
import { Suspense } from 'react';

export default function Page() {
  return (
    <>
      <Header />
      <Suspense fallback={<div>正在加载统计……</div>}>
        <SlowStats />
      </Suspense>
    </>
  );
}
~~~

## 四、核心原理

loading.tsx 会为当前路由段创建基于 Suspense 的加载边界，适合覆盖整个页面段；Suspense 可以放得更靠近慢组件，获得更细粒度的渐进展示。

错误边界捕获渲染阶段的错误，但不是所有错误都自动由同一个边界处理。事件处理函数中的错误、某些服务器启动错误和写操作错误仍需在相应位置显式处理。

not-found 表达“资源不存在”，error 表达“系统或代码执行失败”，不能混用。

## 五、常见场景

- 列表页首屏：loading skeleton。
- 详情页不存在：not-found。
- 第三方 API 失败：error + 重试。
- 页面主体很快、统计很慢：Suspense 局部流式。
- AI 输出：Route Handler 的响应流，不等同于 loading.tsx。

## 六、踩坑点

- 把 loading 当成请求函数内部的状态组件，忽略路由段边界。
- error.tsx 忘记使用 use client。
- 把权限不足、资源不存在和服务器异常都返回成 500。
- 在 layout 中使用未缓存数据后，误以为同级 loading 一定能立即出现。
- 流式 UI 没有处理客户端断开、重试和重复提交。

## 七、项目中的实际使用

笔记详情页推荐：

~~~text
app/notes/[slug]/
├─ page.tsx
├─ loading.tsx
├─ error.tsx
└─ not-found.tsx
~~~

page 只负责获取和渲染资源；not-found 处理查询不到；error 处理异常并允许重试；loading 提供骨架屏。对于页面中慢的推荐列表，再使用局部 Suspense。

## 八、一句话总结

加载、错误、不存在和流式是四种不同的生命周期状态，必须在不同边界上分别表达。

## 九、核心问答

### 1. error.tsx 和 not-found.tsx 的区别是什么？

error 是执行失败后的恢复 UI；not-found 是请求的资源不存在。

### 2. loading.tsx 和 Suspense 的关系是什么？

loading.tsx 是路由级的便捷加载边界；Suspense 可以在组件级提供更细粒度的 fallback。

### 3. 为什么错误页面需要 reset？

允许用户在临时网络或服务错误后重新尝试渲染当前路由段。

### 4. AI 流式输出和 loading.tsx 有什么区别？

loading.tsx 是等待页面或路由段内容的占位；AI 流式输出是在响应已经开始后持续接收内容。

## 十、自测与答案

1. 数据库找不到笔记时应该进入哪个边界？
2. error.tsx 为什么不能直接使用 useState 而不写 use client？
3. 一个页面只有右侧统计很慢，如何避免左侧也被阻塞？
4. 流式响应开始后发生错误，用户界面至少要显示什么？

<details>
<summary>参考答案</summary>

1. not-found。
2. error.tsx 本身需要客户端交互和 reset，因此必须是 Client Component。
3. 把右侧统计放进 Suspense，左侧先渲染。
4. 已收到的内容、错误提示、重试或重新生成入口，以及必要的取消状态。

</details>
