# 部署与生产环境

> 优先级：⭐ 第二阶段必须掌握：运行时、环境变量、构建和部署验证。

## 一、是什么

部署是把 Next.js 应用、环境变量、数据库和静态资源放到可以稳定运行的环境中。生产环境不仅要能打开页面，还要支持应用实际使用到的运行时能力。

## 二、为什么需要

开发机上的文件系统、数据库、密钥和网络条件与线上不同。很多“本地能运行”的问题，来自部署平台不支持动态渲染、Route Handler、Server Action、数据库连接或流式响应。

## 三、核心用法

常见构建流程：

~~~text
安装依赖
    ↓
类型检查与 lint
    ↓
next build
    ↓
启动 next start
    ↓
配置生产环境变量
    ↓
运行数据库迁移
    ↓
检查日志、域名、缓存和健康状态
~~~

常用脚本：

~~~json
{
  "scripts": {
    "dev": "next dev",
    "build": "next build",
    "start": "next start",
    "lint": "eslint ."
  }
}
~~~

静态导出适合完全静态的网站：

~~~ts
// next.config.ts
const nextConfig = {
  output: 'export',
};

export default nextConfig;
~~~

但使用数据库直连、Server Actions、Route Handlers、动态服务器渲染和 AI 流式响应时，不能把静态导出当作默认方案。

## 四、核心原理

### 1. 部署目标必须匹配运行时

| 应用能力 | 静态文件托管 | Node.js / 支持 Next 运行时的平台 |
| --- | --- | --- |
| 静态页面和资源 | 适合 | 适合 |
| Server Component 服务器取数 | 不适合 | 适合 |
| Route Handler | 不适合 | 适合 |
| Server Action | 不适合 | 适合 |
| PostgreSQL 直连 | 不适合 | 适合 |
| AI 长响应流 | 通常不适合 | 需要确认平台支持 |

### 2. 构建时和运行时配置

公开环境变量可能在构建阶段被内联；私密变量应在服务器运行时提供。不同平台对变量注入、构建环境和运行时环境的处理不同，发布前要验证。

### 3. 可观测性是功能的一部分

生产应用至少要能定位：

- 哪个请求失败。
- 哪个用户或请求 ID 相关。
- 数据库和第三方 API 延迟。
- AI 流式在哪一步中断。
- 是否发生权限拒绝或异常重试。

## 五、常见场景

- Vercel：适合 Next.js 体验和预览部署。
- 自建 Node.js：适合需要控制运行时、网络和部署流程。
- 容器：适合统一环境和后续接入云平台。
- GitHub Pages：只适合静态导出，不适合完整 Next.js 全栈能力。

## 六、踩坑点

- 只上传构建出的静态文件，却期待 Server Actions 工作。
- 本地 .env.local 有值，线上平台没有配置。
- 线上使用开发数据库或共享预览数据库。
- 迁移脚本和应用启动顺序不清楚。
- 忽略数据库连接池和区域延迟。
- 部署后缓存、Cookie、域名和 HTTPS 配置不一致。
- AI 流式在本地正常，但平台代理会缓冲或提前超时。

## 七、项目中的实际使用

你的个人资料库本身是静态内容，继续使用 GitHub Pages 没问题。未来如果用 Next.js 做真正的全栈 AI 应用，应单独部署到支持服务器运行时的平台。

建议先部署一个没有数据库的小 Next.js 项目，再加入 PostgreSQL，最后加入 AI 流式。每次只增加一个线上变量和一种运行时能力，问题更容易定位。

## 八、一句话总结

部署不是把文件上传，而是让代码、运行时、数据库、密钥和网络能力彼此匹配。

## 九、核心问答

### 1. GitHub Pages 能运行完整 Next.js 全栈应用吗？

通常只能承载静态导出，不能直接承载需要服务器运行时的数据库访问、Server Actions、Route Handlers 和 AI 流式。

### 2. 为什么生产环境要单独配置环境变量？

本地配置不会自动进入云平台，且不同环境必须使用不同密钥、数据库和回调地址。

### 3. 为什么部署后 AI 流式可能失效？

平台代理、函数超时、响应缓冲和运行时限制都可能破坏持续输出，需要验证平台对流式响应的支持。

### 4. 最小上线检查是什么？

构建通过、环境变量齐全、数据库可连接、权限生效、错误日志可见、页面和流式请求在真实域名下可用。
