# Next.js 跨章节综合问答

> 优先级：⭐ 必须掌握：用于主动回忆和检查全链路判断。

这篇用于主动回忆。先遮住答案，只根据问题说出“运行位置、数据来源、权限、缓存和失败状态”。

## 一、总依赖关系

~~~text
React
  ↓
App Router：URL 与组件树
  ↓
Server / Client：网络边界
  ↓
数据获取：读什么、何时读
  ↓
loading / error / not-found：怎么反馈
  ↓
Server Action / Route Handler：怎么写、怎么对外提供
  ↓
认证 / 授权 / 环境变量：谁能做、秘密在哪
  ↓
PostgreSQL：数据如何持久化
  ↓
缓存重新验证：写入后如何变新
  ↓
部署 / AI 流式：如何交付和扩展
~~~

## 二、跨章节核心问答

### 1. 一个 URL 到页面显示，中间发生了什么？

App Router 根据 app 目录匹配路由段，执行对应 layout 和 page。默认的 Server Component 在服务器获取数据并生成结果，需要交互的 Client Component 通过客户端边界完成 hydration。

### 2. 页面、Route Handler、Server Action 如何分工？

- 页面：返回 UI。
- Route Handler：处理明确的 HTTP 请求和响应。
- Server Action：执行应用内的服务器命令，常用于表单和变更。

它们都可以调用共享的数据访问层，但都不能绕过权限检查。

### 3. 什么时候选 Server Component，什么时候选 Client Component？

默认 Server。需要状态、事件、Effect、浏览器 API 或客户端 Hook 时，把最小交互区域拆为 Client。

### 4. 为什么数据读取和数据库客户端不应该分散在组件中？

分散后很难统一类型、权限、缓存、错误和连接管理。集中数据访问层可以让组件只声明需要什么数据。

### 5. 为什么加载、错误、not-found 和空数据不能合并？

它们代表不同事实：

| 状态 | 意义 |
| --- | --- |
| loading | 还没有结果 |
| error | 执行失败 |
| not-found | 资源不存在 |
| empty | 成功但结果集合为空 |
| success | 成功并有内容 |

### 6. Server Action 是否可以不做授权？

不可以。客户端能触发的服务器函数都应把输入视为不可信，并检查身份、资源归属和操作权限。

### 7. 缓存重新验证解决的是什么问题？

解决“数据库已更新，但页面或数据读取仍复用旧结果”的问题。要根据标签、路径和用户是否立即看到新数据选择策略。

### 8. Next.js 和 AI SDK 分别负责什么？

Next.js 提供路由、服务器运行、Route Handler 和流式响应基础；AI SDK 提供模型调用、消息协议和 React 聊天状态工具。AI SDK 不是 Next.js 内置 API。

## 三、综合场景题

### 场景：用户搜索并编辑一篇学习笔记

请按顺序说明：

1. 搜索条件放在哪里？
2. 列表和详情使用什么组件？
3. 数据在哪里读取？
4. 编辑由什么触发？
5. 如何检查权限？
6. 成功后如何更新界面？
7. 失败和资源不存在如何显示？

<details>
<summary>参考答案</summary>

1. 如果需要分享、刷新和回退，放在 URL searchParams。
2. 页面和数据内容优先 Server Component；搜索输入和编辑表单是 Client Component。
3. 通过服务器数据访问层读取 PostgreSQL。
4. 当前页面表单优先使用 Server Action；独立客户端或外部调用使用 Route Handler。
5. 服务器检查会话、笔记存在性和作者或角色权限。
6. 数据库写入成功后让相关缓存标签或路径失效，并返回成功状态或重定向。
7. 请求期间显示 loading；查询不到使用 not-found；异常进入 error；搜索成功但无结果显示 empty。

</details>

## 四、进入真实 AI 全栈项目前的清单

- 能解释 app、page、layout 和动态路由。
- 能独立拆出 Server Component 与 Client Component。
- 能在 Server Component 读取数据库。
- 能写 loading、error 和 not-found。
- 能区分 Route Handler 和 Server Action。
- 能完成一个带服务端校验的表单。
- 能在服务器完成认证和授权。
- 能保护环境变量和数据库连接。
- 能在写入后重新验证缓存。
- 能部署到支持 Next.js 运行时的平台。
- 能处理 AI 流式的提交、生成、完成、错误、停止和重试。

## 五、最终自测

1. 为什么一个纯静态资料库可以部署到 GitHub Pages，而带 PostgreSQL 和 Server Actions 的应用不适合？
2. 一个 Client Component 需要数据库数据时，推荐的组件组合方式是什么？
3. 用户已经登录但没有这篇笔记的编辑权限，应该在哪一步拒绝？
4. 页面显示旧数据时，如何区分数据库问题、缓存问题和客户端状态问题？
5. AI 流式已经返回部分内容后失败，为什么不能简单把 HTTP 状态改成 500？
6. 如果只能用一个星期学习 Next.js，哪些主题必须先学，哪些可以推迟？

<details>
<summary>参考答案</summary>

1. GitHub Pages 只提供静态文件，不能执行服务器代码、访问数据库或维持服务端流。
2. Server Component 读取数据并把可序列化 Props 传给最小的 Client Component。
3. 在 Server Action、Route Handler 或数据访问层真正执行操作之前拒绝，不能只在页面隐藏按钮。
4. 先检查数据库写入结果，再检查标签或路径失效，最后检查客户端是否仍持有旧状态或请求竞争结果。
5. 响应头通常已经发送，后续只能通过流协议传递错误或让客户端进入 error 状态。
6. 先学 App Router、page/layout、动态路由、Server/Client、数据获取、loading/error、Server Action、环境变量和一次数据库 CRUD；复杂缓存内部、并行路由和高级部署可以推迟。

</details>

## 六、一句话总结

Next.js 的学习终点不是记住所有文件名，而是能够沿着一次请求解释：它在哪里运行、读取什么、谁有权限、是否缓存、失败怎么恢复，以及如何部署。
