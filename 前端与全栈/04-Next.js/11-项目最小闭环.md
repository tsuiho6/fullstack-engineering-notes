# Next.js 项目最小闭环

> 优先级：⭐ 必须掌握：把路由、读取、写入、权限、缓存和交付串成一个功能。

## 一、是什么

最小闭环是一个可以从 URL 进入、读取数据、展示状态、提交修改、检查权限、更新缓存并部署运行的真实功能。

本笔记用“全栈学习资料库”作为练习项目：

~~~text
公开阅读 → 搜索 → 笔记详情 → 登录 → 新增/编辑/删除
                         ↓
                    AI 摘要与问答
~~~

## 二、为什么需要

只学目录和 API 容易产生“都看过但不会做”的错觉。一个小项目会强迫你处理组件边界、URL、数据库、表单、权限、错误、缓存和部署之间的真实关系。

## 三、核心用法

推荐目录：


最小功能分阶段：

1. 静态首页和笔记列表。
2. 动态详情页与 not-found。
3. PostgreSQL 读取。
4. 搜索参数和分页。
5. 登录与受保护 dashboard。
6. Server Action 新增、编辑、删除。
7. 缓存重新验证和错误恢复。
8. AI 流式摘要。
9. 生产部署。

## 四、核心原理

一个功能的完整链路：

~~~text
URL / 表单
    ↓
路由入口
    ↓
Server Component 或 Client Component
    ↓
数据访问 / Server Action / Route Handler
    ↓
认证与授权
    ↓
数据库或模型服务
    ↓
缓存失效与 UI 状态
~~~

每个功能都要同时回答：

- 数据由谁拥有？
- 哪段代码运行在服务器？
- 输入在哪里校验？
- 哪一步检查权限？
- 成功后哪一份缓存需要失效？
- 失败、空数据和中断如何表现？

## 五、常见场景

- 内容资料库：适合先做公开读，再做后台写。
- AI 笔记助手：适合最后加入，避免一开始被模型调用细节带偏。
- 用户系统：先理解认证，再实现资源级授权。
- PostgreSQL：先完成 CRUD，再学习索引和查询优化。

## 六、踩坑点

- 一开始就做完整 AI Agent，跳过路由、表单和数据层。
- 只写 happy path，没有 loading、error、empty 和 not-found。
- 所有代码都放 page.tsx，组件和数据访问难以测试。
- 只在客户端判断权限。
- 写入成功后不重新验证缓存。
- 把静态资料库部署经验直接套到动态全栈应用。

## 七、项目中的实际使用

建议每个阶段都留下一个可运行版本：

| 阶段 | 可验证结果 |

## 八、一句话总结

真正掌握 Next.js 的标志，是能把一次用户动作完整地走过路由、组件、服务器、数据库、权限、缓存和反馈。

## 九、核心问答

### 1. 为什么先做公开阅读，再做后台写入？

公开读取能先建立路由、Server Component、数据库读取和错误边界；写入会进一步引入表单、权限和缓存复杂度。

### 2. 为什么 AI 功能最后做？

AI 只是数据源和交互协议的一种，若基础请求、状态和权限不稳定，AI 流式只会放大问题。

### 3. 什么叫“功能闭环”？

不是页面看起来能打开，而是输入、处理、持久化、反馈、错误恢复和权限都能被验证。

### 4. 如何判断一个阶段可以继续？

能解释原理、独立写出最小代码、判断使用场景、处理异常，并能在项目中复现。
