# Next.js 心智模型与学习路线

> 优先级：⭐ 必须掌握：建立 App Router、服务端/客户端边界和全栈数据流的总模型。

## 一、是什么

Next.js 是建立在 React 之上的全栈 Web 框架。React 负责组件和 UI；Next.js 负责应用级的路由、服务端渲染、数据访问、缓存、接口、部署和性能约定。

可以先用这个模型理解：

~~~text
用户请求 URL
    ↓
App Router 匹配路由段
    ↓
Server Component 获取数据并生成 RSC / HTML
    ↓
Client Component 接管交互
    ↓
Server Action 或 Route Handler 写入数据
    ↓
重新验证缓存并更新页面
~~~

## 二、为什么需要

只用 React，需要自己组合路由、服务端渲染、数据请求、接口、构建和部署方案。Next.js 把这些高频问题放入统一的文件约定和运行时模型中。

但它也增加了新的判断：一段代码究竟运行在服务器还是浏览器，数据何时读取，缓存何时失效，以及谁有权执行写操作。

## 三、核心用法

学习 Next.js 时，始终围绕一个真实页面练习：

~~~text
学习笔记详情页
    ├─ URL：/notes/[slug]
    ├─ Server Component：读取笔记
    ├─ Client Component：收藏、复制、主题切换
    ├─ loading.tsx：数据加载时的占位
    ├─ not-found.tsx：slug 不存在
    ├─ error.tsx：页面级错误恢复
    └─ Server Action：修改收藏状态
~~~

每增加一个概念，都回答四个问题：

1. 它解决哪一类请求或渲染问题？
2. 它运行在服务器还是客户端？
3. 它的数据输入和输出是什么？
4. 它失败或缓存过期时页面怎么表现？

## 四、核心原理

### 1. 路由是文件系统与运行时约定

app 目录中的文件不是普通组件目录。文件名和目录位置会参与构建，决定 URL、布局继承、加载边界和错误边界。

### 2. Server 与 Client 是网络边界

Server Component 运行在服务器，可直接访问数据库和私密凭证；Client Component 被发送到浏览器，需要承担 JavaScript 体积、序列化和交互成本。

### 3. 数据生命周期决定用户体验

读取数据不仅是调用函数，还包括：

~~~text
数据来源 → 是否缓存 → 何时重新验证 → 加载反馈 → 失败恢复 → 写入后的新鲜度
~~~

### 4. 写入必须经过权限边界

无论是 Server Action 还是 Route Handler，客户端隐藏按钮都不是安全措施。真正的认证和授权检查必须发生在服务器的数据访问或写操作附近。

## 五、常见场景

- 内容型页面：Server Component 读取数据，尽量减少客户端 JavaScript。
- 强交互页面：Server Component 负责页面和数据，Client Component 负责局部交互。
- 浏览器或第三方系统需要调用的接口：Route Handler。
- 页面表单直接触发数据库写入：Server Action。
- 需要搜索、分页、分享和可回退的筛选条件：URL search params。
- 需要实时输出：流式 Response 或 AI SDK。

## 六、踩坑点

- 把 Next.js 当成“所有组件默认都在浏览器运行”的 React SPA。
- 为了使用一个 onClick，把整个页面树都标记为 Client Component。
- 以为 Route Handler 和 Server Action 可以互相替代。
- 只在客户端判断登录状态，服务器写操作却不检查权限。
- 看到缓存问题就盲目添加动态配置，没有先确定数据的新鲜度要求。
- 将需要 Node.js 运行时的功能部署到只支持静态文件的托管环境。

## 七、项目中的实际使用

建议用一个“学习资料库”作为贯穿项目：

1. 静态首页与笔记列表。
2. 动态笔记详情页。
3. PostgreSQL 存储笔记和标签。
4. 表单新增、编辑、删除。
5. 登录后才能编辑。
6. 让 AI 对笔记生成摘要，并实时显示。
7. 部署到支持服务器运行时的平台。

这个项目足够覆盖你的短期 Next.js 学习目标，也能自然衔接中期的 PostgreSQL 和 AI 应用。

## 八、一句话总结

Next.js 的核心是把一次 URL 请求组织成“路由、渲染、数据、权限、缓存和部署”的完整链路。

## 九、核心问答

### 1. React 和 Next.js 的边界是什么？

React 解决组件和 UI 更新；Next.js 解决应用路由、服务器运行、数据访问、缓存、接口和部署。

### 2. 为什么 Next.js 学习必须先掌握 React？

因为 Server Component、Client Component、Suspense、表单交互和状态边界都建立在 React 组件模型之上。

### 3. Next.js 应用中最重要的判断是什么？

判断代码运行环境、数据来源、数据新鲜度和权限边界。

### 4. 为什么不能只按目录逐页学习？

因为 Next.js 的难点不是 API 数量，而是多个概念在一次请求中协同工作。必须用一个小项目形成读、写、错误、缓存和部署的最小闭环。
