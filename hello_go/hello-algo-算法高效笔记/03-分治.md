# 分治

## 一、是什么

分治把一个大问题拆成若干规模更小、结构相同且相对独立的子问题，递归解决后再合并结果。核心不是“必须递归”，而是子问题之间足够独立，分解与合并的成本可控。

## 二、为什么需要

直接处理大问题往往结构混乱；拆小后，每个子问题更容易定义和验证。二分查找、归并排序、快速排序、按遍历序列构建树都利用了这一思想。

## 三、核心用法

### ⭐ 通用框架

```go
func solve(problem Problem) Result {
    if isSmall(problem) {
        return baseCase(problem)
    }
    left, right := split(problem)
    leftAns := solve(left)
    rightAns := solve(right)
    return combine(leftAns, rightAns)
}
```

实际写题时把 `Problem/Result` 换成具体切片、区间、树节点或索引。每次递归前必须明确：规模如何变小、基例是什么、合并是否需要复制数据。

### ⭐ 分治复杂度

若每层产生 `a` 个规模为 `n/b` 的子问题，并且合并成本为 `f(n)`：

```text
T(n) = aT(n/b) + f(n)
```

直观含义：总成本等于所有子问题成本，加上当前层拆分/合并成本。归并排序是 `2T(n/2)+O(n)`，因此为 `O(n log n)`；二分查找只有一个子问题，且没有线性合并，得到 `O(log n)`。

### ⭐ 分治构建二叉树

由前序和中序序列构建唯一二叉树时，前提是节点值不重复：

```go
// TreeNode 使用数据结构笔记中的定义：Val、Left、Right。
func buildTree(preorder, inorder []int) *TreeNode {
    pos := make(map[int]int, len(inorder))
    for i, v := range inorder {
        pos[v] = i
    }

    var build func(int, int, int, int) *TreeNode
    build = func(pl, pr, il, ir int) *TreeNode {
        if pl > pr || il > ir {
            return nil
        }
        rootVal := preorder[pl]
        k := pos[rootVal]
        leftSize := k - il
        root := &TreeNode{Val: rootVal}
        root.Left = build(pl+1, pl+leftSize, il, k-1)
        root.Right = build(pl+leftSize+1, pr, k+1, ir)
        return root
    }
    return build(0, len(preorder)-1, 0, len(inorder)-1)
}
```

输入输出形状是 `[]int, []int → *TreeNode`；哈希表定位根在中序中的位置，使总时间 `O(n)`、额外空间 `O(n)`。没有 map 时每层扫描中序，最坏会退化到 `O(n²)`。

### △ 递归二分

递归二分是分治的直接例子：每次只递归到左或右半区间。工程和 LeetCode 中迭代写法通常更省栈，递归版本主要用于理解“只保留一个子问题”。

### △ 汉诺塔

汉诺塔把 `n` 个盘的移动拆为：先把 `n-1` 个盘移到辅助柱，再移动最大盘，最后把 `n-1` 个盘移到目标柱。移动次数满足：

```text
T(n) = 2T(n-1) + 1 = 2^n - 1
```

直观含义：递归树每层都复制两份工作，规模增长是指数级；它适合训练递归状态，不适合作为高频刷题模板。

## 四、核心原理

### 1. 分解必须保持信息完整

拆出子问题时，不能丢掉合并所需的信息。构建树时需要知道前序和中序的对应区间；归并排序需要两个有序半段；若分解后无法确定结果如何合并，说明状态或切分方式还不完整。

### 2. 分治与动态规划的区别

- 分治：子问题通常独立，重复较少，结果在合并处汇总。
- DP：子问题高度重叠，同一个状态会被反复计算，需要缓存/表格复用。

直观判断：若把递归调用画成树，出现大量相同状态，分治应考虑升级为 DP。

### 3. 递归栈是空间成本

递归深度为 `h` 时，调用栈至少需要 `O(h)`；若切片合并还创建新数组，空间要把两部分相加。不能只写时间复杂度而忽略递归和复制。

## 五、常见场景

- 归并排序、快排、二分查找。
- 根据遍历序列构建树、递归处理子树。
- 统计逆序对、区间递归、最近点等需要“拆分 + 合并”的问题。
- 汉诺塔等递归练习。

不适合：子问题强烈重叠却没有缓存；合并成本和原问题一样大且无法控制；递归深度可能超过栈限制而又没有必要递归。

## 六、踩坑点

1. **基例必须覆盖空区间/单元素**，否则递归不会收敛。
2. **区间端点要统一**：`[l,r]` 与 `[l,r)` 的长度、切分和基例不能混用。
3. **构建树需要值唯一**：重复值时仅凭前序/中序通常不能唯一定位根。
4. **切片切分共享底层数组**：若递归会原地修改，要确认子问题是否互相影响。
5. **合并时不要重复复制**：多层 `append` 可能隐藏额外空间和时间。
6. **汉诺塔指数复杂度不要误写成 `O(n log n)`**。
7. **分治不等于 DP**：没有重复状态时不要为了“记忆化”增加复杂结构。

## 七、项目中的实际使用

工程里优先把递归函数的区间和返回值写成明确契约：

```text
build(pl, pr, il, ir) 返回：由 preorder[pl:pr+1] 和 inorder[il:ir+1] 构成的子树根
```

当递归只读输入，可共享切片；当需要原地修改或异步保存结果，要显式复制。对深度不受控的输入，优先改成显式栈或迭代。

## 八、一句话总结

**分治的关键是“子问题独立、信息不丢、合并可控”，递归只是表达方式。**

## 九、核心问答

1. **为什么归并排序是分治而不是 DP？**
   - 左右区间通常独立，子问题不大量重复；结果在一次合并中汇总。
2. **构建树时为什么用 map？**
   - 由根值快速定位它在中序中的位置，将左右子树区间切开，避免每层线性扫描。
3. **如何判断分治递归是否会收敛？**
   - 每次调用的规模必须严格小于当前问题，并最终到达可直接处理的基例。
4. **为什么递归版本的二分不一定优于迭代版？**
   - 两者时间相同；递归多了调用栈和函数调用开销，迭代更适合工程热点。
5. **什么时候分治应改成 DP？**
   - 发现多个递归分支会反复求同一个状态时，用缓存或状态表复用结果。

## 十、自测与答案

### 题目

1. `T(n)=2T(n/2)+O(n)` 的复杂度是什么？
2. 构建树递归中 `leftSize := k-il` 表示什么？
3. 为什么前序 + 中序通常要求节点值不重复？
4. 分治算法的空间复杂度除了临时数组，还要考虑什么？
5. 汉诺塔的移动次数为什么是指数级？

<details>
<summary>答案</summary>

1. `O(n log n)`；每层合并总成本 `O(n)`，递归深度 `O(log n)`。
2. 根在中序区间中的位置减去区间左端，表示左子树节点数。
3. 根值才能唯一映射到中序位置；重复值会产生多个候选切分。
4. 递归调用栈、缓存、输出容器以及切片复制的额外空间。
5. 每次要移动两个规模为 `n-1` 的子问题，再移动一次最大盘，满足 `T(n)=2T(n-1)+1`。
