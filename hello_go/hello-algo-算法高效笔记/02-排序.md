# 排序

## 一、是什么

排序把一组元素按某个比较规则重排，使后续查找、双指针、去重、区间处理或贪心选择更容易。排序算法的差异主要在时间复杂度、额外空间、稳定性和是否原地。

## 二、为什么需要

无序数据中的关系常常难以直接利用；排序后，大小、相邻、边界和重复值变得可见。例如两数之和可以用哈希，也可以排序后用双指针；区间调度常先按结束时间排序。

## 三、核心用法

### ⭐ Go 项目推荐

```go
import "sort"

sort.Ints(nums) // []int 升序，原地修改
sort.Slice(items, func(i, j int) bool {
    return items[i].Score < items[j].Score
})
```

自定义排序的比较函数必须表达严格弱序：不能在 `Less` 中修改数据，也不要让比较关系循环矛盾。若需要稳定地保留相等元素的相对顺序，使用 `sort.SliceStable`。

### ⭐ 复杂度地图

| 算法 | 最好 | 平均 | 最坏 | 额外空间 | 稳定性 | 主干级别 |
|---|---:|---:|---:|---:|---|---|
| 选择排序 | `O(n²)` | `O(n²)` | `O(n²)` | `O(1)` | 通常不稳定 | ○ |
| 冒泡排序 | `O(n)`* | `O(n²)` | `O(n²)` | `O(1)` | 稳定 | ○ |
| 插入排序 | `O(n)` | `O(n²)` | `O(n²)` | `O(1)` | 稳定 | △ |
| 快速排序 | `O(n log n)` | `O(n log n)` | `O(n²)` | `O(log n)`平均 | 通常不稳定 | ⭐理解 |
| 归并排序 | `O(n log n)` | `O(n log n)` | `O(n log n)` | `O(n)` | 稳定 | ⭐理解 |
| 堆排序 | `O(n log n)` | `O(n log n)` | `O(n log n)` | `O(1)` | 不稳定 | △ |
| 计数排序 | `O(n+k)` | `O(n+k)` | `O(n+k)` | `O(k)` | 可稳定 | △ |
| 桶/基数排序 | 依赖分布 | 依赖分布 | 依赖分布 | 依赖桶 | 可稳定 | ○ |

`*` 冒泡排序只有在实现了提前退出且输入接近有序时才达到最好情况。

### ⭐ 快速排序：分区不变量

教学和面试中要理解分区；工程中优先用 `sort`。

```go
func quickSort(a []int, l, r int) {
    if l >= r {
        return
    }
    i, j := l, r
    pivot := a[l+(r-l)/2]
    for i <= j {
        for a[i] < pivot {
            i++
        }
        for a[j] > pivot {
            j--
        }
        if i <= j {
            a[i], a[j] = a[j], a[i]
            i++
            j--
        }
    }
    if l < j {
        quickSort(a, l, j)
    }
    if i < r {
        quickSort(a, i, r)
    }
}
```

关键不是背代码，而是保证每轮交换后：左侧候选不大于 pivot，右侧候选不小于 pivot，并且 `i/j` 都向内移动。重复值很多时必须确保指针会推进，否则可能死循环。

### ⭐ 归并排序：稳定合并

```go
func mergeSort(a []int) []int {
    if len(a) <= 1 {
        return a
    }
    mid := len(a) / 2
    left := mergeSort(a[:mid])
    right := mergeSort(a[mid:])
    out := make([]int, 0, len(a))
    i, j := 0, 0
    for i < len(left) && j < len(right) {
        if left[i] <= right[j] {
            out = append(out, left[i])
            i++
        } else {
            out = append(out, right[j])
            j++
        }
    }
    out = append(out, left[i:]...)
    out = append(out, right[j:]...)
    return out
}
```

输入输出形状是 `[]int → []int`；这份教学代码返回新切片，额外空间 `O(n)`。需要原地排序时使用标准库或专门的底层实现，不要把“返回新切片”的版本误称为原地。

### △ 计数排序

当整数值域 `[min,max]` 很窄时，用频次数组代替比较：

```go
func countingSort(nums []int) []int {
    if len(nums) == 0 {
        return nil
    }
    minV, maxV := nums[0], nums[0]
    for _, x := range nums[1:] {
        if x < minV {
            minV = x
        }
        if x > maxV {
            maxV = x
        }
    }
    count := make([]int, maxV-minV+1)
    for _, x := range nums {
        count[x-minV]++
    }
    out := make([]int, 0, len(nums))
    for offset, c := range count {
        for ; c > 0; c-- {
            out = append(out, offset+minV)
        }
    }
    return out
}
```

它的复杂度是 `O(n+k)`，其中 `k=max-min+1`；若值域巨大而元素很少，会浪费大量内存，不如比较排序或 map 计数。

### ○ 桶排序、基数排序、堆排序

它们适合特殊输入分布或特殊内存约束。当前刷题主干只需知道：桶排序依赖均匀分布，计数排序依赖小整数值域，基数排序按位稳定处理，堆排序利用堆不变量获得 `O(n log n)` 且额外空间小。

## 四、核心原理

### 1. 比较排序的下界直觉

只通过元素比较来排序时，需要区分大量排列，通常不能突破 `Ω(n log n)` 的比较次数；计数、桶、基数排序之所以能更快，是利用了值域、位数或分布等额外信息。

### 2. 稳定性为什么重要

若先按年龄排序，再按姓名稳定排序，前一次的年龄顺序仍能作为次关键字保留。直观含义：相等元素的相对顺序是额外信息；不稳定排序可能丢掉它。

### 3. 快排与归并的取舍

快排通常原地、缓存友好、常数小，但最坏可退化；归并复杂度稳定、天然稳定，代价是额外数组。工程标准库会综合考虑这些因素，不应只根据理论平均值手写生产级排序。

## 五、常见场景

- 普通整数/结构体排序：`sort.Ints`、`sort.Slice`。
- 需要稳定多关键字排序：`sort.SliceStable`。
- 排序后双指针、去重、合并区间：先排序再扫描。
- 统计小范围整数频次：计数排序/频次数组。
- 需要保留原始下标：排序 `struct{value,index int}`，不要直接改原数组后再猜下标。

## 六、踩坑点

1. **排序通常原地修改切片**：需要保留原数据就复制一份。
2. **自定义 `Less` 不要写成 `<=`**：严格相等时应返回 false，否则可能破坏排序约束。
3. **快排分区要推进指针**：重复值多时容易死循环。
4. **归并代码的 `<=` 决定稳定性**：相等时优先取左侧。
5. **计数排序值域可能溢出或过大**：`max-min+1` 要先检查范围。
6. **排序后下标失效**：需要索引就和元素打包保存。
7. **算法复杂度与实现空间要一起写**：新建 `out` 的归并版本不是 `O(1)` 空间。
8. **只要 Top-K 不一定要完整排序**：可用堆把空间和时间压到 `O(k)` 相关规模。

## 七、项目中的实际使用

普通业务代码直接使用标准库：

```go
sort.Slice(records, func(i, j int) bool {
    if records[i].Score != records[j].Score {
        return records[i].Score > records[j].Score
    }
    return records[i].ID < records[j].ID
})
```

先写清主关键字、次关键字、是否稳定和是否允许修改输入，再选择 `sort.Slice` 或 `sort.SliceStable`。只有算法题要求实现排序本身、统计逆序对或利用分区过程时，才手写对应算法。

## 八、一句话总结

**工程用标准库排序，刷题要理解分区、合并、稳定性和特殊值域的边界。**

## 九、核心问答

1. **什么时候选择归并而不是快排？**
   - 需要稳定性、稳定的 `O(n log n)` 最坏保证，或要在合并过程中统计信息时。
2. **为什么计数排序不总比快排快？**
   - 它依赖值域 `k`；当 `k` 远大于 `n` 时，初始化和空间成本很高。
3. **排序的稳定性什么时候有用？**
   - 多关键字排序、需要保留相等元素原顺序、或相等元素承载额外顺序信息时。
4. **为什么排序后双指针能工作？**
   - 排序让移动指针具有方向性：某个和太小只能增大左指针，太大只能减小右指针。
5. **为什么快排平均 `O(n log n)` 但最坏 `O(n²)`？**
   - 分区平衡时递归深度为 `log n`；每次都极不平衡时会形成长度约 `n` 的递归链。

## 十、自测与答案

### 题目

1. 需要按分数降序、ID 升序排序，`Less` 应如何写？
2. 归并排序为什么天然适合统计逆序对？
3. 计数排序中 `k=max-min+1` 为什么是关键？
4. 排序前后都要使用原始下标，数据应该如何保存？
5. 什么时候完整排序不是最省的选择？

<details>
<summary>答案</summary>

1. 先比较分数 `>`；分数相等时比较 ID `<`。
2. 左右半段各自有序，合并时若右侧元素先出，则它会与左侧当前及之后所有元素形成逆序，可批量统计。
3. 它决定频次数组大小和额外空间；值域越宽，计数排序越不划算。
4. 保存 `struct{ value, index int }`，排序结构体而不是丢弃索引。
5. 只需要 Top-K、判断阈值、或数据值域很小可用计数/堆/选择性扫描时。
