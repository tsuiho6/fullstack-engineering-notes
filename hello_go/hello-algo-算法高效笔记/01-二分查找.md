# 二分查找

## 一、是什么

二分查找利用有序性或单调性，每次排除一半不可能区域，在 `O(log n)` 时间内定位目标或边界。它本质上不是“找某个数”，而是维护一个不会丢失答案的区间。

## 二、为什么需要

线性扫描每次要看一个元素；有序数组允许通过中点判断整段方向。更一般地，只要存在一个布尔谓词 `P(x)`，使它从 `false` 单调变成 `true`，就可以二分“答案空间”。

## 三、核心用法

### ⭐ 精确查找：双闭区间

**输入输出形状**：升序 `[]int` + `target int` → 下标 `int`；不存在返回 `-1`；不修改输入。

```go
func binarySearch(nums []int, target int) int {
    l, r := 0, len(nums)-1 // 搜索区间 [l, r]
    for l <= r {
        m := l + (r-l)/2
        if nums[m] < target {
            l = m + 1
        } else if nums[m] > target {
            r = m - 1
        } else {
            return m
        }
    }
    return -1
}
```

当 `nums[m] < target` 时，`m` 以及左侧都不可能是答案；当 `nums[m] > target` 时同理排除右侧。

### ⭐ 插入点 / lower bound：半开区间

返回第一个满足 `nums[i] >= target` 的下标；如果不存在，返回 `len(nums)`。

```go
func lowerBound(nums []int, target int) int {
    l, r := 0, len(nums) // 搜索区间 [l, r)
    for l < r {
        m := l + (r-l)/2
        if nums[m] < target {
            l = m + 1
        } else {
            r = m
        }
    }
    return l
}
```

返回第一个满足 `nums[i] > target` 的下标，即 upper bound：

```go
func upperBound(nums []int, target int) int {
    l, r := 0, len(nums)
    for l < r {
        m := l + (r-l)/2
        if nums[m] <= target {
            l = m + 1
        } else {
            r = m
        }
    }
    return l
}
```

在重复值数组中：

- `lowerBound` 找左边界；
- `upperBound-1` 找右边界；
- 出现次数是 `upperBound-lowerBound`。

### ⭐ Go 标准库写法

对升序 `[]int` 可使用 `sort.Search`：

```go
import "sort"

idx := sort.Search(len(nums), func(i int) bool {
    return nums[i] >= target
})
```

它返回第一个使谓词为 `true` 的位置；若不存在，返回 `len(nums)`。项目中推荐标准库，面试/刷题要能手写边界。

### ⭐ 二分答案

当答案范围为 `[lo, hi]`，且 `feasible(x)` 具有单调性（例如超过某值后全部可行）时：

```go
func firstTrue(lo, hi int, feasible func(int) bool) int {
    for lo < hi {
        mid := lo + (hi-lo)/2
        if feasible(mid) {
            hi = mid
        } else {
            lo = mid + 1
        }
    }
    return lo
}
```

先确认 `hi` 确实可行；如果没有可行解，必须由题目逻辑单独处理。

## 四、核心原理

### 1. 区间不变量

闭区间版本的核心不变量是：若答案存在，它始终位于 `[l,r]`。每次比较后，更新为 `[m+1,r]` 或 `[l,m-1]`，严格排除已经证明不可能的位置。

半开区间版本常维护：`[0,l)` 已知不满足，`[r,n)` 已知满足，答案在 `[l,r)`。循环结束时 `l==r`，边界自然落在插入点。

### 2. 为什么是 `O(log n)`

每轮把候选数量约减半：

```text
n → n/2 → n/4 → ... → 1
```

满足 `n / 2^k <= 1` 的最小 `k` 约为 `log₂n`。直观含义是每次获得一位“方向信息”，快速排除一半候选。

### 3. 二分的真正前提

不是“数组看起来排过序”，而是：比较结果能把答案空间分成“左边不可能、右边可能”或“左边可行、右边不可行”的单调两段。没有单调性，二分可能静默返回错误结果。

## 五、常见场景

- 升序数组查目标、左/右边界、插入位置。
- 旋转数组、峰值等具有局部单调结构的问题。
- 最小速度、最小容量、最大最小值等二分答案。
- `sort.Search` 查找第一个满足条件的位置。

不适合：无序且无单调谓词的数据；链表随机访问；答案可行性不单调的问题。

## 六、踩坑点

1. **区间表示混用**：`[l,r]` 用 `l<=r` 和 `m±1`；`[l,r)` 用 `l<r` 和 `r=m`，不能混写。
2. **中点不要写 `(l+r)/2`**：极大下标时可能溢出，用 `l+(r-l)/2`。
3. **重复值不能随便返回第一次命中的位置**：若题目要左/右边界，必须继续收缩。
4. **插入点可能等于 `len(nums)`**：返回后访问 `nums[idx]` 前要检查边界。
5. **二分答案的谓词必须单调**：先用小样例列出 `false/true` 序列。
6. **空数组和单元素要单测**：尤其是半开区间与 `len=0`。
7. **整数答案范围可能溢出**：`mid` 安全不代表 `feasible` 内部乘法安全，必要时用 `int64`。
8. **排序方向要一致**：降序数组不能直接套升序比较。

## 七、项目中的实际使用

工程代码优先使用 `sort.Search` 表达边界，手写版本用于需要自定义状态或减少闭包开销的热点路径。二分答案的 `feasible` 应独立成函数或清晰注释，写明输入、返回条件和复杂度，避免“二分套二分”后无法分析总成本。

## 八、一句话总结

**二分不是猜中点，而是维护一个不会丢失答案的单调区间。**

## 九、核心问答

1. **精确查找和 lower bound 的核心区别？**
   - 精确查找命中即可返回；lower bound 即使命中也继续向左收缩，找第一个满足条件的位置。
2. **为什么二分答案要求可行性单调？**
   - 只有单调时，检查一个中点才能排除整侧答案；否则中点信息不足以缩小范围。
3. **为什么 `sort.Search` 不存在目标时返回 `len(nums)`？**
   - 它返回第一个满足谓词的位置，若所有位置都不满足，边界就在序列末端。
4. **为什么链表不适合二分？**
   - 找中点需要沿指针走，单次不是 `O(1)` 随机访问，整体优势消失。
5. **什么时候用 `upperBound-lowerBound`？**
   - 升序数组中统计某个值的出现次数，或统计落在半开值域 `[a,b)` 的元素数量。

## 十、自测与答案

### 题目

1. 闭区间二分为什么在排除中点后使用 `m+1` 或 `m-1`？
2. `lowerBound([]int{1,2,2,4}, 2)` 返回多少？
3. `upperBound([]int{1,2,2,4}, 2)` 返回多少？
4. 二分答案前如何验证谓词是否可用？
5. `sort.Search` 找不到目标时，为什么不能直接访问返回下标？

<details>
<summary>答案</summary>

1. 因为当前 `m` 已经比较过且不满足目标，不能再次保留，否则可能死循环。
2. 返回 1，第一个 `>=2` 的位置。
3. 返回 3，第一个 `>2` 的位置。
4. 在答案范围上列出若干点，确认可行结果呈单调的全假后全真或全真后全假。
5. 返回值可能等于 `len(nums)`，它是插入点，不是合法元素下标。
