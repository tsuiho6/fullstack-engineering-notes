# 跨章节综合问答与最终自测

## 一、算法选择总表

| 题目线索 | 首选算法 | 关键验证 |
|---|---|---|
| 已排序，找值/边界 | 二分查找 | 区间不变量、重复值边界 |
| 答案范围可判断可行性 | 二分答案 | `false → true` 或相反的单调性 |
| 需要相邻关系、双指针、区间处理 | 排序 + 扫描 | 是否允许改变顺序、是否保留索引 |
| 子问题独立，结果可合并 | 分治 | 基例、规模缩小、合并成本 |
| 枚举排列/组合/棋盘方案 | 回溯 | 选择、剪枝、撤销、复制答案 |
| 重复状态 + 最优/计数/可行性 | DP | 状态定义、转移、顺序、初始化 |
| 局部选择可能安全 | 贪心 | 交换论证或其他正确性证明 |

## 二、跨章节核心问答

1. **二分查找和二分答案有什么本质区别？**
   - 前者在有序数据中定位元素/边界；后者在答案范围上调用可行性函数，要求可行性单调。

2. **排序为什么能帮助贪心，却不能自动证明贪心正确？**
   - 排序只确定选择顺序；仍需证明按这个顺序选不会损害全局最优。

3. **分治和回溯都使用递归，如何区分？**
   - 分治把问题拆成通常独立的子问题并合并；回溯在同一决策树上尝试多个选择并撤销状态。

4. **回溯和 DP 都会枚举状态，为什么复杂度不同？**
   - 回溯通常保留不同路径并可能指数枚举；DP 识别相同状态并复用结果，代价变为状态数乘转移数。

5. **为什么 0-1 背包常用 DP，而分数背包可以贪心？**
   - 0-1 物品不可切分，单位价值最高的选择可能阻塞更优组合；分数背包可切分，交换论证成立。

6. **为什么“排序 + 双指针”有时比哈希表更合适？**
   - 当需要有序输出、去重、控制空间或处理区间关系时，排序后的单调移动更容易表达；哈希表更适合一次精确查找。

7. **为什么 DP 状态定义不完整会导致转移看似正确却答案错误？**
   - 如果状态没有包含决定未来所需的历史信息，不同历史会被错误合并；同一个 `dp` 值无法代表所有后续情况。

8. **为什么回溯中的剪枝和贪心中的“提前放弃”不同？**
   - 回溯剪枝必须证明整个分支不可能有解；贪心直接固定一个选择，必须证明存在最优解包含它，证明强度不同。

9. **什么时候“先排序”会破坏算法？**
   - 题目依赖原始下标、原始相邻关系、时间顺序或稳定顺序时；可保存索引或换用 map/队列。

10. **如何判断一个算法模板是否真的掌握？**
    - 能解释不变量，能从空白写出，能说出使用前提和复杂度，能构造一个让错误变体失败的反例。

## 三、混合场景判断

### 场景 A：最小可行运输容量

若容量越大越容易完成运输，`feasible(capacity)` 呈 `false → true` 单调变化，使用二分答案；每次可行性检查按天/包裹扫描，整体复杂度为 `O(n log range)`。

### 场景 B：三数之和

先排序，再固定一个数，用左右双指针；排序提供方向性，双指针避免三重枚举。若要保留原始下标，排序前把值和下标打包。

### 场景 C：排列去重

先排序，让相同值相邻；在同一层跳过重复值，递归到下一层仍允许选择相同值的不同位置。不能简单用全局 `map` 把所有重复值都删掉，否则可能漏掉合法使用次数。

### 场景 D：硬币找零

先问硬币是否可重复、目标是最少枚数还是方案数。常见任意面额的最少枚数用 DP；不能因为每次拿最大面额看起来合理就直接贪心。

### 场景 E：区间选择

若目标是选择最多个互不重叠区间，通常按结束时间升序贪心，并证明最早结束留下的剩余空间最多。若还有权重、冲突收益或更多状态，可能需要 DP。

## 四、最终自测

### 题目

1. 写出 lower bound 的返回含义，并说明找不到目标时可能返回什么。
2. `n=20` 的全排列为什么可能允许回溯，而 `n=100` 通常不行？
3. 归并排序的合并阶段为什么是线性，而不是平方级？
4. 0-1 背包一维压缩为什么倒序，完全背包为什么正序？
5. 二分答案和普通二分都需要什么“单调性”？
6. 回溯结果为什么必须复制 `path`？
7. 给一个贪心算法失败时应该先做什么？
8. 题目要返回方案而不是最优值时，DP 需要额外保存什么？
9. 排序后双指针中，和太小或太大时分别移动哪一侧？
10. 如何估算“状态数 × 转移数”来判断 DP 是否可行？

<details>
<summary>答案</summary>

1. 返回第一个满足 `nums[i] >= target` 的下标；若所有元素都小于目标，返回 `len(nums)`。
2. 全排列规模约 `n!`；`n=20` 已经很大但在强约束题中可能有特殊剪枝，`n=100` 通常无法枚举全部排列。
3. 两个有序段各自只向前移动一次，每个元素最多比较/复制常数次，所以合并是 `O(n)`。
4. 倒序阻止当前物品在本轮重复使用；正序允许读取已经更新的同一物品状态。
5. 普通二分利用数据或谓词的单调分界；二分答案利用“答案越大/越小，可行性单调变化”。
6. 递归返回后 `path` 会被回退并复用；不复制就会让已记录结果跟着后续选择变化。
7. 构造最小反例，检查局部选择是否真的安全；若无法证明，改用 DP 或回溯，而不是继续堆样例。
8. 保存每个状态的选择/前驱，或保留足够信息从终点反向恢复路径；只存最优值无法还原方案。
9. 和太小移动左指针增大和；和太大移动右指针减小和；前提是数组已排序。
10. 先数状态维度和每维上限，再估算每个状态的转移数量；若乘积超出时间/内存预算就需要压缩状态或换算法。

## 五、复习检查表

合上笔记后，能完成以下动作，说明算法主干形成了最小闭环：

- 手写闭区间二分、lower bound、二分答案，并解释每个边界更新。
- 说明 Go 标准排序与快排/归并/计数排序的使用边界。
- 用一句话解释分治的基例、分解和合并。
- 从空白写出子集、排列、组合求和回溯，并指出哪里复制、哪里撤销。
- 对一维 DP 明确状态含义，解释 0-1 与完全背包的循环方向。
- 对一个贪心策略给出交换论证，或构造反例证明它不安全。
- 看到新题时，先写约束规模、候选算法、正确性依据和复杂度，再开始编码。

## 六、一句话总结

**真正的算法能力，是能说清“为什么这个模板在这里成立，以及什么时候它会失效”。**
