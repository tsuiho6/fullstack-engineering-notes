# 贪心

## 一、是什么

贪心算法每一步都选择当前看起来最优的方案，并且不回退，希望这些局部选择组合成全局最优。它的难点不在写循环，而在证明“这一步选了以后，仍然存在一个全局最优解包含它”。

## 二、为什么需要

如果问题满足合适的局部选择性质，贪心可以把 DP 或枚举压缩成一次排序 + 一次扫描，代码短、速度快、空间小。但没有证明时，贪心只是启发式，可能在简单样例之外失败。

## 三、核心用法

### ⭐ 贪心判断清单

1. 当前选择是否有明确的“最优指标”？
2. 选择它后，剩余问题是否仍是同类问题？
3. 能否用交换论证把任意最优解改造成包含当前选择的最优解？
4. 是否存在一个小反例，说明局部最优会阻塞更好的组合？

### ⭐ 分数背包：按单位价值贪心

物品可切分时，按 `value / weight` 从高到低取：

```go
func fractionalKnapsack(weights, values []float64, capacity float64) float64 {
    type item struct {
        weight, value, ratio float64
    }
    items := make([]item, len(weights))
    for i := range weights {
        items[i] = item{
            weight: weights[i],
            value:  values[i],
            ratio:  values[i] / weights[i],
        }
    }
    sort.Slice(items, func(i, j int) bool {
        return items[i].ratio > items[j].ratio
    })
    ans := 0.0
    for _, it := range items {
        if capacity <= 0 {
            break
        }
        take := it.weight
        if take > capacity {
            take = capacity
        }
        ans += take * it.ratio
        capacity -= take
    }
    return ans
}
```

输入输出形状是两个等长 `[]float64` + 容量 → `float64`。交换论证：若某方案先取了单位价值更低的部分而漏掉更高的部分，把低价值部分换成高价值部分不会变差，因此最优解可被调整为按比值降序取。

### ⭐ 双指针最大容量

两条竖线围成的面积为 `min(height[l], height[r]) * (r-l)`。移动较短的一侧：

```go
func maxArea(height []int) int {
    l, r := 0, len(height)-1
    best := 0
    for l < r {
        h := height[l]
        if height[r] < h {
            h = height[r]
        }
        area := h * (r - l)
        if area > best {
            best = area
        }
        if height[l] < height[r] {
            l++
        } else {
            r--
        }
    }
    return best
}
```

证明直觉：当前面积受较短边限制；若移动较长边，宽度减少而短边上限不变，不可能得到更大面积，所以必须尝试移动短边。

### △ 整数拆分

把正整数拆成至少两个正整数，使乘积最大：

```go
func integerBreak(n int) int {
    if n <= 3 {
        return n - 1
    }
    ans := 1
    for n > 4 {
        ans *= 3
        n -= 3
    }
    return ans * n
}
```

核心性质：在固定和下，两个数越接近乘积越大；拆出大于 4 的部分时继续拆成 `3 + (x-3)` 会增大乘积，因此尽量拆成 3，剩余 2/3/4 直接处理。这个结论针对该题，不能推广为所有乘积优化题。

## 四、核心原理

### 1. 局部选择性质

某一步的选择必须能被证明为“安全”：存在一个全局最优解与当前选择兼容。常见证明方式是交换论证、反证法或维护一个可行解的最优边界。

### 2. 贪心与 DP 的区别

- 贪心只保留一个当前选择，不记录所有历史状态；依赖局部选择性质。
- DP 同时保留多个可能状态，等到未来信息明确后再取最优；适用于局部选择无法证明安全的情况。

0-1 背包是典型反例：按单位价值选可能装入一个大件后浪费容量，错过两个总价值更高的组合；分数背包因为可切分才成立。

### 3. 排序常是贪心的前置

排序把“当前最优”的定义固定下来，例如按结束时间最早、单位价值最高、左端点最小。排序本身不保证贪心正确，证明仍要说明这个顺序为何安全。

## 五、常见场景

- 分数背包、按比例/收益密度分配。
- 区间调度（通常按结束时间最早）。
- 双指针容量、跳跃、覆盖范围等具有边界推进性质的问题。
- 最小生成树、Huffman 等有严格证明的算法（后续图算法可继续学习）。
- 数学结构明确的拆分或局部交换问题。

不适合：任意 0-1 背包、硬币面额不满足特殊性质的找零、局部选择会影响未来多种状态且没有交换证明的问题。

## 六、踩坑点

1. **“当前最大”不等于“最终最优”**：必须找证明或反例。
2. **分数背包与 0-1 背包不同**：能否切分决定按单位价值是否安全。
3. **双指针移动哪一侧要有依据**：不能只凭“左右各走一步”。
4. **浮点比值可能有精度问题**：可用交叉乘法比较 `value1*weight2` 与 `value2*weight1`，或明确误差边界。
5. **排序后要保留同值的次序需求**：相等时可能需要稳定规则或第二关键字。
6. **整数拆分的 3 法则有边界**：`n=2/3` 要单独处理，不能无条件乘 3。
7. **贪心解通常不需要回溯**：如果仍要大量试错，可能其实是 DP/回溯问题。

## 七、项目中的实际使用

工程中把贪心规则写成命名清晰的排序或选择函数，并把证明前提写在注释里：

```text
规则：按结束时间升序选择；安全性：选择最早结束的活动不会减少后续可安排空间。
```

如果规则无法用一句话说明，先不要提交实现；构造最小反例，或改用 DP/搜索。金额、比例和容量计算要明确使用整数还是浮点，避免精度和溢出。

## 八、一句话总结

**贪心的核心不是“每次选最大的”，而是证明当前选择可以安全地出现在某个全局最优解中。**

## 九、核心问答

1. **为什么分数背包可以按单位价值贪心？**
   - 物品可切分，低单位价值部分可以被高单位价值部分替换，不会破坏容量约束。
2. **为什么 0-1 背包不能直接按单位价值贪心？**
   - 物品不可切分，先选高比值物品可能留下无法利用的容量，交换不一定保持可行。
3. **最大容量题为什么移动短边？**
   - 面积上限由短边决定，移动长边只会缩小宽度而不提高高度上限。
4. **如何证明一个贪心策略？**
   - 证明局部选择安全：将任意最优解通过交换改造成包含该选择的最优解，再对剩余问题归纳。
5. **什么时候优先怀疑 DP？**
   - 当前选择会改变未来多个维度，且无法证明某个局部选择始终安全时。

## 十、自测与答案

### 题目

1. 分数背包和 0-1 背包的关键差异是什么？
2. 最大容量双指针为什么不能移动较长的一侧？
3. 构造一个说明“按价值最高先选”不一定最优的 0-1 背包例子，需要哪些条件？
4. 贪心正确性证明中“交换”是什么意思？
5. 整数拆分中为什么大于 4 的部分倾向拆出 3？

<details>
<summary>答案</summary>

1. 分数背包允许切分，0-1 背包每件只能整体选或不选；因此单位价值规则只对前者安全。
2. 长边已经不是瓶颈，移动它只会缩小宽度；短边不变，面积上限不会增加。
3. 容量有限、物品不能切分，并且高价值物品占用的容量组合不如多个中等价值物品；这会让局部最高价值阻塞全局组合。
4. 把一个最优方案中的某个选择替换成贪心选择，并证明替换后仍可行且价值不下降。
5. 固定总和时，拆分为更接近的数乘积更大；对大于 4 的部分，拆出 3 往往能增加乘积，剩余 2/3/4 单独处理。
