# 动态规划

## 一、是什么

动态规划（DP）把一个问题拆成有限个“状态”，用状态之间的转移复用重复子问题的结果，从而求最优值、方案数、可行性或匹配代价。DP 不是“套二维数组”，而是先定义状态含义，再推导转移。

## 二、为什么需要

递归/回溯常会反复计算同一状态，例如不同路径都到达同一个位置；DP 把这个状态的结果保存下来。它把指数级重复计算压成“状态数 × 每个状态的转移数”。

## 三、核心用法

### ⭐ DP 五步法

1. **定义状态**：`dp[...]` 精确表示什么。
2. **写出转移**：当前状态从哪些更小状态来。
3. **确定初值**：最小输入或边界状态是什么。
4. **确定计算顺序**：转移依赖的状态必须先算。
5. **定位答案**：答案是某个状态、最后一行，还是所有状态的最值。

可行性 DP 用布尔值，计数 DP 用整数，最优值 DP 用最大/最小值；状态的数据类型必须与目标一致。

### ⭐ 一维 DP：打家劫舍

```go
func rob(nums []int) int {
    prev2, prev1 := 0, 0
    for _, money := range nums {
        take := prev2 + money
        skip := prev1
        cur := skip
        if take > cur {
            cur = take
        }
        prev2, prev1 = prev1, cur
    }
    return prev1
}
```

状态含义：`prev1` 是处理到前一间房的最大值，`prev2` 是处理到前两间房的最大值；当前只能“偷”或“不偷”。由于 `dp[i]` 只依赖 `i-1/i-2`，可把 `O(n)` 空间压成 `O(1)`。

### ⭐ 0-1 背包：每件物品最多一次

```go
func knapsack01(weights, values []int, capacity int) int {
    dp := make([]int, capacity+1)
    for i, w := range weights {
        for c := capacity; c >= w; c-- { // 必须倒序
            candidate := dp[c-w] + values[i]
            if candidate > dp[c] {
                dp[c] = candidate
            }
        }
    }
    return dp[capacity]
}
```

`dp[c]` 表示容量不超过 `c` 时的最大价值。倒序更新保证本轮物品不会被再次使用；输入形状是两个等长切片 + 容量，输出 `int`，空间 `O(capacity)`。

### ⭐ 完全背包 / 零钱兑换：物品可重复

```go
func coinChange(coins []int, amount int) int {
    inf := amount + 1
    dp := make([]int, amount+1)
    for i := 1; i <= amount; i++ {
        dp[i] = inf
    }
    for sum := 1; sum <= amount; sum++ {
        for _, coin := range coins {
            if coin <= sum && dp[sum-coin]+1 < dp[sum] {
                dp[sum] = dp[sum-coin] + 1
            }
        }
    }
    if dp[amount] == inf {
        return -1
    }
    return dp[amount]
}
```

这里 `dp[sum]` 是凑出 `sum` 所需的最少硬币数；由于当前状态可以依赖同一轮已经更新的 `dp[sum-coin]`，允许重复使用硬币。若题目限制每件只能用一次，状态和遍历方向都要改。

### ⭐ 编辑距离：二维状态

```go
func min3(a, b, c int) int {
    if a < b {
        if a < c { return a }
        return c
    }
    if b < c { return b }
    return c
}

func editDistance(s, t string) int {
    a, b := []rune(s), []rune(t)
    dp := make([][]int, len(a)+1)
    for i := range dp {
        dp[i] = make([]int, len(b)+1)
        dp[i][0] = i
    }
    for j := 0; j <= len(b); j++ {
        dp[0][j] = j
    }
    for i := 1; i <= len(a); i++ {
        for j := 1; j <= len(b); j++ {
            if a[i-1] == b[j-1] {
                dp[i][j] = dp[i-1][j-1]
            } else {
                dp[i][j] = 1 + min3(
                    dp[i-1][j],   // 删除
                    dp[i][j-1],   // 插入
                    dp[i-1][j-1], // 替换
                )
            }
        }
    }
    return dp[len(a)][len(b)]
}
```

`dp[i][j]` 表示前 `i` 个字符和前 `j` 个字符的最少编辑次数；二维形状是 `(len(a)+1) × (len(b)+1)`。使用 `[]rune` 是为了按 Unicode 码点处理；若题目明确是 ASCII，`[]byte` 也可以。

### △ 记忆化搜索与状态压缩

自顶向下递归 + memo 适合状态转移自然但计算顺序不直观的题；自底向上表格适合依赖顺序清晰、需要压缩空间的题。压缩前先确认被覆盖的旧值不会再被后续状态使用。

## 四、核心原理

### 1. DP 的两个条件

- **最优子结构**：最优解可以由子问题的最优解组成。
- **重叠子问题**：不同路径会反复遇到相同状态。

缺少重叠时，普通分治可能更自然；缺少最优子结构时，单纯保存子问题最优值可能丢失必要信息。

### 2. 0-1 与完全背包的循环方向

一维压缩后：

- 0-1 背包容量倒序，阻止同一物品在本轮重复使用；
- 完全背包容量正序，允许使用刚刚更新的同一物品状态。

直观含义：循环方向决定“本轮更新能否被本轮再次读取”。

### 3. 状态压缩的前提

若 `dp[i]` 只依赖有限个最近状态，可以保留滚动变量；若还要恢复具体路径，可能需要保留决策、前驱或完整表。空间压缩不是无条件优化，会改变可回溯的信息。

## 五、常见场景

- 线性选择：打家劫舍、股票、爬楼梯。
- 背包：容量、预算、是否可重复、价值最大化。
- 字符串：编辑距离、最长公共子序列、匹配。
- 网格路径：从左上到右下的最小代价/路径数。
- 计数与可行性：方案数、能否凑出目标、分割字符串。

不适合：状态数本身接近输入所有排列且没有压缩；只需枚举具体方案；存在可证明的更简单贪心结构。

## 六、踩坑点

1. **状态定义模糊**：不知道 `dp[i]` 包含当前元素还是不包含，会导致转移错位。
2. **初始化不当**：最小值 DP 的不可达状态不能默认 0，计数 DP 的加法单位和最优 DP 不同。
3. **0-1/完全背包方向写反**：这是最常见的重复使用或漏用错误。
4. **压缩后覆盖依赖**：先画依赖箭头，再决定正序/倒序。
5. **无穷大加法溢出**：不可达状态参与转移前要判断或使用安全哨兵。
6. **字符串索引按字节**：Unicode 题要明确 `[]rune` 或题目保证 ASCII。
7. **DP 不等于递推公式**：要解释状态覆盖哪些历史信息，以及为什么足够决定未来。
8. **只求最优值与要恢复方案不同**：后者要保存选择或前驱信息。

## 七、项目中的实际使用

真实项目中将 DP 状态写成注释或文档契约：

```text
dp[i]：处理前 i 个元素，在当前约束下的最优值
dp[i] 从哪些状态转移而来：...
不可达状态：...
```

先写二维、容易验证的版本，再根据内存约束压缩；不要一开始就写滚动数组，导致无法判断覆盖错误。对大容量背包，要确认容量单位是否过大、`int` 是否可能溢出。

## 八、一句话总结

**DP 先定义“状态代表什么”，再写转移；循环方向决定资源能否重复使用。**

## 九、核心问答

1. **如何判断一个递归问题适合 DP？**
   - 递归分支会反复到达相同状态，并且目标满足最优子结构或可累加/可判断的状态转移。
2. **0-1 背包为什么倒序，完全背包为什么正序？**
   - 倒序避免本轮再次读到当前物品更新过的状态；正序允许读取它，从而重复使用。
3. **为什么不可达状态不能初始化为 0？**
   - 0 可能被误当成合法最优值，参与转移后制造不存在的方案。
4. **DP 与回溯的关系是什么？**
   - 回溯枚举决策树；DP 把会产生相同未来的路径合并为一个状态，避免重复探索。
5. **什么时候不能做空间压缩？**
   - 需要恢复路径、依赖更远历史、或压缩后无法保持正确的更新顺序时。

## 十、自测与答案

### 题目

1. “每件物品只能选一次”对应哪种背包，容量循环方向是什么？
2. `dp[i]` 若表示前 i 个元素的最优值，为什么常有 `dp[0]`？
3. 编辑距离中 `dp[i-1][j]`、`dp[i][j-1]`、`dp[i-1][j-1]` 分别对应什么操作？
4. 为什么状态压缩前要先写二维版本？
5. 打家劫舍中当前房屋为什么只能在“偷”和“不偷”之间取最大？

<details>
<summary>答案</summary>

1. 0-1 背包；容量倒序。
2. 它表示空前缀，是递推的边界；很多状态都从空输入开始建立。
3. 删除、插入、替换；若字符相同则直接继承左上角。
4. 二维表最直观地展示依赖关系，便于验证状态和边界；压缩只是存储优化。
5. 相邻房屋不能同时偷；偷当前只能加上前两间的最优，不偷则继承前一间最优。
