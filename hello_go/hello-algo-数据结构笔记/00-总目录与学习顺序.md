# 总目录与学习顺序

## 一、是什么

数据结构是“数据的组织方式 + 对这些数据允许进行的操作 + 操作的代价”。学习重点不是背名称，而是把题目需求映射到结构不变量：连续、链接、先进后出、先进先出、按键定位、按优先级取出、父子层级或邻接关系。

## 二、为什么需要

同一批数据，换一种组织方式，核心操作的代价可能从 `O(n)` 变成 `O(1)` 或 `O(log n)`。刷题的本质之一，就是用题目要求的操作反推结构：

| 题目最常问的操作 | 首选结构 | 典型代价 |
|---|---|---:|
| 按下标访问、双指针、区间扫描 | 数组/切片 | 访问 `O(1)` |
| 已知节点位置后插入/删除 | 链表 | 改指针 `O(1)` |
| 只处理最近加入的元素 | 栈 | 栈顶操作 `O(1)` |
| 按到达顺序逐层处理 | 队列 | 队首/队尾 `O(1)` |
| 判断出现过、统计次数、按键找值 | 哈希表 | 平均 `O(1)` |
| 层级、子树、递归定义 | 树 | 遍历 `O(n)` |
| 动态取得最小/最大优先级 | 堆 | 取顶 `O(1)`，更新 `O(log n)` |
| 节点之间有任意连接关系 | 图 | 遍历 `O(V+E)` |

## 三、核心用法

### 推荐学习顺序

1. **基础分类与 Go 语义**：先解决数组和切片不是一回事、指针和 `nil`、`map` 的读写规则。
2. **数组/切片与链表**：所有线性结构的地基；掌握双指针、哨兵节点。
3. **栈/队列/双端队列**：从线性容器过渡到“处理顺序”与 BFS。
4. **哈希表**：贯穿后续题目的计数、去重、索引和访问标记。
5. **树与遍历**：把递归、栈、队列统一起来；先会普通二叉树，再理解 BST。
6. **堆/优先队列**：树的顺序约束与数组存储的结合；掌握 Top-K。
7. **图与遍历**：邻接表 + DFS/BFS；网格题看成隐式图。
8. **跨章节综合**：不看提示判断结构，并能解释为什么其他结构不合适。

### 每篇的最小闭环

```text
定义 → 不变量 → 3 个核心操作 → 复杂度 → Go 模板 → 题型信号 → 坑点 → 合上文档自测
```

### 复习节奏

- 当天：写出模板，不看答案完成 3 道自测。
- 次日：只回答“什么时候用、为什么快、最容易错什么”。
- 一周后：做 [08-跨章节综合问答.md](08-跨章节综合问答.md)，按题目约束选择结构。
- 做题后：把新发现归入“结构不变量”或“输入输出形状”，不要只记录题号。

## 四、核心原理

数据结构的选择可以归结为三件事：

1. **访问模式**：随机访问、顺序访问、按优先级、按邻接关系。
2. **更新模式**：尾部追加、任意位置插入/删除、只改引用、频繁改变优先级。
3. **约束不变量**：数组连续、栈只看顶、队列保持先来先出、堆顶最优、BST 左小右大、图的边表示可达关系。

复杂度不是标签，而是这些不变量带来的结果。例如切片随机访问 `O(1)`，因为地址可由 `base + index × elementSize` 计算；链表按值查找仍是 `O(n)`，因为必须顺着指针走。

## 五、常见场景

- **连续区间、排序、双指针、前缀和**：优先切片。
- **需要回退、匹配括号、单调约束**：栈或单调栈。
- **最短步数、按层扩散、最少操作次数**：队列 + BFS。
- **频次、配对、去重、记忆化**：`map`。
- **子树、路径、层序、祖先后代**：二叉树 + DFS/BFS。
- **第 K 大/小、动态最值、合并多个有序流**：堆。
- **依赖、连通、路径、网格扩散**：图。

不适合的反例同样重要：不要为了“插入快”在普通数组题里强行使用链表；不要用堆解决只需要一次排序后的静态查询；不要把有环图当树递归而不记录访问状态。

## 六、踩坑点

- `O(1)` 只说明某个操作，不代表整个算法 `O(1)`。
- `cap` 是容量，不是有效元素个数；遍历使用 `len`。
- Go 的 `map` 读不存在的键得到零值，写入 `nil map` 会 panic。
- 树高/深度有的题按边数、有的题按节点数，先看题目定义。
- 图遍历必须处理访问状态；队列入队时标记通常比出队时标记更稳。
- 堆只保证堆顶最优，不保证整个底层切片有序。

## 七、项目中的实际使用

项目设计时先写“操作清单”，再选结构，而不是先选一个熟悉的容器。例如：

```text
需求：按用户 ID 查找、更新、删除，并保留最近访问顺序
拆解：按 ID 快速查找 → map；维护顺序 → 双向链表；两者互相保存指针/节点
```

LeetCode 则把这个流程压缩成读题时的信号识别：关键词决定操作，约束决定复杂度上限，结构不变量决定模板。

## 八、一句话总结

**先看“最频繁、最昂贵的操作”，再选择能把它变快的不变量。**

## 九、核心问答

1. **为什么数组和链表的优势相反？**
   - 数组靠连续内存换来 `O(1)` 随机访问；链表靠节点引用换来已知位置后的 `O(1)` 插入/删除。
2. **为什么哈希表平均 `O(1)` 但不是严格 `O(1)`？**
   - 哈希函数把键分散到桶中，平均冲突少；极端冲突或扩容会改变代价。
3. **队列和堆都能取元素，它们区别是什么？**
   - 队列按到达时间取出；堆按优先级取出，顺序来源不同。
4. **什么时候树必须升级为图？**
   - 当节点可能有多个父节点、存在环、或连接关系不是唯一父子关系时。
5. **为什么刷题常用切片而不是 Go 的定长数组？**
   - 题目输入长度运行时才知道，且切片支持追加、截取和传参；定长数组长度属于类型的一部分。

## 十、自测与答案

### 题目

1. 一个操作需要“快速判断某元素是否出现过”，最小结构是什么？
2. 一个问题要求持续取出当前最小值，但新元素会不断加入，为什么不是每次重新排序？
3. 为什么 BFS 的队列可以用切片 + 头指针实现？
4. 如果图没有环，是否一定可以用普通二叉树表示？

<details>
<summary>答案</summary>

1. `map[T]struct{}` 集合；若还要计数则用 `map[T]int`。
2. 堆把插入和取最小值控制在 `O(log n)` / `O(log n)`，避免每轮 `O(n log n)` 重排。
3. 只递增逻辑头部即可避免搬移剩余元素；出队均摊 `O(1)`。
4. 不一定。树要求连通且每个非根节点只有一个父节点；一般无环图仍可能有多个父节点或不连通。
