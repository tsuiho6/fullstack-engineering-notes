# Hello 算法：数据结构高效笔记（Go + LeetCode）

这是一套面向刷题与长期复习的二次整理。目标不是逐页复述 Hello 算法，而是把数据结构压缩成：

1. 能解释：知道它维护了什么不变量，以及为什么快。
2. 能写出：能在 Go 中从空白写出最小模板。
3. 能判断：看到题目约束，能选对结构。
4. 能避坑：知道 `nil`、下标、指针、别名、遍历时机和复杂度的高频错误。

## 记号

- ⭐ 必须掌握：高频使用、后续依赖、面试常问。
- △ 理解即可：知道机制和适用边界，暂时不追求手写全部细节。
- ○ 知道存在：低频或实现细节，需要时回查。

代码约定：默认 Go 1.18+；LeetCode 代码优先使用题目给出的 `ListNode` / `TreeNode`，工程代码再考虑封装类型。Go 没有 Python/NumPy 意义上的 `dtype` 和 `device`，但仍必须明确元素类型、`len/cap`、是否可能为 `nil`、输入输出形状和是否共享底层数组。

## 快速使用法

第一次学习：按 `00 → 01 → 02 → 03 → 04 → 05 → 06 → 07` 阅读，每篇只运行核心模板并完成自测。

刷题前：只看对应文件的“一句话总结”“核心用法”“踩坑点”，然后合上文档写模板。

复习时：先回答每篇的核心问答，再做折叠区中的主动回忆题；答不出时只回看相关小节，不从头重读。

## 依赖主干

```text
Go 基础语义 / 复杂度
        ↓
数组与切片 ───────→ 栈、队列、双端队列
        ↓                    ↓
   链表与指针          BFS / 单调结构
        ↓                    ↓
     二叉树 ───────→ 堆 / 优先队列
        ↓                    ↓
     图的表示 ─────→ 图遍历与网格题
        └──────────→ 哈希表贯穿所有结构的查找与去重
```

哈希表不是树或图的“后续章节”，而是横向工具：两数之和、访问标记、记忆化、索引映射、频次统计都会用到。
