# 栈、队列与双端队列

## 一、是什么

- **栈（stack）**：后进先出（LIFO），只在同一端压入和弹出。
- **队列（queue）**：先进先出（FIFO），一端入队，另一端出队。
- **双端队列（deque）**：两端都可以插入和删除。

它们不是“特殊数组”，而是对访问端点施加限制后得到的操作顺序不变量。

## 二、为什么需要

很多题的难点不是存数据，而是**只允许按某种顺序处理数据**：最近的未匹配符号、最先到达的状态、当前窗口的最大值。直接扫描历史数据会重复工作，栈/队列/双端队列能把“仍有用的候选”维护起来。

## 三、核心用法

### ⭐ 用切片实现栈

```go
st := make([]int, 0)

st = append(st, x)       // push，输入 int，栈顶在 len(st)-1
top := st[len(st)-1]     // peek；调用前保证 len(st) > 0
st = st[:len(st)-1]      // pop
```

入栈、查看栈顶、出栈均为均摊 `O(1)`。LeetCode 中不需要为了栈自定义结构体。

### ⭐ 用切片 + 头指针实现队列

```go
q := make([]int, 0, len(nums))
head := 0
q = append(q, start) // enqueue

for head < len(q) {
    cur := q[head]   // dequeue
    head++
    _ = cur
}
```

**输入输出形状**：队列存储 `int`、节点指针或状态结构体；`head` 是逻辑队首，不删除底层切片前缀，因此出队均摊 `O(1)`。

树/图 BFS 里若队列存指针，出队后可清空槽位帮助 GC：

```go
node := q[head]
q[head] = nil
head++
```

### ⭐ 单调栈

维护一个从栈底到栈顶单调的索引栈。以“下一个更大元素”为例：

```go
func nextGreater(nums []int) []int {
    ans := make([]int, len(nums))
    for i := range ans {
        ans[i] = -1
    }
    st := make([]int, 0) // 存下标，nums[st] 从栈底到栈顶递减
    for i, x := range nums {
        for len(st) > 0 && nums[st[len(st)-1]] < x {
            j := st[len(st)-1]
            st = st[:len(st)-1]
            ans[j] = x
        }
        st = append(st, i)
    }
    return ans
}
```

**为什么存下标而不是值**：通常既要比较值，又要把答案写回原位置；下标同时保留两种信息。

### ⭐ 单调队列

滑动窗口最大值的队列存下标，并维护对应值从队首到队尾递减：

```go
func maxSlidingWindow(nums []int, k int) []int {
    ans := make([]int, 0, len(nums)-k+1)
    dq := make([]int, 0) // 下标；nums[dq] 递减

    for i, x := range nums {
        // 队首过期：不在窗口 [i-k+1, i] 中
        if len(dq) > 0 && dq[0] <= i-k {
            dq = dq[1:]
        }
        // 比 x 小的候选不可能成为未来窗口最大值
        for len(dq) > 0 && nums[dq[len(dq)-1]] <= x {
            dq = dq[:len(dq)-1]
        }
        dq = append(dq, i)
        if i >= k-1 {
            ans = append(ans, nums[dq[0]])
        }
    }
    return ans
}
```

若窗口特别大且运行时间长，反复 `dq = dq[1:]` 可能让底层数组保留旧引用；刷题通常无碍，工程中可用环形缓冲区或周期性压缩。

### △ 双端队列的工程实现

Go 的 `container/list` 提供双端操作：`PushFront`、`PushBack`、`Remove`。刷题中更常见的是“只存下标的单调队列”，因为两端操作可以用切片完成。

如果需要高吞吐且稳定的双端操作，使用环形数组：

```text
物理位置 = (head + logicalOffset) mod capacity
```

当队头/队尾到达边界时绕回数组开头；扩容时一次性按逻辑顺序复制。实现细节属于 △，除非项目确实需要自定义 deque。

## 四、核心原理

### 1. 栈/队列的复杂度来自端点限制

栈永远在同一端操作，因此不需要搬移中间元素；队列若用头指针表示逻辑队首，也只需增加 `head`。直观含义：把“删除前面元素”改成“向后移动边界”，避免每次整体搬移。

### 2. 单调结构为什么能做到线性

每个元素最多入栈/入队一次，最多被弹出一次。即使某一轮有很多弹出，所有轮次的弹出总数不超过 `n`，所以总时间是 `O(n)`，不是 `O(n^2)`。

### 3. 单调队列必须同时维护值和有效范围

- 值不单调：尾部无用候选应淘汰。
- 下标过期：队首超出当前窗口应淘汰。

只维护单调值而不存下标，无法判断候选是否还在窗口中。

## 五、常见场景

| 信号 | 结构 | 典型题型 |
|---|---|---|
| 匹配最近未闭合项、撤销、回退 | 栈 | 括号匹配、路径化简、表达式 |
| 按层扩散、最少步数、任务先来先处理 | 队列 | BFS、拓扑层序、生产者消费者 |
| 下一个更大/更小、温度、柱状图 | 单调栈 | 右侧第一个更大值、最大矩形 |
| 固定窗口最值、维护候选序列 | 单调队列 | 滑动窗口最大/最小 |
| 两端都要操作 | 双端队列 | 0-1 BFS 的基础容器、单调队列 |

不适合用栈/队列的情况：需要按任意下标读取、需要按键定位、需要同时保持全局有序；应考虑切片、哈希表或堆。

## 六、踩坑点

1. **空栈/空队列先判断**：`st[len(st)-1]` 和 `q[head]` 在边界时会 panic。
2. **队列不要 `q = q[1:]` 后忘记判空**：虽然切片切头是 `O(1)`，但边界和引用保留更容易失控。
3. **BFS 队列要区分逻辑长度和底层长度**：用 `head < len(q)`，不是 `len(q) > 0`。
4. **单调栈的严格/非严格比较影响重复值**：`<` 与 `<=` 决定相等元素保留哪一个，按题目“下一个严格更大”或“更大或等于”选择。
5. **单调队列存下标**：只存值无法移除过期元素。
6. **栈顶方向要统一**：切片尾部作为栈顶最自然；不要一会儿从头部、一会儿从尾部操作。
7. **循环数组的空/满状态**：若用 `head == tail` 表示空，就需要额外计数或预留一个槽位区分满。

## 七、项目中的实际使用

- 普通栈/队列优先用切片，减少抽象层和分配。
- 生产者消费者或需要阻塞/并发安全时，使用 channel 或成熟队列实现；LeetCode 不涉及并发语义。
- 需要 O(1) 的两端操作且元素类型固定时，用环形缓冲区；不要把 `container/list` 当作所有场景的默认容器。
- 单调结构尽量保存“索引 + 原数组”，这样既能判断有效范围，又能还原答案位置。

## 八、一句话总结

**栈管最近，队列管最早，单调结构只保留仍可能成为答案的候选。**

## 九、核心问答

1. **为什么 Go 切片尾部适合实现栈？**
   - `append` 和缩短尾部切片通常均摊 `O(1)`，不需要搬移其他元素。
2. **为什么 BFS 不能用栈替代队列？**
   - 栈会优先深入，得到 DFS 顺序；无权图最短步数依赖按距离逐层处理。
3. **单调栈为什么不等于排序？**
   - 它只维护与当前位置相关的候选顺序，不保证所有元素全局有序。
4. **滑动窗口最大值为什么要在队尾弹出更小元素？**
   - 新元素更晚过期且更大，小元素永远不可能在未来成为最大值。
5. **什么时候使用 `container/list` 而不是切片？**
   - 需要保存节点句柄并在已知节点处频繁移动/删除；单纯做栈、队列或刷题通常切片更简单。

## 十、自测与答案

### 题目

1. 用切片写出一个栈的 push、peek、pop，并说明每一步的边界条件。
2. 队列用 `head` 指针后，为什么不需要真的删除 `q[0]`？
3. 单调栈中每个元素为什么最多被弹出一次？
4. 滑动窗口单调队列为什么必须保存下标？
5. 对重复值 `[2, 2]`，单调栈中使用 `<` 和 `<=` 的结果有什么区别？

<details>
<summary>答案</summary>

1. `push: append`；`peek: st[len(st)-1]`；`pop: 取尾元素后 st=st[:len(st)-1]`；peek/pop 前保证非空。
2. `head` 把前缀标记为逻辑无效，访问从 `q[head]` 开始；这样避免搬移剩余元素。
3. 元素一旦因不满足单调性被弹出，就不会再次入栈；每个元素入栈一次、出栈一次。
4. 需要判断队首是否已经离开窗口；值本身没有位置，无法判断过期。
5. `<` 会保留相等值，`<=` 会弹出旧的相等值、保留更新的下标；两者都可能正确，但对应的重复值语义不同。

</details>
