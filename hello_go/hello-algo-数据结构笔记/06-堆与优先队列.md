# 堆与优先队列

## 一、是什么

堆是满足局部序关系的完全二叉树：以小根堆为例，每个父节点不大于子节点，因此根是全局最小值。优先队列用堆实现“每次取当前最高优先级元素”。

堆不是完整有序数组：只保证父子关系和堆顶，不保证任意两个非祖先节点的大小关系。

## 二、为什么需要

如果数据动态到来，却要持续取最小/最大值：每次排序会反复付出排序成本，无序切片每次取最优要扫描 `O(n)`，而堆取顶 `O(1)`、插入和删除顶 `O(log n)`。

它是 Top-K、任务调度、合并有序流、Dijkstra 等场景的最小工具。

## 三、核心用法

### ⭐ 数组下标关系

0 下标数组表示完全二叉树：

```text
left(i)  = 2*i + 1
right(i) = 2*i + 2
parent(i) = (i-1)/2  // i > 0
```

上浮：新元素与父节点比较，违反不变量就交换；下沉：节点与更优的子节点比较并交换。每次只经过树高 `O(log n)` 层。

### ⭐ Go `container/heap`：小根堆

```go
package main

import "container/heap"

type IntHeap []int

func (h IntHeap) Len() int           { return len(h) }
func (h IntHeap) Less(i, j int) bool { return h[i] < h[j] } // 小根堆
func (h IntHeap) Swap(i, j int)      { h[i], h[j] = h[j], h[i] }

func (h *IntHeap) Push(x any) {
    *h = append(*h, x.(int))
}

func (h *IntHeap) Pop() any {
    old := *h
    n := len(old)
    x := old[n-1]
    *h = old[:n-1]
    return x
}

func useHeap() int {
    h := &IntHeap{5, 1, 3}
    heap.Init(h)
    heap.Push(h, 2)
    min := (*h)[0]
    _ = heap.Pop(h).(int)
    return min
}
```

`Push` 和 `Pop` 方法使用指针接收者，因为它们会改变切片长度；外部添加/删除必须调用 `heap.Push` / `heap.Pop`，不要直接调用实现接口的 `h.Pop()`。

### ⭐ 大根堆

只需反转比较：

```go
func (h IntHeap) Less(i, j int) bool { return h[i] > h[j] }
```

LeetCode 中常用“固定大小的小根堆维护第 K 大”：堆顶是当前 K 个候选中的最小者；一旦新数更大，就弹出堆顶并加入新数。

### ⭐ Top-K 模板

```go
func kthLargest(nums []int, k int) int {
    h := &IntHeap{}
    heap.Init(h)
    for _, x := range nums {
        heap.Push(h, x)
        if h.Len() > k {
            heap.Pop(h)
        }
    }
    return (*h)[0]
}
```

输入输出形状是 `[]int, k → int`；时间 `O(n log k)`，空间 `O(k)`。若求第 K 小，则使用大根堆并保留最小的 `k` 个。

### △ 建堆

- 逐个 `heap.Push` 建堆：`O(n log n)`；
- 先把元素放入切片，再 `heap.Init`：`O(n)`。

`heap.Init` 从最后一个非叶节点开始下沉，叶节点本身已经满足堆不变量。一次性加载大量数据时，批量建堆更合适。

### ○ 优先级结构体

实际队列可以把 `Item{Value, Priority}` 或 `*Item` 放进自定义堆，`Less` 只负责比较优先级；若需要修改任意元素的优先级，维护它在堆中的索引并调用 `heap.Fix`。这些是标准库接口的扩展写法，先掌握整数堆和方向判断即可。

## 四、核心原理

### 1. 堆不变量

小根堆满足：对每个节点 `i`，`h[i] <= h[left(i)]` 和 `h[i] <= h[right(i)]`（若子节点存在）。直观含义：每条从根向下的路径都不下降，所以根一定是最小值；不同分支之间没有全序关系。

### 2. 为什么操作是 `O(log n)`

完全二叉树高度约为 `log₂ n`。插入只可能沿一条路径上浮，删除堆顶只可能沿一条路径下沉，因此时间与高度成正比。

### 3. 为什么固定大小堆能做 Top-K

以第 K 大为例，维护“目前最大的 K 个数”，让小根堆顶表示这 K 个数的门槛：新数不超过门槛则丢弃；新数超过门槛则替换门槛。堆保存的是候选边界，不是全部顺序。

## 五、常见场景

- 第 K 大/小、前 K 个高频元素。
- 动态任务按优先级处理。
- 合并 K 个有序链表/流。
- 需要反复取当前最小边、最短距离的图算法。
- 实时流数据只保留有限个候选。

不适合的场景：需要完整排序输出；需要按任意值查找或删除；只取一次最小值且数据静态。

## 六、踩坑点

1. 堆顶不等于底层切片全局有序：只能保证 `(*h)[0]` 是最优值。
2. `heap.Pop` 与接口 `Pop` 不同：前者维护堆并返回堆顶，后者是接口实现中的末元素弹出方法。
3. 比较方向决定大小根堆：`Less <` 是小根堆，`Less >` 是大根堆。
4. `heap.Push` 要传指针，因为堆长度会变化。
5. Top-K 堆大小要控制为 `k`，否则空间从 `O(k)` 变成 `O(n)`。
6. 相等值的稳定顺序不自动保证；需要稳定时加入序号作为第二关键字。
7. 结构体优先级更新后要 `heap.Fix`，直接改字段会破坏堆不变量。
8. 不要混淆第 K 大与第 K 小的堆方向。

## 七、项目中的实际使用

工程优先使用标准库 `container/heap`，把比较逻辑集中在 `Less`，把业务数据放进 `Item`。若需要删除或修改任意元素，维护索引并使用 `heap.Remove` / `heap.Fix`；若只需要固定 K 个候选，不要引入完整排序。

## 八、一句话总结

**堆只守住堆顶：用小根堆守第 K 大的门槛，用大根堆守第 K 小的门槛。**

## 九、核心问答

1. **堆和排序后的数组有什么区别？**
   - 堆只保证父子局部关系和堆顶最优；排序数组保证全局顺序。
2. **为什么第 K 大使用小根堆？**
   - 保留最大的 K 个候选，并让其中最小者在堆顶作为淘汰门槛。
3. **为什么 `heap.Init` 是 `O(n)` 而逐个插入是 `O(n log n)`？**
   - 批量建堆从底部下沉，绝大多数节点高度很小；逐个插入每次都可能上浮整条路径。
4. **修改堆中元素后为什么要调用 `heap.Fix`？**
   - 修改可能破坏沿该节点向上的或向下的局部不变量，`Fix` 重新调整它。
5. **什么时候不用堆而用切片排序？**
   - 数据静态且需要完整有序结果，排序一次更直接；堆适合动态取最优或只保留部分候选。

## 十、自测与答案

### 题目

1. 0 下标堆中下标 5 的父节点和子节点下标是什么？
2. 第 K 小为什么使用大根堆而不是小根堆？
3. 只要堆顶是最小值，为什么不能二分查找任意目标？
4. `heap.Push(h, x)` 为什么通常传 `h` 的指针？
5. `heap.Init` 前把元素放在任意顺序是否可以？

<details>
<summary>答案</summary>

1. 父节点 `(5-1)/2=2`；左子节点 `11`；右子节点 `12`。
2. 保留最小的 K 个数，并让其中最大者在堆顶，超过容量时淘汰它。
3. 堆的兄弟分支没有全序关系，只有父子局部关系，无法像有序数组那样排除一半区间。
4. 入堆会改变切片长度，指针接收者才能把新长度写回调用方。
5. 可以；`heap.Init` 会把任意切片调整为满足堆不变量的堆，复杂度 `O(n)`。
