# 跨章节综合问答与最终自测

## 一、先看需求，再选结构

### 选择流程

```text
需要按下标/顺序扫描？ ── 是 → 切片
          │ 否
需要按键精确查找/计数？ ── 是 → map
          │ 否
只处理最近加入？ ─────── 是 → 栈
          │ 否
按到达顺序或层数处理？ ── 是 → 队列 / BFS
          │ 否
持续取当前最优？ ─────── 是 → 堆
          │ 否
存在父子层级？ ───────── 是 → 树
          │ 否
存在任意连接/环/多路径？ ─ 是 → 图
```

这不是机械决策树：若同一题同时满足多个条件，就按最昂贵、最频繁的操作做组合。例如 LRU 是 `map + 双向链表`，滑动窗口最值是“切片 + 单调队列”，树的层序遍历是“树 + 队列”。

## 二、核心对比

| 结构 | 核心不变量 | 强项 | 主要弱点 | Go 刷题形状 |
|---|---|---|---|---|
| 数组/切片 | 元素连续 | 下标访问、扫描 | 中间插入搬移 | `[]T` |
| 链表 | 节点由引用连接 | 已知位置改链接 | 找位置慢、局部性差 | `*ListNode` |
| 栈 | LIFO | 最近未处理项 | 不能访问中间项 | `[]T` 尾部 |
| 队列 | FIFO | 分层、最短无权路 | 不按优先级取 | `[]T + head` |
| 双端队列 | 两端可操作 | 单调窗口、两端调度 | 实现边界较多 | 切片/环形数组 |
| 哈希表 | 键映射到桶 | 精确查找、计数 | 无序、占空间 | `map[K]V` |
| 二叉树 | 父子层级 | 递归、子树问题 | 可能退化 | `*TreeNode` |
| BST | 左小右大 | 有序查找 | 不平衡会退化 | `*TreeNode` |
| 堆 | 父节点优先 | 动态最值、Top-K | 非全局有序 | `container/heap` |
| 图 | 任意邻接关系 | 可达、路径、依赖 | 状态与环更复杂 | `[][]int` |

## 三、跨章节核心问答

1. **切片、链表都能保存序列，为什么 LeetCode 大多数序列题先用切片？**
   - 题目通常需要顺序扫描、双指针、排序或按下标访问；切片访问快、缓存友好、代码少。只有操作模式明确需要改链接时才选链表。

2. **队列和堆都能“取一个元素”，为什么不能互换？**
   - 队列按到达顺序取出，堆按优先级取出；前者保证 FIFO，后者只保证当前最优。

3. **栈、递归 DFS、单调栈有什么关系？**
   - 递归 DFS 的调用栈保存待返回的路径；迭代 DFS 显式模拟它；单调栈在此基础上额外维护值的单调性，只保留有用候选。

4. **为什么哈希表能加速图遍历，却不能代替图？**
   - map 可记录访问状态或 ID 映射，但不能表达节点之间的邻接关系；图仍需要邻接表/矩阵保存边。

5. **树的层序遍历和图的 BFS 代码为什么相似？**
   - 两者都是队列按层扩展；树没有环时通常不需要 `visited`，一般图必须记录访问状态。

6. **BST 和堆都利用了树的顺序，为什么用途不同？**
   - BST 的全局方向不变量支持按键搜索和中序排序；堆只保证父子局部优先，换来堆顶最优和高效更新。

7. **为什么“有序”不等于“适合二分查找”？**
   - 二分还需要支持按中间下标 `O(1)` 访问；链表即使逻辑有序，找中点也要走指针，不能直接获得二分的整体优势。

8. **什么时候用 `map[Point]struct{}`，什么时候用二维 `[][]bool`？**
   - 坐标范围规则且网格紧凑时用二维切片更省常数；坐标稀疏、范围巨大或只访问少量点时用 map。

9. **Top-K 为什么不用完整排序？**
   - 只需要 K 个候选时，小根/大根堆将空间控制到 `O(k)`，时间为 `O(n log k)`；完整排序是 `O(n log n)`。

10. **图遍历中最常见的“复杂度正确但答案错误”原因是什么？**
    - 方向加错、访问标记时机错、距离初值混淆、漏掉不连通分量、把带权图当无权图。

## 四、混合场景判断

### 场景 A：保存最近访问的 K 个页面

需求包含“按页面 ID 查找”和“按最近访问顺序移动/淘汰”。最小组合是 `map[ID]*DNode + 双向链表`：map 定位节点，链表维护顺序。单独 map 无法 `O(1)` 找到最旧页面；单独链表无法按 ID 快速定位。

### 场景 B：数据流中的第 K 大

使用大小为 K 的小根堆。堆顶是当前候选中最小的一个，也就是下一名进入 Top-K 所需超过的门槛。总时间 `O(n log k)`，空间 `O(k)`。

### 场景 C：迷宫最少走几步

把可通行格子视为节点、上下左右移动视为无权边，用 BFS；队列保存待处理格子，`dist` 保存最少步数，首次到达即为最短。若移动代价不同，切换到带权最短路方法。

### 场景 D：括号是否匹配

用栈保存尚未匹配的左括号。遇到右括号时检查栈顶是否对应；最后栈必须为空。这里关键是 LIFO，不是“存过就算”，所以 map 不够。

### 场景 E：统计单词出现次数并按次数排序

先用 `map[string]int` 计数，再把键值对放进切片或堆，根据要求选择完整排序、Top-K 堆或频次桶。map 负责聚合，不负责最终顺序。

## 五、最终自测

### 题目

1. 一个操作序列包含：随机访问、尾部追加、偶尔中间删除。默认选什么结构？删除时要承认什么代价？
2. 题目要求“返回第 K 大”，但所有数据一次性给出且没有额外空间限制。堆和排序如何取舍？
3. 为什么 `map` 的查找平均 `O(1)` 不能推出“用 map 的整个算法就是 `O(1)`”？
4. 给定普通二叉树，要求每层从左到右输出，选择 DFS 还是 BFS？为什么？
5. 无向图边表中只添加 `u -> v`，会导致什么错误？
6. 单调队列为什么存索引而不是只存窗口内的值？
7. 给定单链表头指针，删除头节点时为什么哨兵有帮助？
8. 判断一个节点是否访问过，为什么在 BFS 入队时标记通常比出队时标记好？
9. `make([]int, 0, 10)` 的 `len` 和 `cap` 分别是多少？能否直接写 `s[0]=1`？
10. 什么时候普通 BFS 不能用来求最短路？

<details>
<summary>答案</summary>

1. 选切片；随机访问和尾部追加匹配它的优势；中间删除通常需要搬移后缀，为 `O(n)`。
2. 静态数据且要完整结果时排序更直接；只要第 K 个或希望空间 `O(k)` 时使用大小 K 的堆。
3. 单次查找平均 `O(1)` 不代表建表、遍历、扩容或多次调用总成本为常数；还要按输入规模累加。
4. BFS；队列按层处理，天然得到“每层从左到右”的结构。DFS 也能模拟，但需要额外记录深度并维护结果层。
5. 从 `v` 出发找不到 `u`，可达性、度数、连通分量和最短路都会错误。
6. 索引可以判断元素是否离开当前窗口；值本身没有位置，无法判断过期。
7. 把真实头挂在 `dummy.Next` 后，删除头节点和删除普通节点都变成删除某个前驱的后继。
8. 入队时标记能保证节点只入队一次，避免多个前驱重复加入队列。
9. `len=0, cap=10`；不能直接写 `s[0]`，必须先 `append(s, 1)` 或先创建长度大于 0 的切片。
10. 边权不全相同、移动代价不同，或状态转移不是单位代价时；普通 BFS 只保证无权图按边数最短。

</details>

## 六、复习检查表

合上所有笔记后，若能不查资料完成下面动作，说明数据结构主干已经闭环：

- 解释切片的 `len/cap`、共享底层数组和安全删除。
- 写出链表反转、哨兵删除、快慢指针。
- 写出栈、队列 + 头指针、单调栈/单调队列。
- 用 map 完成集合、计数、两数之和，并说出 nil map 与 `ok`。
- 写出二叉树三种 DFS、层序 BFS、BST 中序性质。
- 写出 `container/heap` 的 `Less/Swap/Push/Pop`，判断大小根堆方向。
- 用邻接表写 DFS/BFS，解释 visited、方向、连通分量和无权最短路。
- 面对混合需求，能说清楚为什么要组合两种结构，以及每种结构负责什么。

## 七、一句话总结

**刷题不是背容器，而是从操作、约束和不变量反推出最小结构组合。**
