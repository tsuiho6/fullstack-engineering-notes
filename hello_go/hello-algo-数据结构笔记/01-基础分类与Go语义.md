# 基础分类与 Go 语义

## 一、是什么

数据结构按组织关系可先分成两类：**线性结构**（数组、链表、栈、队列）和**非线性结构**（树、图）；按存储方式又可分为连续存储和链接存储。Go 中最常用的对应物是数组、切片、结构体指针、`map` 以及“切片 + 不变量”实现的容器。

## 二、为什么需要

LeetCode 的很多错误并不是算法不会，而是容器语义错了：把 `len` 当 `cap`、把数组当切片、忘记 `nil` 指针、向 `nil map` 写入，或以为切片传参一定会复制数据。先把输入输出的形状和别名关系弄清，后续模板才可靠。

## 三、核心用法

### ⭐ 定长数组 vs 切片

```go
var a [3]int          // 类型是 [3]int，长度固定，零值 [0 0 0]
b := [3]int{1, 2, 3}  // 定长数组
s := []int{1, 2, 3}   // 类型是 []int，运行时长度
t := make([]int, 0, 8) // len=0, cap=8，适合追加

s = append(s, 4) // 可能复用底层数组，也可能重新分配
```

**形状**：`[]int` 可以理解为 `{指针, len, cap}` 的切片描述符；切片本身不是数据的完整副本。

### ⭐ `len`、`cap`、截取和别名

```go
s := []int{10, 20, 30, 40}
u := s[1:3] // 值为 [20 30]，len=2；通常与 s 共享底层数组
u[0] = 99  // s 也可能变为 [10 99 30 40]

u = append(u, 50) // 是否影响 s，取决于 u 是否还有容量
```

如果需要隔离底层数组，显式复制：

```go
v := append([]int(nil), s...)
// 或 v := make([]int, len(s)); copy(v, s)
```

### ⭐ `map`：集合、计数、映射

```go
seen := make(map[int]struct{}, len(nums))
freq := make(map[int]int)
pos := make(map[int]int)

seen[x] = struct{}{}          // 集合
freq[x]++                     // 计数；不存在的键先取零值
if i, ok := pos[target]; ok { // 查找时区分“值为零”和“不存在”
    _ = i
}
```

键必须是可比较类型：整数、字符串、指针、数组、字段全可比较的结构体可以作为键；切片、`map`、函数不能直接作为键。

### ⭐ 指针、`nil` 与结构体节点

```go
type ListNode struct {
    Val  int
    Next *ListNode
}

var head *ListNode // nil，表示没有节点
if head == nil {
    // 空链表/空树的合法状态
}
```

树和链表题中的 `*Node` 是“可能为空的引用”。访问 `head.Val` 前必须确保 `head != nil`。

## 四、核心原理

### 1. 连续存储带来随机访问

数组元素连续时，第 `i` 个元素地址可抽象为：

```text
address(i) = base + i × elementSize
```

直观含义：知道首地址和偏移量，就能直接定位，因此按下标访问是 `O(1)`；中间插入要搬移后续元素，因此通常是 `O(n)`。

### 2. 切片扩容为什么会影响别名

`append` 在 `len < cap` 时可能直接写入原底层数组；容量不足时会分配新数组并复制旧元素。直观含义：同一个切片变量可能“换了仓库”，而其他切片仍指向旧仓库，所以不能凭感觉判断是否共享。

### 3. 哈希表为什么快

哈希函数把键映射到桶：

```text
bucket = hash(key) mod bucketCount
```

直观含义：希望把大量键均匀分散，使一次查找只检查少量候选；冲突、扩容和恶劣分布会使最坏情况变差。

### 4. 线性与非线性的区别

- 线性结构：元素有一个主要前驱/后继方向，适合顺序处理。
- 树：层级关系、从根向下分叉，通常没有环。
- 图：任意节点之间可有边，可有环、多个连通分量、多条路径。

这是关系模型的区别，不是“代码写法”的区别。

## 五、常见场景

| 需要 | Go 选择 | 备注 |
|---|---|---|
| 运行时长度的数字序列 | `[]int` | LeetCode 默认首选 |
| 固定少量字段的记录 | `struct` | 节点、边、状态 |
| 是否出现过 | `map[T]struct{}` | 空结构体不携带有效数据 |
| 计数 | `map[T]int` | 读不存在键得到 0 |
| 键到值 | `map[K]V` | 写前要 `make` |
| 可为空的节点 | `*TreeNode` / `*ListNode` | 通过 `nil` 表示空 |
| 需要双向移动的容器 | `container/list` 或自定义双链表 | 刷题常常自己写节点更直观 |

### △ 数值与字符编码

书中第 3 章还介绍二进制、补码、浮点数和字符编码。刷题当前只需记住：整数溢出要关注类型范围，Go 的字符串是 UTF-8 字节序列，按字节索引不等于按 Unicode 字符索引；需要处理 Unicode 字符时使用 `[]rune`。编码原理保留理解，不进入当前主干模板。

## 六、踩坑点

1. **数组长度属于类型**：`[3]int` 和 `[4]int` 不是同一类型；函数参数若写 `[3]int` 也只能接收长度为 3 的数组。
2. **`len` 和 `cap` 不同**：只能访问 `0 <= i < len(s)` 的元素；`cap` 不能扩大可访问范围。
3. **`nil map` 可读不可写**：`var m map[int]int; _ = m[1]` 安全，但 `m[1] = 2` 会 panic。
4. **`map` 遍历无序**：不要依赖输出顺序；需要顺序就把键取出后排序或改用切片。
5. **切片是共享视图**：函数收到 `[]int` 后修改元素通常会影响调用方；`append` 是否影响调用方取决于容量。
6. **`range` 的值是副本**：`for _, x := range nodes { x.Val++ }` 不会修改节点本身；要用索引或指针。
7. **字符串索引是字节**：`s[i]` 的类型是 `byte`；按字符遍历用 `for _, r := range s`。
8. **空输入要先想清楚**：空切片、空树、空链表、空 map 的返回值是否应为 `0`、`nil`、空切片还是错误。

## 七、项目中的实际使用

在函数边界先写清数据契约：

```go
// 输入：长度可变的整数切片；函数会原地修改 nums。
// 输出：无；调用方继续使用同一底层数组。
func normalize(nums []int) {
    for i := range nums {
        if nums[i] < 0 {
            nums[i] = 0
        }
    }
}
```

如果函数不应修改调用方，就复制后再改。若数据量大且允许共享，则在文档中明确“借用/原地修改”的约定。工程中不要因为教程展示底层扩容就手写一个泛用动态数组；Go 的切片已经是成熟实现，只有在学习机制或特殊内存布局时才自建。

## 八、一句话总结

**先确认类型、长度、容量、空值和别名，再谈算法复杂度。**

## 九、核心问答

1. **`make([]int, 5)` 和 `make([]int, 0, 5)` 的区别？**
   - 前者 `len=5`，已有 5 个零值元素；后者 `len=0, cap=5`，需要 `append` 才产生有效元素。
2. **为什么 `map[int]bool` 和 `map[int]struct{}` 都能做集合？**
   - 两者都能表达存在性；`struct{}` 不存额外布尔值，语义更专一。
3. **什么时候必须复制切片？**
   - 需要隔离后续元素修改、保存快照、或防止子切片长期占住大数组时。
4. **为什么 `range` 修改结构体切片元素常常不生效？**
   - `range` 变量是元素副本；用 `for i := range xs { xs[i].Field = ... }`。
5. **Go 中“数组”和刷题常说的“数组题”为什么不完全对应？**
   - 题目中的数组通常指连续序列；Go 中实际输入多为运行时长度的切片 `[]T`。

## 十、自测与答案

### 题目

1. `s := make([]int, 2, 4)` 后，合法下标范围和最多能追加多少元素？
2. 为什么 `var m map[string]int` 可以读取 `m["x"]` 却不能写入？
3. `u := s[1:3]` 后修改 `u[0]`，什么时候会影响 `s`？
4. 要按 Unicode 字符统计频次，应使用 `map[byte]int` 还是 `map[rune]int`？

<details>
<summary>答案</summary>

1. 合法下标是 `0`、`1`；在不扩容的前提下还能追加 `cap-len=2` 个元素。
2. 读取缺失键会返回值类型零值；写入需要分配桶，`nil map` 没有可写存储。
3. 通常会影响，因为 `u` 与 `s` 共享底层数组；除非后续 `append` 使 `u` 先换了底层数组。
4. `map[rune]int`，因为 `rune` 表示 Unicode 码点；`byte` 只适合按 UTF-8 字节处理。
