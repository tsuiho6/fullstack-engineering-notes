# 数组、切片与链表

## 一、是什么

数组把同类型元素放在连续空间中，擅长按下标随机访问；链表把节点分散存放，用指针/引用连接，擅长在已知节点位置附近改链接。Go 刷题里“数组”通常落地为切片 `[]T`，链表则是 `*ListNode`。

## 二、为什么需要

两者的核心取舍是：

| 结构 | 访问第 `i` 个 | 已知位置插入/删除 | 尾部追加 | 局部性 |
|---|---:|---:|---:|---|
| 数组/切片 | `O(1)` | `O(n)`，要搬移元素 | 均摊 `O(1)` | 好 |
| 单链表 | `O(n)` | `O(1)`，要有前驱节点 | 有尾指针时 `O(1)` | 差 |

没有这个区分，就容易在数组中间频繁插入，或在链表上反复按下标查找，得到远超预期的复杂度。

## 三、核心用法

### ⭐ 切片：LeetCode 的默认线性容器

**输入输出形状**：`[]int` → `[]int`；长度运行时确定；元素类型固定；`len` 是有效元素数，`cap` 是底层数组容量。

```go
// 在 index 处插入 x，返回新切片。
func insertAt(s []int, index, x int) []int {
    s = append(s, 0)       // 先扩一格
    copy(s[index+1:], s[index:])
    s[index] = x
    return s
}

// 删除 index，返回新切片。
func deleteAt(s []int, index int) []int {
    copy(s[index:], s[index+1:])
    return s[:len(s)-1]
}
```

工程中若元素含指针，删除后要清理尾部引用再缩短，以免大对象被底层数组继续保持：

```go
// 对 []*Node 等引用元素，先 old := s[len(s)-1]; s[len(s)-1] = nil
```

### ⭐ 链表节点与哨兵节点

```go
type ListNode struct {
    Val  int
    Next *ListNode
}

// 在 prev 后插入 node；输入 prev != nil，输出仍是原链表头。
func insertAfter(prev, node *ListNode) {
    node.Next = prev.Next
    prev.Next = node
}

// 删除 prev 后的节点；输入 prev != nil 且 prev.Next != nil。
func deleteAfter(prev *ListNode) {
    prev.Next = prev.Next.Next
}
```

当头节点也可能被删除时，加一个不承载业务值的哨兵：

```go
dummy := &ListNode{Next: head}
// 从 dummy 出发，统一处理“删除头节点”和“删除中间节点”
head = dummy.Next
```

### ⭐ 反转链表：三个指针的最小模板

```go
func reverseList(head *ListNode) *ListNode {
    var prev *ListNode
    for head != nil {
        next := head.Next // 先保存后继，避免断链
        head.Next = prev
        prev = head
        head = next
    }
    return prev
}
```

**状态形状**：`prev` 指向已经反转好的前缀，`head` 指向尚未处理的后缀；每轮只移动一个节点，总时间 `O(n)`，额外空间 `O(1)`。

### ⭐ 快慢指针：中点、环、相交

```go
func hasCycle(head *ListNode) bool {
    slow, fast := head, head
    for fast != nil && fast.Next != nil {
        slow = slow.Next
        fast = fast.Next.Next
        if slow == fast {
            return true
        }
    }
    return false
}
```

同一不变量还可用于找中点：`fast` 每次走两步，`slow` 每次走一步；循环结束时 `slow` 位于中部附近。偶数长度取前中点还是后中点，取决于初始化和循环条件，必须先对小样例模拟。

### △ 双向链表

双向节点多一个 `Prev`：

```go
type DNode struct {
    Val        int
    Prev, Next *DNode
}
```

它允许从节点向前、向后移动，以及在已知节点处 `O(1)` 删除；代价是维护两个方向的连接，出错面更大。LRU 等需要“哈希表 + 双向链表”的结构会用到它。

### ○ Go `container/list`

标准库 `container/list` 是双向链表，节点以 `*list.Element` 表示，值通过 `any` 存储，需要类型断言。它适合工程中的通用链表操作；LeetCode 给定 `ListNode` 时直接操作题目节点更简单，也避免装箱和断言。

## 四、核心原理

### 1. 数组的随机访问

```text
address(i) = base + i × elementSize
```

直观含义：连续空间让下标变成偏移量，所以访问不随 `n` 增长；中间插入则必须给新元素腾位置，搬移量取决于后缀长度。

### 2. 链表为什么“改指针快”但“找位置慢”

已知 `prev` 和 `node` 时，插入只需改两条 `Next`：

```text
prev → next   变为   prev → node → next
```

直观含义：链表不需要搬动其他节点；但如果只给值或下标，就必须从头顺着指针找，查找仍是 `O(n)`。

### 3. 哨兵节点消除边界分支

把真实头节点挂在 `dummy.Next`，任何删除都变成“删除某个前驱的后继”。直观含义：把“头部没有前驱”的特殊情况人为补出来，统一状态转换。

### 4. 快慢指针的速度差

环中相遇的原因不是“快指针一定追上”，而是进入环后相对速度为 1；有限环上的相对距离每次减少 1，最终为 0。这个解释只用于理解，写题时更重要的是明确 `fast != nil && fast.Next != nil` 的安全条件。

## 五、常见场景

- **切片**：排序、双指针、滑动窗口、前缀和、原地修改、保存遍历结果。
- **单链表**：反转、合并、删除节点、找中点、判断环、分段重排。
- **双向链表**：需要从任一端或任意已知节点移动/删除；LRU 的顺序维护。
- **不适合链表**：需要频繁按下标访问、二分查找、缓存友好扫描；这时切片更好。
- **不适合切片中间插入**：大量随机位置更新且不允许 `O(n)` 搬移；可以考虑链表、树或索引结构。

## 六、踩坑点

1. **切片删除不是自动删除**：必须 `copy` 或 `append` 覆盖元素并缩短 `len`。
2. **`append` 可能换底层数组**：函数返回的新切片要接住；只修改局部变量的切片头，不一定更新调用方的 `len`。
3. **链表反转要先存 `next`**：先改 `head.Next` 再取后继会丢失未处理部分。
4. **删除节点要保存前驱**：单链表只有 `Next`，没有前驱就无法直接 `O(1)` 删除普通节点。
5. **`nil` 是合法空结构**：空链表的头是 `nil`，不是值为 0 的节点。
6. **快慢指针循环条件防空指针**：必须先检查 `fast` 和 `fast.Next`。
7. **中点定义不统一**：长度为偶数时要明确返回左中点还是右中点。
8. **`range` 复制节点值**：若切片元素是结构体，改副本无效；若切片元素是指针，改指针指向的对象才会生效。
9. **链表不是“天然更快”**：缓存局部性差、节点分配多；只在操作模式匹配时使用。

## 七、项目中的实际使用

LeetCode 中优先使用题目提供的节点类型，函数只返回新的头指针：

```go
// 输入：任意单链表头指针；输出：反转后的新头指针。
// 只改 Next，不新建节点；时间 O(n)，额外空间 O(1)。
func reverseList(head *ListNode) *ListNode {
    var prev *ListNode
    for head != nil {
        next := head.Next
        head.Next = prev
        prev, head = head, next
    }
    return prev
}
```

真实项目里，如果需要高性能的顺序容器，优先用切片；如果需要“键定位 + 顺序淘汰”，才组合 `map[key]*DNode` 与双向链表。结构的两个索引必须同步更新：从链表移除时同时删除 map；从 map 删除时也要断开链表节点。

## 八、一句话总结

**数组用空间换访问，链表用引用换局部修改；哨兵统一边界，快慢指针统一速度。**

## 九、核心问答

1. **为什么切片按下标快，但中间插入慢？**
   - 下标访问是地址偏移；中间插入要搬移后缀元素，通常 `O(n)`。
2. **链表已知“节点”时为什么还常说删除是 `O(1)`？**
   - 单链表实际需要已知前驱节点；只有在双向链表或题目给出可替换的当前节点时才可直接删除。
3. **哨兵节点解决的是什么问题？**
   - 统一头部、内部和尾部操作，减少“删除头节点”的特殊分支。
4. **反转链表为什么只需 `O(1)` 额外空间？**
   - 直接复用原节点和指针，不创建与 `n` 成正比的新容器。
5. **什么时候不该因为插入 `O(1)` 就选链表？**
   - 如果每次插入前都要遍历找位置，整体仍可能是 `O(n^2)`；若主要是随机访问或扫描，切片更合适。

## 十、自测与答案

### 题目

1. 手写删除单链表头节点的最小代码，为什么哨兵能让它和删除中间节点统一？
2. `s := []int{1,2,3,4}`，删除下标 1 后如何得到 `[1,3,4]`？
3. 反转链表时四个状态变量分别表示什么？
4. 判断链表有环时，为什么循环条件不能只写 `fast != nil`？
5. 偶数长度链表找中点时，如何明确得到后中点？
