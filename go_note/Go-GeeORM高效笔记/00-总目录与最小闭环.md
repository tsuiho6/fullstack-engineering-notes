# 7天用 Go 从零实现 ORM 框架 GeeORM：核心主干与最小闭环

## 这套笔记怎么用

这不是原文的逐章缩写，而是把 GeeORM 压缩成一条可解释、可实现、可迁移的主线：

```text
database/sql
    ↓
Session / Engine：连接、执行、资源生命周期
    ↓
Dialect + Schema：数据库差异 + struct 元数据
    ↓
Clause：把结构化条件稳定地编译成 SQL + 参数
    ↓
CRUD：Insert / Find / Update / Delete / Count
    ↓
Hooks：在生命周期节点插入扩展
    ↓
Transaction：让多个操作成为一个原子单元
    ↓
Migrate：让数据库 schema 随版本演进
```

原材料是 GeeORM 系列总览及 7 个日更章节；原教程的目标是理解 ORM 设计原理，不是提供可直接用于生产的完整 ORM。笔记因此保留教学骨架，同时把当前项目中更重要的安全性、错误传播、`context.Context`、资源关闭和显式迁移补上。

## 三、最小闭环：只保留一条能跑通的路径

先不要背所有 API。能够解释下面这条链，才算抓住 GeeORM：

1. 用 `sql.Open` 得到 `*sql.DB`；用 `PingContext` 验证启动时可用。
2. `Engine` 持有数据库句柄和 Dialect；`NewSession` 创建一次操作上下文。
3. `Model(&User{})` 通过反射解析出 `Schema{Name, Fields, FieldNames}`。
4. `Schema` 只描述元数据，不保存某一行的值；行值来自 `reflect.Value`。
5. `Where`、`Limit`、`OrderBy` 等只设置 Clause 状态。
6. 终结操作按固定顺序 `Build` 出 SQL 和参数切片：

   ```text
   SQL 文本：SELECT Name, Age FROM User WHERE Age > ? ORDER BY Age DESC LIMIT ?
   参数：    [18, 10]
   ```

7. `ExecContext`/`QueryContext` 执行；查询把每一行扫描到一个可寻址的 struct，再追加到目标切片。
8. 发生多个写操作时，把同一个 `*sql.Tx` 作为执行器传入所有操作；错误回滚，成功提交。

## 五、核心问答

### 1. GeeORM 最核心的不是“少写 SQL”，而是什么？

是把重复的数据库差异、对象映射、SQL 组装、结果回填和生命周期管理收敛成可复用的抽象，同时保留在复杂查询处使用原生 SQL 的能力。

### 2. `Schema`、`Clause`、`Session` 分别负责什么？

`Schema` 负责“模型是什么”；`Clause` 负责“这次 SQL 怎么组成”；`Session` 负责“如何执行并管理这次操作”。把三者混在一起，会导致反射、SQL 和连接生命周期互相耦合。

### 3. 为什么 ORM 仍然必须懂 SQL？

因为 ORM 只是 SQL 的生成与执行层。索引、锁、事务隔离、`NULL`、JOIN、执行计划和数据迁移的正确性，最终仍由数据库语义决定。

### 4. 为什么 `*sql.DB` 可以复用，而一个带可变 Clause 的 Session 通常不能跨请求复用？

`*sql.DB` 是并发安全的连接池抽象；教学版 Session 把 SQL、参数和条件存放在可变字段中，若跨请求共享会发生状态串线。项目中应让查询构造器短生命周期、按请求或操作隔离。

### 5. 自动迁移和版本化迁移有什么根本区别？

自动迁移从当前 struct 与数据库状态推断差异，方便但无法可靠判断“改名”和“删掉”；版本化迁移由人明确记录每一步变更，可审计、可回滚，适合生产。

## 六、自测与答案

### 题目

1. 从 `Find(&users)` 到 `rows.Scan(...)`，中间至少需要哪些形状转换？
2. 为什么 `UPDATE users SET name = ?` 中的值可以参数化，而表名不能直接用 `?`？
3. 一次转账的两个 `UPDATE` 为什么必须使用同一个 `*sql.Tx`？
4. 如果 `Find` 的目标是 `users []User`，传入 `users` 和 `&users` 的差别是什么？
5. 为什么“struct 少一个字段”不应直接等价为“生产数据库删一列”？

<details>
<summary>答案</summary>

1. 先得到 `*slice` → 取出 slice 元素类型 → 为每行创建可寻址的 struct → 按列顺序创建 `[]any` 扫描地址 → `Scan` → 追加到 slice。
2. 参数值由驱动绑定；表名、列名属于 SQL 语法/标识符，通常不能作为绑定参数，必须来自受控元数据并经过方言引用。
3. 只有同一个事务句柄才能保证两个操作在同一事务边界内；若第二步使用 `db`，它可能在另一个连接上自动提交。
4. `users` 只是 slice 的副本，不能让函数替换其长度；`&users` 才能通过反射修改调用方的 slice。
5. 少字段可能是重命名、暂时不用或代码与数据库版本不一致；删除列还可能造成不可逆数据损失，所以必须显式迁移并审核。

</details>

## 七、一句话总结

GeeORM 的主干是：用 Schema 描述对象，用 Clause 生成 SQL，用 Session 执行并回填，用 Transaction 保证边界，用 Migrate 管理演进。
