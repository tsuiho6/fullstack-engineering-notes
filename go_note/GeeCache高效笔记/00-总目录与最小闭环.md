# 7天用 Go 从零实现分布式缓存 GeeCache：总目录与最小闭环

> 目标：把教程压缩成一条可以复述、手写、迁移和排错的主干。
>
> 笔记口径：原理保留；教学代码只保留最小闭环；项目写法补上超时、错误边界、协议版本、安全和可观测性。

## 一、先记住整条主线

```text
业务 Get(group, key)
  ↓
本地并发缓存查找
  ├─ 命中 → 返回不可变 ByteView
  └─ 未命中
       ↓
   singleflight：同一进程内，相同 key 只允许一个加载进行
       ↓
   一致性哈希选择 owner 节点
       ├─ owner 是远程节点 → HTTP + Protobuf 获取
       │                         └─ 失败 → 回退本地
       └─ owner 是本机/未启用节点 → Getter 回源
                                  ↓
                              写入本地 LRU
                                  ↓
                                返回结果
```

GeeCache 的真正主干不是“写了 7 天代码”，而是四个问题的连续解法：

1. **内存有限**：用 LRU 控制容量。
2. **请求并发**：用锁保护 LRU，用不可变值隔离外部修改。
3. **节点变多**：用一致性哈希稳定地选择 owner。
4. **同一缺失同时发生**：用 singleflight 合并相同 key 的加载。

HTTP 和 Protobuf 是节点之间的传输层；它们不改变缓存主流程，只改变“如何访问远程节点”。

## 三、最小闭环：做到这些就算学会主干

1. 能写出 `Cache.Get`、`Cache.Add`、`RemoveOldest`，并知道为什么必须同时维护 map 和链表。
2. 能解释为什么 LRU 的 `Get` 也可能需要加锁：它会改变最近访问顺序。
3. 能写出 `Group.Get`：先查本地，未命中后调用 `Getter`，成功后放回缓存。
4. 能说清 `ByteView` 为什么返回字节副本：缓存内部值必须避免被调用方修改。
5. 能把 key 映射到一致性哈希环上，并处理“没有节点”和“超过最大 hash 后回到环首”。
6. 能画出远程访问链路：选 peer → 发请求 → 校验状态码/响应形状 → 解码 → 失败回退本地。
7. 能解释 singleflight 的边界：它合并的是同一进程内、同一 key 的并发加载，不是分布式锁。
8. 能区分 Protobuf 的“消息序列化”和 gRPC 的“RPC 框架”；只用 HTTP 承载 Protobuf 时不需要生成 gRPC stub。

## 四、优先级与“原文—教学—项目”边界

| 内容 | 在教程中的作用 | 当前学习口径 |
|---|---|---|
| `container/list` + map | 直观展示 LRU 的 O(1) 操作 | ⭐ 必须能手写；生产可评估成熟缓存库 |
| `ByteView` | 让缓存值只读、可计算大小 | ⭐ 项目中保留“不可变/复制”原则 |
| 全局 `groups` map | 方便 HTTP 服务端按名称找到 Group | △ 教学方便；项目优先依赖注入或明确注册表 |
| `HTTPPool.ServeHTTP` | 快速搭建节点间协议 | ⭐ 要理解；生产需超时、鉴权、限流和版本校验 |
| 一致性哈希 | 减少节点变更导致的大面积失效 | ⭐ 必须理解；不等于复制、不等于一致性保证 |
| 自研 `singleflight` | 解释重复抑制的机制 | △ 理解机制；项目优先使用 `golang.org/x/sync/singleflight` |
| 旧 `ioutil` / `http.Get` / 旧 proto 包 | 适合 2020 年教学代码 | ○ 只认原理，代码改用 `io.ReadAll`、复用 `http.Client`、`google.golang.org/protobuf` |
| protobuf `service` 声明 | 文章中的协议示例 | ○ 仅 HTTP 承载消息时不是必需；使用 gRPC 时才生成服务 stub |

## 六、全局代码检查口径

GeeCache 没有机器学习里的 `dtype/device`，对应的检查项是：

- **数据形状**：`group`、`key`、`[]byte`、Protobuf `Request/Response` 是否一一对应。
- **所有权**：返回的 `[]byte` 是否可能被调用方修改缓存内部数据。
- **生命周期**：HTTP response body 是否关闭；客户端请求是否绑定超时和取消信号。
- **时序**：先设置响应头，再写状态码，再写 body；协议解码前先检查状态码。
- **并发边界**：锁保护哪些字段；网络/数据库调用是否发生在锁内；singleflight key 是否真的相同。
- **故障边界**：远程失败是否能回退；回退是否会形成新的回源洪峰；错误是否可观测。
- **容量边界**：`maxBytes == 0` 的语义、单条记录大于容量时的行为、容量统计是否只是近似值。
