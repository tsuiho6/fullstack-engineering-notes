## 一、先记住整条主线

```text
HTTP 请求
  ↓
http.Server 调用 Engine.ServeHTTP
  ↓
创建 Context：统一保存请求、响应、路由参数、链路状态
  ↓
Router 按 method + path 匹配 Handler
  ↓
收集全局/分组中间件，组成 handlers 链
  ↓
Context.Next() 驱动“洋葱模型”
  ↓
Handler 读取输入并写入 JSON/HTML/文件响应
  ↓
Recovery、Logger 等中间件收尾
```

框架的本质不是“替代 HTTP”，而是把高频且容易不一致的流程集中起来：路由匹配、参数读取、响应编码、横切逻辑和错误边界。

## 三、优先级说明

- **⭐ 必须掌握**：后续路由、中间件、服务端项目都会反复用到；需要能脱稿解释和写出最小版本。
- **△ 理解即可**：能说明机制和使用边界，细节需要时查文档。
- **○ 知道存在**：只保留入口，不进入日常复习主干。

## 四、最小闭环：只实现这些就算学会

1. `Engine` 实现 `ServeHTTP`，交给 `http.Server` 接管全部请求。
2. `Context` 统一承载 `Request`、`ResponseWriter`、path、method、params、status。
3. Router 先按 method 隔离，再按 path 匹配，最后拿到 Handler 和参数。
4. 中间件按顺序包住 Handler，并能在 Handler 之后执行收尾逻辑。
5. Handler 至少能稳定输出一种 JSON 响应，并正确设置状态码和响应头。
6. Recovery 能把请求级 panic 转成 500，同时日志保留堆栈。

## 五、教程演示与项目推荐的边界

| 教程做法 | 学习价值 | 当前项目建议 |
|---|---|---|
| 用 map 做静态路由 | 理解 method + path → handler | 仍可用于极简内部服务；复杂路由使用 `ServeMux` 或成熟路由器 |
| 自己实现 Trie | 理解匹配、优先级、参数提取 | 只有路由规则/性能确实需要时才自研 |
| `HandlerFunc func(*Context)` | 理解框架统一抽象 | 项目中要保留 `*http.Request.Context()` 的取消/超时语义 |
| `template.ParseGlob` | 理解模板加载和执行 | 新项目优先 `embed.FS` + `ParseFS`，启动时一次解析 |
| `http.ListenAndServe` | 快速启动演示 | 使用 `http.Server` 配置超时和优雅关闭 |
| `strings.HasPrefix` 判定分组 | 演示分组思路 | 不能单独作为权限边界，必须按路由归属或路径段匹配 |

## 七、当前 Go 语境下的一个重要更新

Go 1.22 起，标准库 `http.ServeMux` 已支持方法模式、路径通配符和 `Request.PathValue`，例如 `GET /users/{id}`。因此，Gee 的 Trie 实现今天仍然非常适合学习“路由器如何工作”，但生产项目不应默认为了普通 CRUD 路由重复造轮子。

## 八、代码检查口径

这个主题没有机器学习里的 `dtype/device`，对应的检查项是：

- **输入类型**：`*http.Request`、请求体、查询参数、路径参数是否来自正确位置。
- **输出类型**：`ResponseWriter` 写的是 JSON、HTML、文本还是文件；状态码是否符合语义。
- **时序**：Header 必须在第一次 `WriteHeader`/`Write` 前设置。
- **生命周期**：请求级 Context、取消信号、超时、panic 是否只影响当前请求。
- **并发安全**：路由注册通常在启动期完成；运行期共享 map 需要同步或禁止写入。
- **安全边界**：模板使用 `html/template`；静态资源不能把用户输入直接拼成任意文件路径。
