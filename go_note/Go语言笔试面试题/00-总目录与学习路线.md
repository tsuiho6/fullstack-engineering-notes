# Go 语言笔试面试题：核心主干、最小闭环与主动回忆

> 这套笔记基于[原文汇总](https://geektutu.com/post/qa-golang.html)及其四个分篇，按当前 Go 项目实践重新组织。原材料发表于 2020 年；原理保留，示例优先采用 Go 1.20+ 的常用写法。整理日期：2026-09-19。

## 这套笔记要解决什么

原文适合快速扫过面试题，但零散问题之间存在依赖：

~~~text
声明 / 作用域 / 常量
    -> 函数 / error / defer
        -> 指针 / 方法集 / interface
            -> channel / goroutine 生命周期
                -> 最小项目闭环
~~~

复习时应沿着因果链回忆，而不是把 26 个问答当成 26 个孤立答案。

## 推荐学习顺序

### 第 1 轮：建立可运行的语言骨架

先读 01。读完应能写出一个带多返回值和 error 的小函数，解释 := 的作用域，并用 typed constant、iota、struct tag 写出基本模型。

### 第 2 轮：建立“值如何流动”的模型

再读 02。重点不是背接口内部结构，而是能判断：

1. 传入的是值、地址还是共享底层数据；
2. 两个接口是否可比较；
3. nil 到底是接口 nil，还是接口里装了一个 nil 指针；
4. 一个值是否满足接口，以及指针 receiver 能否被调用。

### 第 3 轮：掌握执行时序

读 03。把 init 的包初始化顺序和 defer 的“注册时求值、返回前执行、后进先出”连成同一类问题：它们都在考察“什么时候发生”。

### 第 4 轮：把并发当成生命周期管理

读 04。任何 goroutine 都必须回答：谁启动、谁等待、谁发送、谁关闭、谁取消、如何退出。

### 第 5 轮：完成最小闭环

最后读 05，并独立完成其中的综合题。目标不是背完，而是能把数据、错误、接口、并发和测试串成一次真实改动。

## 当前写法的更新说明

1. 不再把旧版 Go 的 GOPATH 或 GO111MODULE=on 当作主流程；项目以 go.mod 为依赖边界。
2. error 处理使用 errors.Is、errors.As 和 fmt.Errorf 的 %w 包装，避免用错误字符串做分支。
3. interface{} 可以使用，但 Go 1.18 起通常写 any；核心业务模型仍优先使用具体类型。
4. GOMAXPROCS 不是“总线程数”，当前运行时还会结合 CPU 亲和性和容器配额选择默认值；项目中不要凭经验手工设置，先测量。
5. GC 仍可用“并发三色标记-清扫”建立直觉，但具体阶段和调度属于实现细节；不要把某一版 runtime 细节当成语言规范。

## 一句话总纲

**Go 面试题的主线是：值如何声明和流动，错误如何返回和包装，方法如何绑定，goroutine 如何通信和退出。**

## 跨章节综合问答

### 1. 为什么 map 查询要返回 value 和 ok，而 error 又常作为第二返回值？

两者都在利用多返回值表达“结果 + 状态”，但含义不同：map 的 ok 表示 key 是否存在；error 表示操作是否失败。不要用 map 的零值代替存在性，也不要把所有业务状态都塞进 error。

### 2. 为什么函数返回局部变量指针是安全的，但 map 元素不能直接调用指针 receiver 方法？

前者由编译器的逃逸分析保证对象在函数返回后仍然有效；后者是因为 map 元素不可寻址，编译器无法把 x.M() 改写成 (&x).M()。安全性和可寻址性是两件事。

### 3. 为什么用了 channel 仍可能有 goroutine 泄漏？

channel 只定义通信和阻塞规则，不会自动提供取消和完整的接收方。如果发送永远等不到接收、接收永远等不到发送，或循环没有退出条件，goroutine 仍会卡住。

### 4. 为什么 defer fmt.Println(n) 和 defer func() { fmt.Println(n) }() 可能输出不同？

前者的参数在 defer 注册时求值；后者保存的是闭包，真正执行时读取外层变量的当前值。

### 5. 一个项目为什么不能只用 go run 验证正确？

go run 只说明当前入口能构建并运行；还需要 go test 验证行为，go test -race 检查已覆盖路径中的数据竞争，go vet 发现部分可疑构造，go build 验证可交付构建。

## 总自测

1. 解释 slice、map、interface 三种值在函数传递时各自“复制了什么、共享了什么”。
2. 写出一个能被 errors.Is 识别的包装错误。
3. 设计一个不会靠 time.Sleep 判断完成的 worker 流程。
4. 解释为什么一个 goroutine 的任务失败后，其他 goroutine 不能只靠 WaitGroup 自动停止。
5. 给一个项目选择 slice、map、struct、interface、channel、mutex 的理由。

<details>
<summary>答案</summary>

1. slice 描述符按值复制，但可能共享底层数组；map 值按值传递，但引用同一 map 数据结构；interface 按值复制其动态类型和值描述，但动态值的可变对象仍可能共享。
2. 例如：return fmt.Errorf("load config: %w", ErrNotFound)，调用方用 errors.Is(err, ErrNotFound) 判断。
3. 发送方完成后关闭 channel，接收方 range 到关闭；或使用 WaitGroup 等待所有 worker，并用 context 取消阻塞任务。
4. WaitGroup 只负责等待，不负责传播错误或取消；需要 context.WithCancel、errgroup 或显式错误通道。
5. slice 表示有序序列，map 表示按 key 查找，struct 表示领域数据，interface 隔离可替换行为，channel 传递并同步，mutex 保护共享可变状态。
