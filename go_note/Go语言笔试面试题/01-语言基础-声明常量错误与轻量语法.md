# 语言基础：声明、常量、错误与轻量语法

> 本章合并原文的基础语法题、常量题和作用域题。重点是写得出、读得懂，并能解释编译器为什么这样判断。

## 一、是什么

Go 是静态类型语言：变量的类型在编译期确定；函数通常通过多返回值把正常结果和 error 一起交给调用方。语言刻意减少默认参数、重载等隐式机制，把行为写在函数签名和控制流里。

## 二、为什么需要

这些规则共同解决三个问题：

1. 编译器能尽早发现类型和作用域错误；
2. 调用方能明确知道结果、失败和边界；
3. 代码不依赖“猜默认值”或“运行时找重载”。

如果不理解作用域、常量和 error，最常见的后果是：外层 err 没有被赋值、常量溢出只在某些写法报错、底层错误被字符串拼接后无法判断。

## 三、核心用法

### 1. var、:= 与 =

~~~go
var count int        // 声明，得到零值 0
var name = "gopher"  // 根据右值推断为 string

func run() {
	ready := true       // 声明并赋值，只能在函数体内使用
	count = 1           // 已存在的变量只能用 =
	count, err := load() // 至少有一个新变量即可
	_, _ = ready, err
}
~~~

记忆规则：

- var 可以出现在包级和函数级；
- := 只能出现在函数内；
- := 是“声明 + 赋值”，不是简写版的赋值；
- 变量必须在自己的作用域内使用，否则可能发生遮蔽。

最容易错的代码：

~~~go
var err error
if needLoad {
	err := load() // 新建了 if 块内的 err
	_ = err
}
// 这里的 err 仍可能是 nil
~~~

如果意图是给外层 err 赋值，应写成：

~~~go
if needLoad {
	err = load()
}
~~~

### 2. 多返回值与 error

~~~go
func parseCount(s string) (int, error) {
	n, err := strconv.Atoi(s)
	if err != nil {
		return 0, fmt.Errorf("parse count %q: %w", s, err)
	}
	if n < 0 {
		return 0, errors.New("count must be non-negative")
	}
	return n, nil
}
~~~

调用方先处理 error，再使用结果：

~~~go
n, err := parseCount(input)
if err != nil {
	return err
}
use(n)
~~~

当前项目写法：

- 用 errors.New 创建固定错误；
- 用 fmt.Errorf 的 %w 增加上下文并保留错误身份；
- 用 errors.Is 判断错误类别，用 errors.As 提取错误类型；
- 不用 err.Error() 的字符串内容做业务分支。

### 3. 无默认参数、无方法重载：用显式 API 表达差异

Go 不支持 Python 式默认参数，也不支持 Java 式同名不同签名的方法重载。常用替代方式是：

~~~go
func NewClient(addr string) *Client {
	return NewClientWithTimeout(addr, 5*time.Second)
}

func NewClientWithTimeout(addr string, timeout time.Duration) *Client {
	return &Client{addr: addr, timeout: timeout}
}
~~~

参数个数不固定时可以使用 variadic，但不要把它伪装成任意配置：

~~~go
func Sum(values ...int) int {
	total := 0
	for _, v := range values {
		total += v
	}
	return total
}
~~~

### 4. 常量、iota 与枚举

~~~go
type Status uint8

const (
	StatusUnknown Status = iota
	StatusReady
	StatusFailed
)
~~~

这里的 0 应主动命名为 Unknown 或 Invalid，避免结构体零值悄悄变成一个有效业务状态。

常量有“有类型”和“无类型”之分：

~~~go
const N = 100       // 无类型常量，使用时可转换到合适的数值类型
const M int32 = 100 // 有类型常量，赋值给 int 需要显式转换

var a int = N
var b int = int(M)
~~~

无类型数值常量在编译期保持精确值；一旦要求转换成某个具体类型，就必须能被该类型表示。常量溢出通常在编译期报错，而变量运算可能表现为运行时类型转换后的结果。

### 5. struct tag

tag 是结构体字段上的字符串元数据，由 encoding/json、数据库映射、校验器等工具通过反射读取。

~~~go
type User struct {
	ID   int    `json:"id"`
	Name string `json:"name"`
	Age  int    `json:"-"`
}
~~~

项目中要注意：只有导出字段才能被 encoding/json 默认读写；tag 只改变映射规则，不会把小写字段变成导出字段。

### 6. 低频但要会读

~~~go
a, b = b, a // 多赋值交换，不需要临时变量

type Set map[string]struct{} // 只关心 key 时，用空 struct 表示“没有 value”
set["go"] = struct{}{}
~~~

空 struct 的核心价值是“占位且不需要数据”，常见于集合和信号 channel；它不是通用的业务对象替代品。

## 四、核心原理

### 1. 作用域决定“你改的是哪个变量”

名字解析先找当前最内层作用域，再向外查找。:= 在同一作用域中至少声明一个新变量时合法；如果把同名 err 放进 if、for 或函数内部，就可能遮蔽外层变量。

直观理解：**变量名相同，不代表变量身份相同；先问它属于哪一个大括号作用域。**

### 2. error 是接口值，不是异常控制流

error 的最小约定是一个 Error() string 方法。返回 error 的函数把失败变成普通数据，调用方可以选择重试、转换、记录或继续向上返回。

包装关系可理解为：

~~~text
底层原因 -> 当前操作上下文 -> 请求 / 任务上下文
~~~

%w 保留这条关系，%v 只保留文本。

### 3. struct tag 不改变类型

tag 只是字段元数据。两个字段的 Go 类型、可见性和内存布局不会因为 json tag 改变；改变的是某个反射工具如何解释这个字段。

## 五、常见场景

- ⭐ 解析输入、访问文件/数据库/网络：多返回值 + error。
- ⭐ 定义状态机、协议状态、权限级别：自定义整数类型 + const/iota。
- ⭐ 对外 JSON API：导出字段 + 明确 json tag。
- ⭐ 集合或只发信号：map[T]struct{} 或 chan struct{}。
- △ 需要多个构造方案：显式命名的构造函数，而不是模拟重载。
- ○ 交换变量：读懂多赋值即可，不必把它当成面试主干。

## 六、踩坑点

1. 在 if 或 for 内使用 :=，外层 err 仍为 nil。
2. 只写 if err != nil，不处理错误上下文，导致上层无法定位操作。
3. 用字符串比较错误；应使用 errors.Is 或 errors.As。
4. 把有类型常量直接赋值给不匹配类型的变量。
5. iota 的第一个值默认为 0，却把 0 当作有效状态，造成零值误判。
6. 忽略 json tag 的字段可见性：小写字段即使有 tag 也不会被默认编码。
7. 把空 struct 当成“更省内存的普通对象”；它只适合不需要携带数据的占位场景。

## 七、项目中的实际使用

下面是一个更接近项目的函数边界：

~~~go
var ErrNotFound = errors.New("task not found")

func FindTask(tasks []Task, id int) (Task, error) {
	for _, task := range tasks {
		if task.ID == id {
			return task, nil
		}
	}
	return Task{}, fmt.Errorf("find task %d: %w", id, ErrNotFound)
}
~~~

调用方可以同时得到：

- 成功时的具体 Task；
- 失败时的稳定错误身份；
- 包含 id 的上下文信息。

这比返回一个零值 Task 再让调用方猜“到底没找到还是找到了空对象”更可靠。

## 八、一句话总结

**声明解决变量身份，常量解决编译期值，error 解决可预期失败；写 Go 时先看作用域和类型，再看返回状态。**

## 九、核心问答

### 1. := 和 = 的根本区别是什么？

:= 会在当前函数作用域声明至少一个新变量并赋值；= 只给已有变量赋值。最常见的实际问题是 := 在内层作用域遮蔽外层 err。

### 2. Go 为什么用多返回值表示错误？

因为失败是调用结果的一部分，调用方可以显式处理；它不会像异常那样自动跳转，控制流更容易从函数签名看出来。

### 3. %v 和 %w 的区别是什么？

%v 只把错误格式化进文本；%w 还建立可 unwrap 的错误链，使 errors.Is 和 errors.As 能识别底层错误。

### 4. 为什么枚举最好保留 Unknown = 0？

Go 的结构体和变量有零值。把 0 设计成 Unknown 或 Invalid，可以让“未初始化”不会误表示为 Ready、Admin 等有效状态。

### 5. struct tag 能否让私有字段被 JSON 编码？

不能。默认 encoding/json 只处理导出字段；tag 只改变字段名、忽略规则等映射信息。
