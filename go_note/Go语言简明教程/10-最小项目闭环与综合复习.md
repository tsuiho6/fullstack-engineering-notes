# 10 最小项目闭环与综合复习

## 一、是什么

最小项目闭环是把模块、数据建模、错误处理、测试和交付命令连成一条能重复运行的路径。它检查的是知识能否迁移到真实改动。

## 二、为什么需要

单独记语法容易产生“看过但不会用”的错觉。完整小功能会迫使我们处理输入、状态、错误、边界和验证。

## 三、最小项目建议

做一个内存版任务管理器，不连接数据库，也不先引入 Web 框架：

1. 用 module 建立项目；按职责决定是否拆出 task 包。
2. 用 Task struct 表示 ID、标题和完成状态；明确零值是否可用。
3. 用 slice 保存任务；如需按 ID 查询，再引入 map 索引并保证两者一致。
4. 用函数完成 Add、Get、Complete 等操作；对无效 ID 返回清楚的 error。
5. 先用具体类型完成；只有同一算法服务于多种真实类型时，才考虑泛型。
6. 对每个行为写表驱动测试；错误路径也要有断言。
7. 运行 gofmt、go test ./...、go vet ./...；若添加并发共享，再运行 go test -race ./...。

## 四、项目检查清单

- 数据约束：ID 如何生成？重复 ID 如何处理？标题允许为空吗？
- 错误边界：调用方如何区分不存在、重复和非法输入？
- 可变性：谁可以修改任务列表？是否有意暴露内部 slice？
- 抽象选择：是否真的需要 interface、generic、reflection？
- 并发性：多个 goroutine 访问时由谁保护状态？是否能取消和等待？
- 验证方式：成功路径、边界输入、错误路径是否都有测试？

## 五、跨章节核心问答

1. **slice 为什么容易造成共享修改？** slice 是描述底层数组的视图；复制 slice 不会复制元素数组。
2. **interface 为什么可能非 nil 却装着 nil 指针？** interface 同时保存动态类型和值，动态类型存在时接口就不等于 nil。
3. **什么时候用泛型，什么时候用 interface？** 泛型复用同一算法的类型变化；interface 抽象运行时行为与依赖边界。
4. **类型断言与反射有何不同？** 断言在已知接口边界做类型分支；反射可运行时检查/操作未知结构，能力更强但风险更高。
5. **context.Cancel 会杀掉 goroutine 吗？** 不会；它发出协作式取消信号，任务必须监听并返回。

## 六、自测与答案

1. 设计一个“按 ID 完成任务”的函数，参数、返回值和错误分别是什么？
2. 如果方法要修改结构体 receiver，通常选择值 receiver 还是指针 receiver？为什么？
3. 修改 slice 后发现另一个变量也变了，先检查什么？
4. 一个 goroutine 在测试结束后仍可能阻塞，项目要补上什么？
