# 02 变量、常量与基本类型

## 一、是什么

类型规定值可以是什么、能进行哪些操作；变量保存可变状态，常量表示编译期可确定的不可变值。

## 二、为什么需要

静态类型让错误尽量在编译期暴露；明确零值和转换规则，才能预测字段、容器及函数输入在初始化前后的行为。

## 三、核心用法

~~~go
var count int             // 零值 0
name := "Ada"             // 函数内短声明
var enabled = true        // 由初值推断类型
const maxRetries = 3      // 常量

type UserID int64         // 新的定义类型
var id UserID = 42
rawID := int64(id)        // 显式转换
~~~

常见零值：数值为 0、bool 为 false、字符串为 ""、指针/函数/interface/map/slice/channel 为 nil。结构体字段递归采用各自类型的零值。

常量组的 iota 用来表达规则化编号：

~~~go
const (
    StatusUnknown = iota
    StatusReady
    StatusClosed
)
~~~

## 四、核心原理

- := 是短变量声明，只能在函数体中使用；至少有一个新变量时，才能在已有作用域里混合重声明。
- 未指定具体类型的常量可在使用时根据上下文获得类型；普通变量不会因此自动跨类型赋值。
- Go 不做隐式数值转换。int、int64、自定义定义类型即使底层表示相同，也通常需要显式转换。
- byte 是 uint8 的别名，rune 是 int32 的别名；它们用于表达字节和 Unicode 码点的语义。

## 五、常见场景

业务状态、计数、ID 和配置字段都应有明确类型。用定义类型表达重要领域概念（如 UserID），但不要只为“看起来严格”而给每个字段造类型。

## 六、踩坑点

- var x = 1 会推断为 int，不是任意宽度的整数；边界和平台兼容性敏感时明确类型。
- 类型转换只改变类型，不负责检查业务范围是否有效。
- const 不能保存运行期计算结果或复合结构值。
- Go 中不能把 bool 当作数字，也没有隐式真值转换。
- iota 每遇到新的 const 声明会重新计数；复杂位标志先考虑可读性再使用。

## 七、项目中的实际使用

优先让零值有意义，减少“创建后必须马上初始化”的隐含约束。输入边界做解析与校验；业务内部使用明确类型，外部序列化时再转换成协议需要的类型。

## 八、一句话总结

**Go 的类型检查是显式的：零值先决定默认状态，转换与业务校验要分开做。**

## 九、核心问答

1. var n int 的值是什么？为什么零值重要？
2. byte、rune、string 分别更接近哪种数据含义？
3. 两个底层类型相同的定义类型能否直接赋值？

## 十、自测与答案

2. var x = 1 通常推断成什么类型？
3. iota 适合解决什么问题，不适合替代什么？
