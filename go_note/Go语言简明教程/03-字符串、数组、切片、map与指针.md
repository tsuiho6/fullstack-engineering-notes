# 03 字符串、数组、切片、map 与指针

## 一、是什么

数组、slice 和 map 是 Go 最常见的集合类型；指针让函数或方法能访问并修改某个值。它们的复制和共享语义不同，是日常 bug 的高发区。

## 二、为什么需要

选择错容器、误判复制边界，会导致数据意外共享、更新没有生效、越界或并发读写错误。

## 三、核心用法

~~~go
var fixed [3]int
items := []string{"a", "b"}
items = append(items, "c") // append 可能返回新底层数组，必须接回结果

scores := map[string]int{"Ada": 10}
score, ok := scores["Ada"] // ok 区分“不存在”和“值为零”
if !ok {
    scores["Ada"] = 0
}

for i, r := range "Go语言" {
    fmt.Println(i, r) // i 是 UTF-8 字节偏移，r 是 rune
}
~~~

## 四、核心原理

- 数组的长度属于类型，赋值会复制整个数组。
- slice 是对底层数组的视图，包含指针、长度、容量；复制 slice 只复制描述符，元素仍可能共享。
- append 在容量足够时可能复用底层数组，容量不足时分配新数组；不要依赖具体增长倍数。
- map 是引用语义的数据结构，不保证遍历顺序；未初始化的 nil map 可以读，不能写。
- 字符串是只读字节序列，不等于 rune 切片。按字节索引与按 rune 遍历处理的是不同坐标。
- 指针保存地址；Go 没有指针算术。指针 receiver 可让方法修改原值，但不意味着所有场景都应该传指针。

## 五、常见场景

默认优先用 slice 表示有序、可增长序列；用 map 表示按 key 查找；用数组表达长度固定且有意义的小数据；用指针表达可选值或需要共享/修改的对象。

## 六、踩坑点

- append(s, x) 的结果必须接回：s = append(s, x)。
- 从大 slice 截取一个很小的视图，可能让大底层数组继续存活；需要隔离时复制出新 slice。
- 两个 slice 可能共享底层数组；修改一个切片的元素可能影响另一个。
- nil map 写入会 panic；需要写入时先 make。
- map 遍历顺序不确定；测试和业务逻辑不要依赖它。
- len("你") 是 UTF-8 字节数，不是字符数。字符串不可直接按 rune 位置修改。

## 七、项目中的实际使用

解码输入后先验证边界，再操作集合；对外返回 slice 时，想清楚是否允许调用方修改共享数据。并发访问 map 时使用互斥锁或其他同步设计；普通 map 并不提供并发写保护。

## 八、一句话总结

**数组复制值，slice 复制视图，map 查找不保序；先弄清共享边界，再改数据。**

## 九、核心问答

1. 复制一个 slice 会复制底层数组吗？
2. 为什么 append 的返回值不能丢？
3. 如何区分 map 中 key 不存在和 key 对应零值？
4. 字符串遍历中的索引和元素分别是什么？

## 十、自测与答案

1. nil slice 与空但已分配的 slice 有什么相同和不同？
2. 为什么 s2 := s1[:1] 后修改 s2[0] 可能影响 s1？
3. 什么情况下 map 写入会 panic？

<summary>展开答案</summary>

1. 两者 len 都可以是 0、都可用于 append；nil slice 没有底层数组，空已分配 slice 可能有非 nil 底层存储。
2. 因为两个 slice 可能指向同一底层数组。
3. map 为 nil 时写入会 panic；并发读写还可能触发运行时错误，必须同步。
