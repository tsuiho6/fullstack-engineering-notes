# 01 模块、包与工具链

## 一、是什么

**模块（module）是版本与依赖管理边界；包（package）是编译和命名边界。** 一个仓库通常从一个模块开始，模块中由多个包组成。

## 二、为什么需要

没有模块，项目依赖什么版本、包从哪里导入就难以重复；没有包边界，文件会挤在一个命名空间里，职责和访问权限也难以管理。

## 三、核心用法

新项目从模块根目录开始：

~~~sh
mkdir notes-demo
cd notes-demo
go mod init example.com/notes-demo
~~~

一个小项目可以按职责拆包：

~~~text
notes-demo/
├── go.mod
├── main.go
└── note/
    └── note.go
~~~

根目录的 main.go 声明 package main，程序入口是 func main()；note/note.go 可以声明 package note。导出标识符首字母大写，包内私有标识符首字母小写。

常用命令：

~~~sh
go run .
go test ./...
go vet ./...
go build ./...
go mod tidy
~~~

## 四、核心原理

- 一个目录中的非测试 Go 源文件通常属于同一个包；测试文件以 _test.go 结尾。
- import 路径由模块路径加子目录构成；目录名一般与包名一致，但语法上包名可以不同。
- go.mod 的 go 行声明模块最低语言版本，也影响版本相关语言语义；toolchain 行是建议使用的工具链版本，不等同于最低语言版本。
- Go 1.21 起，go 行是强制的最低版本要求，较新的 Go 命令可按模块声明自动选择/下载合适工具链（受环境设置影响）。

## 五、常见场景

业务项目使用模块；一个功能边界清楚、可被其他包复用的目录适合独立成包。不要按“每个文件一个包”拆分，也不要为了分层制造只有一行转发的包。

## 六、踩坑点

- go run main.go 只把指定文件作为输入，可能漏掉同包的其他源文件；在项目根目录运行 go run . 更稳妥。
- 包名不等于文件夹任意取名：导入时使用 import path，代码中使用包声明名。
- 不要把早期的 GOPATH、手动设置 GO111MODULE=on 当作新项目的必做设置。
- go mod tidy 会根据源码整理依赖，不是每次编译都必须运行。

## 七、项目中的实际使用

先用一个模块完成可运行的最小闭环；只有当职责、复用边界或依赖方向明确时再拆包。每次修改后至少运行 gofmt、go test ./...，有条件再运行 go vet ./...。

## 八、一句话总结

**模块管依赖与版本，包管代码边界；先让一个模块跑通，再按职责拆包。**

## 九、核心问答

1. **模块和包有什么区别？** 模块管理依赖与版本，包是编译、导入和命名的单位。
2. **go 与 toolchain 行一样吗？** 不一样；前者声明最低语言版本，后者建议工具链版本。
3. **为什么推荐 go run .？** 它按当前包构建所有相关源文件，而不是只编译某一个文件。
