# 05 结构体、方法、接口与类型断言

## 一、是什么

结构体把相关数据组合成领域值；方法把行为关联到接收者类型；接口描述调用方需要的行为，不要求显式声明“实现了接口”。

## 二、为什么需要

良好的数据模型能让业务概念直接映射到代码；小接口可以隔离变化、方便测试；类型断言则用于在必要时检查接口值背后的具体类型。

## 三、核心用法

~~~go
type User struct {
    ID   int64
    Name string
}

func (u *User) Rename(name string) {
    u.Name = name
}

type NameReader interface {
    ReadName(context.Context, int64) (string, error)
}

// 安全断言：失败不 panic
if saver, ok := value.(Saver); ok {
    err := saver.Save(ctx)
    _ = err
}

switch v := value.(type) {
case string:
    fmt.Println("text:", v)
case fmt.Stringer:
    fmt.Println(v.String())
default:
    fmt.Printf("unsupported %T\n", v)
}
~~~

## 四、核心原理

- Go 以组合为主，不以类继承组织类型。嵌入字段会提升部分选择器，但不是子类关系。
- 方法集决定类型是否实现接口：T 的方法集包含值 receiver 方法；*T 包含值 receiver 和指针 receiver 方法。
- 接口值可理解为“动态类型 + 动态值”。接口本身为 nil，要求两部分都没有动态内容。
- var p *User = nil; var r io.Reader = p：此时 r != nil，因为它携带动态类型 *User。调用方法时仍需防范接收者是 nil 的情况。
- 单值断言 x.(T) 在类型不匹配时 panic；逗号 ok 形式返回匹配结果和布尔值。

## 五、常见场景

在调用方需要抽象外部依赖时定义小接口（例如存储、时钟、消息发送器）；只有调用方确实需要多态行为时才引入接口。对固定数据形状，优先具体结构体而非 map[string]any。

## 六、踩坑点

- T 与 *T 的方法集不同；某个变量上能自动取地址调用方法，不代表 T 一定实现同一个接口。
- typed nil 不是 nil interface；检查接口是否 nil 不等于检查接口内的指针是否 nil。
- 类型断言用于 interface 值，不能对普通具体值随意使用。
- 断言失败可能是正常分支时，用逗号 ok 或 type switch；避免单值断言导致崩溃。
- 不要为了“面向接口”给每个结构体都配一份一对一接口。

## 七、项目中的实际使用

让业务函数依赖少量行为接口，生产实现由基础设施层提供，测试可注入替身。接口尽量由使用方定义并保持窄小。只有插件、反序列化或兼容多种输入等边界代码，才做类型分派。

## 八、一句话总结

**数据用 struct，行为用 method，依赖用小 interface；断言只在动态类型边界上安全地做。**

## 十、自测与答案

1. if v, ok := x.(T); ok {} 的 ok 代表什么？
2. 什么时候选择 type switch 而非多个单值断言？
3. var x interface{} = (*User)(nil)，x == nil 是 true 还是 false？

<details>
<summary>展开答案</summary>

1. 接口动态值的具体类型是否可断言为 T；不匹配不会 panic。
2. 输入允许多种动态类型、且需要按具体类型分支时；多个断言也可行，但 type switch 通常更清楚。
3. false；接口包含动态类型 *User，因此接口本身非 nil。
