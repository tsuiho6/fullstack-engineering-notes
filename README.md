## 推荐学习顺序

当前仓库适合按照“基础 → 结构 → 工程 → 验证”的顺序阅读：

```text
Go 语言主干
    ↓
数据结构与算法
    ↓
Gee Web / GeeORM
    ↓
GeeCache / GeeRPC
    ↓
性能分析、并发治理与项目化验证
```

对应入口：

1. 先读 [Go 语言简明教程](go_note/Go语言简明教程.md)，建立值、错误、接口和并发的基本模型。
2. 用 [Go 面试主干复习](go_note/Go程序员面试笔试宝典-高效复习笔记/00-总目录与学习路线.md) 把语言、运行时和并发知识串成可主动回忆的骨架。
3. 再读 [数据结构](hello_go/hello-algo-数据结构笔记/README.md) 与 [算法](hello_go/hello-algo-算法高效笔记/README.md)，训练从约束反推结构和算法。
4. 用 [Gee 框架](go_note/Go-Gee框架高效笔记/00-总目录与学习路线.md) 和 [GeeORM](go_note/Go-GeeORM高效笔记/00-总目录与最小闭环.md) 理解后端请求与数据访问的基本闭环。
5. 用 [GeeCache](go_note/GeeCache高效笔记/00-总目录与最小闭环.md) 和 [GeeRPC](go_note/GeeRPC高效笔记/00-总目录与最小闭环.md) 进入缓存、分布式通信和服务治理。
6. 最后用 [Go 高性能编程](go_note/Go语言高性能编程/Go语言高性能编程-总目录与最小闭环.md) 做测量、基准和交付检查。

面试题笔记适合作为阶段性复习和自测，不作为主线的替代品。

## 未来路线

后续新增内容会尽量遵循同一条主线：先建立概念模型，再写最小实现，最后用可重复的验证收口。

### 1. Go 后端

- HTTP API、认证授权、配置、日志、错误边界和可观测性
- PostgreSQL、Redis、消息队列与数据一致性
- 测试分层：单元测试、集成测试、契约测试、并发测试、基准测试
- Docker、CI、部署、故障排查与性能回归

### 2. TypeScript / React 前端

- TypeScript 类型系统、模块化、异步与网络请求
- React 组件、状态、表单、路由、错误处理和可访问性
- 前后端契约、类型生成、端到端测试与构建发布
- 用一个真实业务页面连接 Go API，而不是只记录零散语法

### 3. LLM / Agent 工程

- 模型调用、结构化输出、流式响应、工具调用和重试
- Prompt、上下文、记忆、RAG、权限与安全边界
- Agent 工作流、状态机、任务分解、人工介入和失败恢复
- 评测集、质量指标、延迟、成本、可观测性与版本管理

### 4. AI 辅助开发与验证

- 需求 → 设计 → 实现 → 测试 → Review → 交付的可追踪流程
- 用 AI 生成候选方案，但用测试、基准、静态检查和人工审查收口
- 沉淀可复用的提示词、检查清单、验证脚本和失败案例
- 记录“AI 做了什么、依据是什么、如何证明结果可信”
