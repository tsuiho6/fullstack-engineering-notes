# Go 后端基本功：总目录与最小闭环

> 面向目标：以 Go 为主，能写、测试、排查和交付一个小型 HTTP 后端服务。
>
> 笔记口径：先抓请求与数据的主线，再补工具；每篇都区分原理、教学演示和项目推荐写法。

## 一、先记住总主线

~~~text
客户端输入 URL
  → DNS 找到目标地址
  → TCP 建立字节流连接
  → TLS（HTTPS）验证身份并加密
  → HTTP 请求 / 响应传递业务数据
  → Go Handler 解析、校验、授权
  → 业务逻辑访问依赖并返回结果
  → 测试证明边界正确
  → Linux 与 Git 支持运行、定位和协作
~~~

网络与 HTTP 解释“请求怎样到达服务”；业务 API 解释“服务怎样表达业务”；Go 测试让变化可验证；Linux 与 Git 让服务能运行、排错和协作。

## 四、推荐学习顺序

1. 读网络与 HTTP 的请求链路、消息语义和 Go 客户端超时；熟悉 HTTP 基础后进入业务 API。
2. 用标准库 Handler 或 Gin 完成一组小型 API；每新增一个行为就补对应测试。
3. 掌握表驱动测试、Handler 测试、依赖隔离和必要的集成测试。
4. 用 Git 分支管理这项练习；在 Linux 环境启动服务、看日志、检查端口并做一次故障定位。
5. 回到跨章节问题，能从症状反推是协议、Handler、业务、测试还是运行环境的问题。

## 五、最小项目闭环

用一个“学习资料 API”串联全目录：

~~~text
GET /v1/notes        列表与分页
GET /v1/notes/{id}   查询详情
POST /v1/notes       创建并校验
PATCH /v1/notes/{id} 更新
DELETE /v1/notes/{id}删除
~~~

先用内存存储练接口和测试，再接入数据库；不要为了练 HTTP 一开始引入微服务。完成标准：

- 能从 curl 请求追到 Go Handler，并解释状态码、请求体和响应体。
- 输入错误、资源不存在和内部错误返回不同且稳定的结果。
- 业务逻辑有单元测试，HTTP 边界有 Handler 测试。
- Git 中有清晰提交；服务可在 Linux 环境启动并通过日志和端口检查。

## 六、跨章节综合问答

### 1. TCP 是字节流，为什么应用层还要设计 HTTP 或 RPC？

TCP 只保证有序传输字节，不保留一次业务消息的边界。HTTP/RPC 规定消息结构、含义和状态，应用才能判断一段字节表示什么请求。

### 2. HTTP 请求超时后，服务端一定停止处理了吗？

不一定。客户端超时只代表客户端停止等待；服务端和下游工作需要接收并传播取消信号，并在阻塞点检查它。

### 3. 为什么同一个 API 不能只靠前端校验？

客户端输入可以被绕过或伪造。服务端必须重新解析、校验身份、检查资源权限，并约束请求体大小。

### 4. Handler 测试和数据库集成测试分别证明什么？

Handler 测试验证 HTTP 输入输出与状态码；数据库集成测试验证真实 SQL、事务和 schema 的协作。前者不能证明 SQL 正确，后者也不应承担所有业务分支测试。

### 5. 服务返回 500，第一步查哪里？

先用请求标识关联日志，确认请求是否到达、哪个边界失败，再检查进程、配置、端口和依赖状态；不要先猜某个 Go 语法错误。

### 6. 多人协作时，为什么不该随手强推共享分支？

改写远端历史可能让同伴的提交失去可见祖先。共享分支优先用新提交或 revert 撤销；重写历史前遵循团队约定并确认影响范围。

## 七、总自测与答案

1. 不看笔记画出浏览器到 Go Handler 的请求路径。
2. 解释超时、取消和服务端停止工作的区别。
3. 给一个创建 API 写出成功、校验失败、未登录、无权限和内部错误的响应策略。
4. 说明单元、Handler、集成、竞态测试各自保护哪一层。
5. 服务启动失败、端口被占用、请求超时，分别会先看哪些证据？

<details>
<summary>参考答案</summary>

1. URL 解析与 DNS → TCP →（HTTPS 时 TLS）→ HTTP 请求 → Handler → 业务逻辑与依赖 → HTTP 响应。
2. 超时是等待期限；取消是传播停止信号；处理是否停止取决于服务端和下游是否响应取消。
3. 成功返回资源和合适的 2xx；非法字段返回 4xx；认证和授权分别返回 401/403；内部错误返回稳定的 5xx，不泄露堆栈或数据库细节。
4. 单元测试验证纯业务规则；Handler 测试验证 HTTP 边界；集成测试验证真实依赖；race 检查并发数据访问中的竞态。
5. 启动日志和进程状态；监听端口和占用进程；请求日志、客户端期限、服务端处理耗时和下游调用。

## 九、一句话总结

**后端基本功的闭环是：看懂请求怎样来，设计服务怎样答，用测试证明答得对，再用 Linux 和 Git 安全地运行与演进。**
